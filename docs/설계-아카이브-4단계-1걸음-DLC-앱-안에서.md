# 아카이브 4단계 · 1걸음 설계 — DLC를 앱 안에서 넣고 빼며 줄이 흐르게

작성일: 2026-09-22. 작업 가지: `next-timeline`(작업 폴더 `.claude/worktrees/next-engine`). 컴퓨터(Windows) 전용. 감독 결정: "해줘"(2026-09-22 — 아래 1절의 제안에 대한 승인).

## 1. 왜 · 무엇

감독의 말: **"전 엔진에서 쓰는 방식으로는 안 되는 거야? 자연스럽게 DLC 추가하듯이. 지금은 너무 투박하게 한 번에 다시 다 쌓는 느낌이잖아. 전처럼 자연스럽게 빼고 넣는 느낌이 안 나."**

지금 연표(웹)는 파일을 고르면 그 자리에서 자료를 합치고 줄 배치를 화면 안에서 다시 셈해, 트랙 높이가 옛 높이에서 새 높이로 360ms 흐르고(새 트랙은 0에서 자라나고 뺀 트랙은 옅어지며 접힌다 — `_applyFlip`) 켜고 끄기도 같은 길이다. 새 앱(4단계의 첫 판 `155f23c`)은 ① 줄 배치를 "넣을 때 한 번" 셈해 저장소에 굳혀 두므로 DLC를 더하면 저장소를 **통째로 다시 짓고** ② 앱이 저장소 파일을 잡고 있어 **앱을 닫고 진행 창을 띄운 뒤 다시 켜며** ③ 켜고 끄기는 2단계의 약속대로 **흐르지 않고 바로 뛴다.** 빼기는 앱에 없다(폴더에서 파일을 지우고 도구를 다시 돌려야 한다).

실측(동아시아 DLC · 이 PC): 배치 셈(Node) 7.4초 · 저장소 짓기 0.7초 · 타일 검사 0.2초. 투박함의 대부분은 계산이 아니라 **앱을 닫고 · 진행 창 · 다시 켜기**와 **흐름 없음**에서 온다.

두 걸음으로 간다. **이 문서는 1걸음(느낌)이다.**

- **1걸음(느낌 · 이 문서)**: 앱 안에서 파일을 고르면 뒤에서 다시 짓고, 끝나면 엔진이 저장소를 **닫았다 다시 여는** 명령으로 바꿔 넣고, 줄이 옛 자리에서 새 자리로 흐른다. 켜고 끄기도 흐른다. DLC 관리 창에 **삭제** 단추가 선다. 재시작 · 진행 창 없음.
- **2걸음(구조 · 따로 정한다)**: 통째 다시 짓기 대신 **그 DLC가 닿는 트랙만** 다시 셈해 끼워 넣는다. 지금 연표의 배치도 트랙 단위(`_layoutTrack`)라 결과는 같고, 자료가 커져도 더하는 시간이 DLC 크기에만 비례한다. 최종 목표(모든 역사서를 넣다 뺐다)에서는 이 걸음이 없으면 더할수록 느려진다. 2026-09-22 결정의 "메이커의 아카이브용 내보내기"는 다른 DLC의 트랙에 항목을 얹는 DLC에는 통하지 않는다(배치는 그 트랙의 모든 항목을 한꺼번에 놓는 셈이라 넣는 쪽에서 해야 한다) — 2걸음이 이것도 함께 푼다.

## 2. 1걸음의 흐름(사용자가 보는 것)

| 손짓 | 보이는 것 |
| --- | --- |
| DLC 관리 → `📂 파일에서 더하기…` → 파일 고름 | 창 위 칸에 `더하는 중 — 배치를 셈하는 중…`(도구의 말 그대로 · 회전 표시). 창을 닫아도 앱 위 알림 줄에 같은 글. 연표는 그대로 쓸 수 있다 |
| 다 지어짐(동아시아 기준 8초 안팎) | 저장소가 바뀌고 **줄이 흐른다**: 새 DLC의 트랙은 제자리에서 0에서 자라나고(360ms · `Cubic(.32,.72,0,1)`), 아래 트랙들이 밀려 내려간다. 남의 트랙에 항목을 얹는 DLC면 그 트랙의 높이가 흐르고 새 내용은 200ms로 떠오른다. 보던 줄은 화면에서 제자리(세로 닻). DLC 관리에 카드가 생기고 켜져 있다. 알림 `DLC «이름»을 더했습니다` |
| 카드의 스위치 끄기/켜기 | 이제 **흐른다**(2단계의 '바로 뛰기'를 걷어낸다): 끄면 그 DLC의 트랙이 접히듯 0으로 줄고(줄어드는 동안 옛 타일의 내용이 잘려 보인다) 아래가 올라온다. 켜면 0에서 자라난다. 남의 줄에 사건만 덧붙인 DLC는 줄이 그대로고 사건만 200ms로 오간다 |
| 카드의 자세히 → `DLC 삭제` → 확인 | 먼저 끄는 것과 같은 흐름으로 접히고(360ms), 그 뒤에 뒤에서 다시 지어 바꿔 넣는다(이때는 이미 빠진 뒤라 화면이 움직이지 않는다). 카드가 사라진다. 기본팩(동아시아)은 삭제 단추가 없다 |
| 같은 DLC를 고쳐 다시 내보낸 것을 더함 | 판이 높은 것으로 바뀐다. 그 트랙은 있던 자리에서 높이만 흐르고 내용이 200ms로 바뀐다 |
| 실패(파일이 아님 · 도구 없음 · 짓기 실패) | 창 위 칸과 알림 줄에 까닭(도구의 말 그대로). 저장소는 그대로 |

움직임 값은 `docs/움직임-원칙.md`의 것만(120 · 160 · 200 · 360ms · 되튐 없음). 필터 · DLC로 바뀐 것의 규칙(원칙 표의 "켠 트랙은 0에서 자라나고, 끈 트랙은 0으로 접힘. 바뀌지 않은 것은 그대로")을 그대로 따른다.

## 3. 부품별 변경

### 3-1. 엔진(Rust · DLL) — `docs/계약-아카이브-3단계.md` 2-3절에 더한다

- `{"op":"close"}` — 저장소를 놓는다(SQLite 연결을 닫는다). 답 `{"closed":true}`. 그 뒤의 조회 · 타일은 `저장소가 열리지 않았습니다`로 실패하고, `{"op":"open","path":…}`로 다시 연다(있던 길). 파일을 바꿔 넣으려면 Windows에서는 먼저 닫아야 한다.
- 가져오기(`import-layout`)가 DLC의 **글자 id**(`east-asia-base` · 메이커가 준 id)를 `meta.pack_keys`(JSON `{"<번호>":"<글자 id>"}`)로 남기고, `{"op":"layout"}`의 `packs[]`에 `key`를 함께 준다(옛 저장소는 `key`가 빈 글). 화면이 다시 지은 저장소에서 같은 DLC를 알아보는 열쇠다(번호는 다시 지을 때마다 바뀔 수 있다).

### 3-2. 도구(`prototype/scripts/add-dlc.mjs`)

- `--out=<새 저장소 경로>`: 지은 저장소를 거기에 두고 **바꿔 넣지 않는다**(앱이 바꿔 넣는다). 이때는 열려 있는 저장소를 건드리지 않으므로 앱을 닫을 필요가 없다.
- `--remove=<DLC 글자 id>`: `DLC/` 폴더에서 그 id의 파일을 지운 뒤 짓는다(삭제).
- 옵션이 없으면 예전 그대로(`DLC-추가.cmd` — 앱을 닫은 채로 쓰는 예비 길).

### 3-3. 앱

- **`ui/dlc_add.dart` → 뒤에서 도는 일(`DlcJob`)**: 파일 고르기(있던 PowerShell 창) → `node add-dlc.mjs <저장소> --out=<옆의 archive.새로-지음.db> [파일…] [--remove=…]`를 뒤에서 돌리며 그 말을 줄줄이 받는다(`ValueNotifier<DlcJobState>`: 쉼 · 도는 중(줄들) · 실패(줄들)). 끝나면 앱 틀이 **바꿔 넣는다**: `close` → `archive.db`를 `archive.이전.db`로(그 전 것은 지움 — 도구와 같은 규칙) → 새 것을 `archive.db`로 → `open` → 다시 읽기. `open`이 실패하면 되돌리고 다시 연다. 진행 창(`DlcAddApp` · `--dlc-add=`)은 없앤다.
- **명령줄 `--add-dlc=<파일;파일>`**: 앱이 뜬 뒤 그 파일들을 더한다(연결 프로그램으로 `.htpack`을 열었을 때 · 검증의 손잡이).
- **줄 흐름의 다리(`scene/layout.dart` · `row_flow.dart`)**: 새 저장소의 뼈대(`SceneLayout`)로 바꿀 때 옛 뼈대의 자리를 **새 줄 번호 공간으로 옮겨 적은 출발 자리**(bridge)를 만든다 — 트랙은 글자 열쇠(`tracks.key`)로, 트랙 안 줄은 차례(ord)로 짝을 짓는다. 짝이 있는 줄은 옛 자리 · 옛 높이에서, 새로 난 줄(새 DLC의 트랙 · 늘어난 줄)은 새 자리에서 높이 0으로 출발한다(`isBornRow`). 사라진 옛 줄(줄어든 줄)은 트랙 높이의 흐름에 흡수된다(줄 단위 잔상은 두지 않는다 — 2걸음에서 트랙 단위로 끼워 넣으면 같은 트랙의 줄이 바뀌는 일이 줄어든다). `RowFlow.retargetFrom(from, to)`가 출발 자리를 밖에서 받는다.
- **`TimelineScene.replaceLayout(fresh, …)`**: 장면의 뼈대를 **제자리에서** 새 값으로 바꾼다(부품들이 쥔 `scene.layout`이 같은 객체이게 — 목록을 비우고 채운다). 타일 보관 비움 · 접힘 기억 비움 · 이름 자리 비움 · 닻 잡기 · 출발 자리로 다시 쌓기(흐름). 켠 DLC는 글자 열쇠로 옮겨 적고 새로 더한 DLC는 켠다.
- **`enable()`이 흐른다**: `_stack(instant: false, cause: StackCause.packs)`. `scene.setPacks`는 살아남는 첫 줄을 닻으로 잡고 다시 쌓는다. 흐르는 동안 사라지는 줄(`isGoneRow`)은 **직전 조합의 타일**을 그 줄 자리만큼 잘라 그린다(내용이 팍 사라지지 않게 — 원칙 ②).
- **앱 틀(`archive_app.dart`)의 다시 읽기**: `layout` 다시 받기 → 뼈대 바꾸기 → 보기 상태 옮겨 적기(접은 트랙 · 끈 트랙은 트랙 열쇠로, 펼친 상국은 `uid_of` → `id_of`로, 접은 민족은 트랙 열쇠 + 묶음 이름으로 — 못 찾은 것은 버림) → 범위(`meta.min/max`) · 건수 · 필터 시트의 트랙 칩 · 실재성 칩 · 보조 달력 표 · 검색 결과(비움) · 묶음 카드(닫음) · 고른 것(uid로 다시 고르되 기록이 없으면 닫음) · 표시 상태(`SceneMarks` 판 올림).
- **DLC 관리 창(`ui/dlc_manager.dart`)**: 위 칸에 진행 글(도는 중 · 실패의 까닭) · 자세히에 `DLC 삭제` 단추(기본팩 제외 · 확인 창은 지금 연표의 글 그대로) · `onRemove(key)` · `job` 리스너를 받는다. 나머지는 13물결 그대로.

### 3-4. 배포(`scripts/collect-app.mjs`)

도구 폴더 · Node 동봉은 그대로. `사용-안내.md`의 'DLC 더하기'를 앱 안 흐름(재시작 없음 · 삭제 단추 · 예비 `.cmd`)으로 고친다.
