# 움직임 개선안 — 한 손짓, 한 주연

2026-09-18. 사용자 건의("너무 요동치고 요란법석을 떨고, 정교한 느낌이 없고, 다 따로따로 논다 — 애플이 하던 방식의 변태 같은 정밀함과 감성")를 받아 정리한 **제안**입니다. 아직 구현 전이며, 8절의 질문에 답을 받은 뒤 6절의 순서대로 진행합니다. 확정되면 `docs/움직임-원칙.md`를 이 내용으로 개정합니다.

만든 방법: ① 모든 움직임 전수 조사(CSS·JS·화면 껍데기) ② 실제 화면에서 계측 ③ 사용자 동작별로 "무엇이 언제 함께 움직이는지" 추적 ④ 애플의 움직임 설계 조사(WWDC 2018 Designing Fluid Interfaces, WWDC 2023 Animate with springs, HIG Motion) ⑤ 서로 다른 세 관점(엔진·연출·최소 수술)의 설계안을 뽑아 각각 실제 코드에 비춰 반박 검증 ⑥ 살아남은 것만 합침.

> **한 문장:** 손짓 하나에 주연은 하나, 나머지는 주연을 따라 같은 순간에 도착한다. 손에 잡힌 동안은 고요하고, 놓으면 손의 힘이 이어진다.

## 1. 진단 — 왜 요란하고 따로 노는가

움직임이 많아서가 아닙니다. **한 번의 손짓에 시계가 여러 개 돌고, 그중 몇 개는 실제로 고장 나 있기** 때문입니다.

## 2. 애플이 하는 방식

| 원칙 | 뜻 |
| --- | --- |
| 길이가 아니라 반응으로 조율 | 움직임을 "몇 ms"가 아니라 스프링의 반응 속도로 정한다. 끝 시각이 고정되지 않아 도중에 목표가 바뀌어도 어색하지 않다 |
| 기본은 되튐 0 | 평소에는 튀지 않고 매끄럽게 멈춘다(SwiftUI 기본 스프링: 0.5초·되튐 0). 되튐은 **손이 속도를 준 때만**(던지기·밀기) |
| 언제든 끊고 돌릴 수 있다 | 움직이는 도중에 다시 눌러도 지금 자리·지금 속도에서 이어진다. 끝나길 기다리게 하지 않는다 |
| 한 가족 | 시스템 전체가 같은 스프링 가족을 쓴다. 곡선이 제각각이면 "따로 논다"는 인상이 생긴다 |
| 손과 1:1, 놓으면 관성 | 끄는 동안 내용은 손에 붙어 있고, 놓으면 손의 속도를 이어받아 미끄러진다 |
| 나타난 길로 사라진다 | 들어온 경로를 되짚어 나간다. 공간 감각이 유지된다 |
| 절제 | 자주 하는 동작에는 연출을 넣지 않는다. 움직임이 적어야 정밀하게 읽힌다 |

## 3. 새 원칙 (움직임-원칙.md 개정안)

| 원칙 | 규칙 | 기존 원칙과의 관계 |
| --- | --- | --- |
| **한 손짓, 한 주연** | 동작마다 주로 움직이는 것은 하나. 나머지(조연)는 자기 시계를 갖지 않고 주연의 진행값에서 계산되어 같은 프레임에 시작하고 같은 프레임에 끝난다. 한 동작에서 끝나는 시각은 최대 2개(이동 하나, 투명도 하나) | 새로 추가 |
| **시계 하나, 가족 하나** | 값은 스프링 셋·페이드 셋이 전부(4절). CSS와 JS가 같은 값을 읽는다. 그리기는 프레임당 한 번, 세로 스크롤을 쓰는 주체는 하나 | ⑥ 교체 |
| **손에 잡힌 동안은 고요하다 — 전면 적용** | "손에 잡힘"에 끌기·휠·관성·멀리 가기를 모두 포함. 그동안 허용되는 것은 제자리 120ms 투명도 변화뿐. 튐·잔상·미끄러짐·줄 접힘·알림은 전부 미뤘다가 **정착 한 번**에 처리 | ④ 확장 |
| **속도는 버리지 않는다** | 새 움직임은 지금 값과 **지금 속도**에서 시작. 놓으면 관성. 되튐은 손이 속도를 준 때만, 그 밖의 상태 전환은 되튐 0 | "하지 않는 것" 3번을 원칙으로 승격, "작용과 반작용" 절 개정 |
| **크기가 바뀌면 한 몸으로** | 트랙·줄·이름·민족 칸·계승선·네모·세로 닻이 같은 숫자에서 같은 프레임에 그려진다. 누르지 않은 트랙의 높이 변화는 0px | ③ 강화 |
| **들어온 길로 나간다** | 등장이 있는 모든 것은 같은 길의 퇴장을 갖는다(화면 껍데기 포함). 0ms로 사라지는 표면 0개. 어두운 장면에서 태어난 요소가 번쩍였다 가라앉는 일 금지 | ② 강화 |
| **보던 줄도, 누른 것도 제자리** | 붙잡은 줄의 오차 0.5px 이하. 누른 것이 이미 잘 보이면 화면은 움직이지 않는다(질문 1) | ⑧ 개정 |
| **문턱은 두 개** | 확대 수준에 따라 바뀌는 것(이름 단계·묶음·눈금 간격)은 들어오는 문턱과 나가는 문턱을 8% 벌린다. 경계에서 멈춰도 깜빡이지 않는다 | ① 보강 |
| **재고 나서 더한다** | 모든 변경은 7절 점수표의 합격 숫자를 가진다. "느리게 보기"로 감독이 직접 본다 | 새로 추가 |
| 그대로 두는 것 | ① 자리는 자료가 정한다 · ⑤ 넘어가면 알려 준다(단, 조용히 한 번) · ⑦ 동작 줄이기 존중(껍데기까지 확대) | 유지 |

## 4. 값 — 스프링 셋, 페이드 셋

| 이름 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 스프링 `move` | 반응 360ms · 되튐 0 | 배치가 바뀌는 모든 것: 줄 접힘·트랙 펼침·창·세로로 데려오기 |
| 스프링 `camera` | 반응 250ms · 되튐 0 (지금의 휠 추격 70ms와 같은 계열) | 휠·단추·키보드 확대와 이동. 연타하면 목표가 쌓이고 속도가 이어짐 |
| 관성 `coast` | 지수 감속, 길이는 질문 3에서 결정 | 끌다 놓았을 때. 누르면 즉시 멈춤 |
| 멀리 가기 | 지금의 van Wijk 길 320~1100ms 유지 | 검색·알림 알약·전체 보기. 세로 이동도 같은 박자에 실어 대각선 한 번 |
| 페이드 `micro` | 120ms | 호버·눌림·움직이는 중의 제자리 교체 |
| 페이드 `in` / `out` | 200ms / 160ms | 모든 나타남·장면 어두워짐 / 모든 사라짐 |

진폭 예산: 상태 전환의 되튐 0 · 눌림은 단추류 .97, 띠·칸은 크기를 바꾸지 않고 살짝 어두워짐 · 호버 확대는 점 1.25, 알약 1.06뿐 · 표면이 들어올 때 이동 8px 이하 · 반복하는 움직임 0개 · 도착 표시는 도착한 뒤 600ms 고리 한 번.

없애는 값: 길이 22종 → 6종, 곡선 7종 → 2종, 되튐 곡선(`--pop`, 탭 움찔, 알약 부풂, JS 1.35 곡선) 전부, 브라우저 자동 스크롤(`behavior: smooth`), 움직임을 시작하는 타이머.

## 6. 진행 순서

> **진행 상태 (2026-09-18):** 감독이 8절의 질문 여섯 개를 모두 추천안으로 확정. **0단계·1단계(1-1~1-5)·2단계(2-1~2-3) 완료** — 커밋 `4e65d12`부터 `e184647`까지 열네 개. 3단계(한 가족)·4단계(한 몸)·5단계는 남아 있고, 감독이 1~2단계의 느낌을 본 뒤에 이어 감. 실제로 넣은 값과 벗어난 점은 `docs/움직임-원칙.md`의 해당 줄과 각 커밋 글에 있음. 확인은 메뉴(⋯) 맨 아래 "움직임 계측 · 느리게 보기"(또는 주소 끝에 `?motion=1`).

검증에서 가장 중요하게 걸러진 것은 **순서**입니다. 어느 중간 단계도 오늘보다 나빠 보이면 안 됩니다. 크기: 작음(반나절 이내) · 중간(하루 이틀) · 큼(사흘 이상, 나눠서).

### 0단계 — 재는 도구 (작음)

* **느리게 보기**(×0.1, ×0.25) 스위치와 간이 점수표(끝나는 시각 수·누른 것이 밀린 거리·무관한 트랙의 높이 변화). 감독이 직접 "따로 노는 장면"을 볼 수 있게.
* 토큰 선언(4절의 값을 CSS 변수로, JS가 같은 값을 읽음). 이후 모든 단계가 처음부터 토큰으로 작성됨.

### 1단계 — 먼저 고치고 조용히 (작음~중간 다섯 개)

| 순서 | 내용 | 보이는 변화 |
| --- | --- | --- |
| 1-1 | **풍선 제거**: 새로 그릴 때 처음부터 접힌 크기로 짓기 · 접힘 기억을 다시 그리기 너머로 이어받기 · 닻은 누르기 직전 프레임에서 잡기. **그다음에** 필터·저장 때 등장 연출 재생 중지(순서를 바꾸면 가림막이 사라져 들썩임이 맨눈에 드러남) | 트랙 하나를 누르면 그 트랙만 움직임. 칩을 눌러도 화면 전체가 다시 닦이지 않음 |
| 1-2 | **움직이는 동안 고요**: 죽은 `is-moving` 깃발을 살려, 움직이는 중에는 120ms 투명도만(차단이 아니라 조용한 모드 — "옅어지며 사라진다"를 지킴). 문턱 여유 8%. 눈금은 세계 좌표를 따라가며 옅어짐 | 확대 중의 팝콘이 사라지고 캔버스가 한 덩어리로 움직임 |
| 1-3 | **확대 엔진 하나**: 장치 판정은 제스처 첫 입력에서 한 번, 단추·키 연타는 목표 누적 | 트랙패드 확대 중 끊김이 없고, ＋를 두 번 누르면 정확히 두 번만큼 |
| 1-4 | **세로 스크롤의 주인 하나**: 브라우저 자동 스크롤 제거, 멀리 가기와 같은 박자로 한 대각선, 창이 가리는 폭(392px)을 뺀 가운데에 도착 | 검색해서 갈 때 ㄴ자 두 단계와 덜컥임이 사라짐 |
| 1-5 | **알림·반짝 한 박자**: 까딱임 삭제, 1.5초 반짝 → 도착 뒤 600ms 고리 한 번, 알림은 접힌 뒤의 배치로 계산 | 클릭 한 번의 총 움직임 3.5초 → 1초 미만 |

### 2단계 — 감성 돌려주기 (질문 1·2·3의 답 필요)

* 2-1 **끌기 관성 + 가짜 되튐 삭제를 같은 배포로.** 덜어내기만 이어지면 "조용하지만 죽은" 구간이 생기므로, 관성(애플 느낌에서 가장 크게 비어 있던 곳)을 같이 넣음. 세로 닻과 싸우지 않게 하고, 관성을 멈추려고 누른 것은 선택으로 치지 않음. (중간)
* 2-2 **누른 것은 제자리**(질문 1). (작음)
* 2-3 **정착 한 박자**: 관성·멀리 가기의 끝은 공백 0. 휠과 관성 없는 놓기는 0.3초 안팎 유지(끊어 끌 때 줄이 숨 쉬지 않게). (작음)

### 3단계 — 한 가족 (중간 세 개)

* 3-1 장면 어두워짐을 한 층으로(지금은 띠 58%·점 45%·탭 50%·선 14%가 네 가지 길이로). 띠 안의 칸이 두 번 어두워지지 않게.
* 3-2 토큰 일괄 치환(파일 단위로 나눠서).
* 3-3 껍데기 표면의 대칭 퇴장(CSS만으로, 호출부 수정 없이). 확대 단추 자리는 질문 6.

### 4단계 — 한 몸 (가장 큰 공사, 나눠서)

* 4-1 그리기 루프 합치기: 프레임당 그리기 한 번, 읽고 나서 쓰기. (중간)
* 4-2 **세로 기하를 하나의 숫자로 직접 구동**: CSS 높이 전환을 지우고, 줄·이름·선·네모·트랙 밑변·닻이 같은 스프링 값을 같은 프레임에 씀. 화면에서 위치를 되읽지 않으므로 닻 오차가 구조적으로 0. 도중에 다시 눌러도 속도가 이어짐. (큼)
* 4-3 트랙을 다시 짓지 않고 이어 쓰기: A를 눌러도 B·C는 그대로, 접을 때 내용이 한 프레임에 증발하지 않음. (큼)
* 4-4 카메라 스프링: 상태는 "확대 정도 하나 + 커서 닻", 중심은 닻에서 계산(커서 아래 해 고정을 지키기 위해). 휠 느낌은 조율판에서 지금 방식과 나란히 비교한 뒤 결정. (중간)

### 5단계 — 마무리

* 확대 수준에 묶인 세부(초점이 맞듯 스며들고, 되돌리면 정확히 되돌아감) — 선택 사항, 가장 나중.
* `docs/움직임-원칙.md` 개정 확정.

1단계까지만 해도 "요동·요란·따로 논다"의 체감 대부분이 해소될 것으로 봅니다. 4단계는 "거의"를 "완전히"로 바꾸는 공사입니다.

## 8. 감독에게 묻는 것

1. **고를 때 가운데로 데려오기.** 직전에 직접 정하신 동작이지만, 누른 띠가 손 밑에서 달아나는 가장 큰 원인입니다. 추천: 이미 잘 보이면 1px도 움직이지 않고, 가장자리에 걸렸거나 가려졌을 때만 최소 거리로. 가운데 맞춤은 검색·"여기로 가기"처럼 멀리 갈 때만. (대안: 늘 가운데로 가되 부드러운 스프링으로.)
2. **되튐.** "작용과 반작용" 가운데 **눌림은 남기고**, 튐(탭이 내려앉았다 튕김·알약 부풂·트랙 끝 되튐·점들이 모여드는 잔상)은 없애려 합니다. 물리감은 관성처럼 손에 속도가 있는 곳으로 옮깁니다. 남기고 싶으시면 트랙 펼침 한 곳에만, 거리와 무관하게 2~4px로 묶겠습니다.
3. **관성 길이.** 빠르게(초당 1000px) 놓았을 때 약 100px(짧고 단단) / 약 250px(추천, 마우스에 맞음) / 약 500px(아이폰 느낌). 조율판에서 직접 만져 보고 고르실 수 있게 하겠습니다.
4. **휠 확대 때 커서 아래 띠를 가운데 쪽으로 끌어당기는 기능.** "커서 아래 해는 제자리"와 부딪혀 확대 중 내용이 옆으로 미끄러집니다. 추천: 끌어당김은 없애고 "띠가 화면 밖으로 잘리지 않게 붙잡기"만 남김.
5. **첫 화면 등장.** 추천: 띠가 트랙마다 차례로 닦이는 1.4초 대신, 연표 전체가 0.4~0.5초에 한 번 떠오름. (어느 쪽이든 필터·저장 때는 재생하지 않습니다.)
6. **확대 단추(＋/−) 자리.** 창이 열릴 때 옆으로 376px 밀려나는 대신, 창이 가리지 않는 자리로 옮겨 움직일 이유 자체를 없애는 쪽을 추천합니다.

## 9. 검증에서 걸러 낸 것 (하지 않기로 한 것)

* 필터 때 등장 연출 중지를 풍선 제거보다 **먼저** 넣는 것 — 가림막만 사라져 오늘보다 나빠짐.
* 움직이는 중 효과를 통째로 **차단**하는 것 — "옅어지며 사라진다"가 깨짐. 조용한 모드(120ms 투명도)로.
* 관성을 되튐 0 스프링 + 도착점 투영으로 만드는 것 — 놓은 직후 손 속도의 2.3배로 가속. 지수 감속으로.
* 카메라를 "중심"과 "폭" 두 스프링으로 나누는 것 — 커서 아래 해가 최대 30px 미끄러짐. 확대 정도 하나 + 커서 닻으로.
* 멀리 가기를 스프링으로 바꾸는 것 — 20~65% 길어지고 끝이 기어감. 지금의 van Wijk 길 유지.
* 스프링 곡선을 실행 중에 CSS로 찍어 넣기(`linear()`), 스타일시트 자동 검사기, 확대 한계 넘침, translate-FLIP + clip-path — 되튐 0에서는 체감 이득이 거의 없거나 "겹치지 않는다"를 위협. 4-2의 직접 구동 하나로 대체.
* 정착 대기를 일괄 0.12초로 줄이는 것 — 끊어 끌거나 휠을 연달아 굴릴 때 줄이 숨 쉼.
