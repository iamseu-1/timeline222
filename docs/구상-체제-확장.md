## 0. 공통 원칙

1. **세 곳을 함께**: DLC 형식(`DLC-형식.md` + `HT.normalizePack`) · 메이커 편집 · 연표 표시. 기능마다 점검표: **상세 · 검색 · 문서 · 범례 한 줄 · 뷰어 추가 길(우클릭 메뉴 두 분기 · 단축키 · 독의 ＋) · 같은 해 보기 · `toSVG`**. 기본팩 자료는 건드리지 않습니다.
2. **옛 파일은 1px도 다르지 않게.** 새 칸은 모두 선택 사항. 반대 방향(새 파일 → 옛 앱)은 `FORMAT_VERSION`: `packToJSON`이 새 열쇠·새 칸을 하나라도 쓴 파일만 `2`로 내보내고 나머지는 `1` — 옛 앱은 이미 있는 "더 새로운 형식" 경고를 띄웁니다. 앱이 **읽는** 버전(`HT.FORMAT_VERSION`)은 바탕 다지기까지 `1`이고, 새 열쇠를 처음 읽는 단계(종류·소속 관계)가 `HT.NEW_FORMAT_KEYS`에 적으면서 함께 `2`로 올립니다(먼저 올리면 그 상태의 앱이 `2`인 파일을 경고 없이 열어 새 칸을 조용히 버림 — `dev-smoke`가 확인). 읽는 버전은 `2` 하나뿐이므로 새 열쇠를 더하는 단계들(종류 → 대범위)은 `master`에 **한 덩어리로만** 병합합니다(중간 상태의 앱은 아직 모르는 열쇠가 든 `2` 파일도 경고 없이 엶).
3. **거름망은 여러 겹입니다.** `normalizePack`(파일) · `readCells`(칸 목록) · `HT.readPartOf`(소속) · `HT.readCellRows`/`readPartOfRows`(폼) · `buildModel`의 hosts 복사 · `PATCHABLE`(패치) · 메이커 `FIELD_LABELS`/`fmtVal` · 뷰어 `FIELD_NAMES` · 빈 DLC 경고 목록 · `describePeriods`의 칸 목록 · 메이커 `blank`/`sanitize` 배열 목록/id 접두어 표/`hasWork`. 원칙: **형식에 있는 칸 = 폼에 있는 칸**(폼에 칸이 없으면 `data-*`로 보존). 파일 → 메이커에서 열기 → 아무 칸이나 고침 → 내보내기를 돌아도 자료가 줄지 않아야 합니다.
4. **짐작 값은 다른 이름에.** 모델이 채우거나 끌어낸 값은 파일과 같은 이름의 칸에 넣지 않습니다(`dynastyAuto` · 도읍의 `endY` 선례): `rankSpans` · `rankAuto` · `houseId`/`houseAuto` · `startAuto`/`endAuto`. 뷰어 수정 폼은 모델 항목으로 채워지므로, 섞이면 한 번 열어 저장하는 순간 짐작이 자료로 굳습니다.
5. **겹치지 않게, 띠 밖으로 나가지 않게.** 띠 안 도형은 안쪽(ox·iw)에 가두고, 글자는 `textWidth`로 재서 들어갈 때만(전체 → 첫 글자 → 생략). 이어지는 칸은 **하나의 긴 둥근 칸 + 가는 구분선**(`layoutStrip`).
6. **높이는 자료가 정합니다**(화면 범위가 아니라). 새 단의 유무·단 수는 필터를 통과한 자료 전체로.
7. **움직임은 토큰만**: `HT.motion.T.move`(360) + `HT.motion.C.spring` 글자 그대로 · 나타남 `--t-in` 200 · 사라짐 `--t-out` 160 · 되튐 없음 · 동작 줄이기 존중 · 누른 것은 달아나지 않고 누르지 않은 트랙은 1px도 안 움직임.
8. UI 글에 **실제 역사 이름 예시 금지**, 입력 칸에 **예시 값 placeholder 금지**(줄 입력은 기존 줄처럼 짧은 칸 이름만). 새 안내 글은 형식 설명만.
9. 표시 체크의 기본값은 표 하나(`SHOW_DEFAULTS`)로: 뷰어 기본값 · Timeline 옵션 · 체크 되살리기가 모두 `show[key] ?? 기본값`. 저장된 `ui.show`는 한 단계 더 합칩니다(옛 사용자에게 새 표시가 꺼진 채 나오지 않게). 연표 쪽 검사는 기본 켬이면 `!== false`.
10. 한국어 → id 환산 표는 어휘마다 따로(`KIND_WORDS` · `RELATION_WORDS` · `TREATY_WORDS` · `ARTICLE_WORDS`, `HT.capitalRole` 틀). 다른 트랙의 정권을 가리키는 새 칸은 `{ track?, polity }` 하나로 통일하고(비우면 항목의 트랙) 읽을 때만 `"트랙:이름"` 글도 받습니다 — 그 `track`은 정규화에서 검사하지 않고(기본팩 트랙일 수 있음) 모델에서 못 찾으면 경고만.

### 0-1. 바탕 다지기 (첫 커밋 — 동작 변화 없음)
지금 코드는 "항목은 다섯 종류 · 날짜는 start/end"를 곳곳에 손으로 적어 두었습니다. 새 종류를 넣기 전에 표로 바꿉니다.

* `HT.DATE_KEYS`(날짜 칸 목록: `start` · `end` + 뒤에 `birth` · `death`) — 패치 날짜 고치기(core.js 996-1016) · 메이커 `sanitize`/드로어 저장 정규식/`AT_OF`/패치 탭 `sameDate`/`fmtVal` · 뷰어 `AT_KEYS`/내보내기 비교가 모두 이 목록을 돕니다. 짝 칸(`…At`)도 `PATCHABLE`에.
* `HT.USER_LISTS`(내 데이터 목록 이름 ↔ `HT.FORMS` 종류) — 뷰어의 기본 꼴 3곳 · `editCounts`/`editTotal` · `editsAsPack`(복사 · wiki 지우기 · 돌려주는 팩 · 요약 글) · DLC 통계 2곳 · 백업 가져오기 · `buildModel`의 사용자 블록. 설치 뒤 내 데이터를 비우기 전에 "내보낸 항목 수 = 내 항목 수"를 확인합니다.
* `HT.FORMS` 항목에 `nameKey`(제목 칸) · `fresh(preset)`(새 항목 기본값) · `filterKeys`(저장 뒤 풀 필터) — `openEditor`/submit이 읽음. 표 보기 · CSV의 구분은 `HT.itemWord(x)`.
* 메이커 `CFG`에 `nameKey` · `dateKeys` · `kindCell` · `extraCell` · `syncRow` · `itemKind` — "events면 title" · "마지막 else는 문화" 분기를 표로. kind별 상태 객체(`selected` · `listFilter` · `grid.*`)는 `ITEM_TABS`에서 만들고, 모르는 kind는 조용히 떨어지지 않고 오류. 메이커 탭 목록 사본 세 곳(`render`의 views · 팔레트 `TABS` · `gotoIssue`)을 한 목록에서.
* 뷰어 `openDetail` 맨 앞에 **종류별 갈래 표**(가문 · 인물 · 대범위 · 시대 구분 · 칸 · 기본) + 앞 상세를 정리하는 `leaveDetail()`(가문 강조 · 조명 · 강조 끔)을 `closeDetail` · `openYearPanel` · `openDetail`이 모두 거치게. 제 줄이 없는 종류(가문 · 대범위 · 시대 구분)는 `setSelected(null)` + `setAnchor(null)`.
* 필터 시트의 표시 체크를 작은 제목이 붙은 세 묶음으로: **띠 안**(왕조 · 지위 · 지도자 · 대수 · 내각 · 인물 · 가문) / **날짜 칸**(간지 · 연호 · 도읍 · 시대 구분) / **선·견해**(계승선 · 소속선 · 이설). 코드에만 있던 `show.dynasties`의 체크를 함께 넣습니다(새 체크는 해당 기능 커밋에서).
* **넓은 드로어**(8절 1번)도 여기서 — 뒤의 기능들이 지도자 줄에 칸을 더하기 전에.

## 2. 종류와 소속 관계 (건의 5)

### 2-1. 형식
`periods[].kind`(굵은 것이 새 값):

| id | 이름 | 딱지 | 갈래 | 자율성 |
| --- | --- | --- | --- | :---: |
| `state` | 국가 | — | 자주 | 4 |
| **`tributary`** | 조공·책봉국 | 조공 | 종속 | 3 |
| **`fief`** | 봉국·제후국 | 봉국 | 종속 | 3 |
| **`dominion`** | 자치령 | 자치 | 종속 | 3 |
| `vassal` | 종속국 | 종속 | 종속 | 2 |
| **`protectorate`** | 보호국 | 보호 | 종속 | 2 |
| **`satellite`** | 위성국 | 위성 | 종속 | 2 |
| **`puppet`** | 괴뢰국 | 괴뢰 | 종속 | 1 |
| **`mandate`** | 위임·신탁 통치령 | 위임 | 종속 | 1 |
| **`colony`** | 식민지·속령 | 식민 | 종속 | 0 |
| **`occupied`** | 점령지·군정 | 점령 | 종속 | 0 |

| `federation` · `org` · `era` | 연맹 · 조직체 · 시대 이름 | (그대로) | 특수 | — |

`HT.POLITY_KINDS` 항목에 `short` · `family`(`sovereign|dependent|special`) · `autonomy`. `hint`는 범례가 쓰는 ` — 모양` 꼴을 지킵니다.

`partOf[]` 항목에 두 칸:
* `relation` — 종속 갈래 id 열 가지 + `member`(구성국) + `union`(동군연합). 한국어도 읽음(`RELATION_WORDS`).
* `nest` — `true`면 상위 띠 아래에 접어 둠, `false`면 제 줄. 비우면: `relation`이 없거나 `member`면 지금 규칙 그대로(상위 하나 + 기간 없음 → 접힘), 그 밖의 `relation`이면 **제 줄**.

```json
{ "track": "a", "name": "…", "kind": "puppet", "partOf": [{ "polity": "…", "relation": "puppet" }] },
{ "track": "a", "name": "…", "partOf": [ { "polity": "…", "relation": "tributary", "end": 1895 },
                                          { "polity": "…", "relation": "protectorate", "start": 1905, "end": 1910 } ] }
```

고칠 곳: `HT.readPartOf(v, { relation: true })`(시대의 partOf에서만 받음 — 기관의 host · 왕조의 polities는 받지 않음) · 모델의 hosts 복사(core.js 1465)에 `relation` · `nest` · **`singleHost` 규칙은 core.js 1470 한 곳에서만**(= 상위 하나 + 기간 없음 + (`nest === true` 또는 (`nest`가 비었고 relation 없음/`member`))) — 그러면 timeline의 여섯 군데(`_host` · 예속 단 유무 · 그리기 · `toSVG` · `nMem` · `focusOn`)는 고치지 않아도 맞습니다. 함께 `pushMembers`(timeline.js)의 거르기를 `m._host === host`로 — 제 줄에 선 정권이 소속 줄에도 또 들어가 빈 줄이 생기는(지금도 잠재된) 버그를 막습니다.

### 2-2. 연표
* 띠: `kind-<id>` + 종속 갈래면 `fam-dep`(책갈피 탭 · 범례에도). 종속 갈래의 모양은 **지금의 종속국 모양 하나**(옅은 바탕 + 제 색 파선 테두리) — 선 모양은 이미 다 쓰였고 파스텔에서 바탕 짙기 다섯 단계는 구별되지 않으므로, 종류끼리는 **탭의 딱지**로 가릅니다. CSS는 파일 끝에 `.tl-lane .tl-band.fam-dep` / `.tl-tab.fam-dep` / `.lg.fam-dep`로 한 번에(기존 `kind-vassal` 세 층과 같은 세기).
* `exile`: 옅은 바탕 + 딱지. `movement`: 옅은 바탕 + 왼쪽 **깃대**(`.tl-band.kind-movement:not(.clip-l)::before`, 3px, 띠 모서리를 따라 둥글게, 테두리 굵기는 건드리지 않음). 실재성(8-4 마)의 전설 · 반전설 띠는 안개가 같은 `::before`를 쓰므로 깃대 규칙에서 빼고 안개 안쪽 왼쪽 3px의 그림자로 그림(안개와 함께 옅어지고, 그림 내보내기의 깃대도 같은 가림막) · 부정됨이면 깃대도 회색.
* **예속 띠**(`.tl-dep`)를 `layoutStrip`으로(keyOf = 상국 uid): 같은 상국 아래 관계만 바뀌면 하나의 긴 둥근 칸 + 구분선, 상국이 바뀌면 끊김. 글은 들어가는 대로 `〈관계 딱지〉 · 〈상국〉` → `〈상국〉` → `〈딱지〉` → 없음. **종속이 깊을수록 상국 색이 짙게**: 자율성 3 = 상국 색 테두리만(속 빔) · 2 = 옅은 칠 · 1 = 중간 · 0 = 짙은 칠(`union`은 3과 같은 모양). 짙기는 JS의 숫자표 하나(`DEP_MIX = [..%]`)가 `--mix`를 퍼센트로 넘김(`toSVG`도 같은 표). 홀짝 `is-alt`는 그 띠의 어느 구간에도 relation이 없을 때만. `relation`이 없을 때 `kind`에서 빌린 이름은 **설명글에만**(옛 파일의 띠 글이 바뀌지 않게).
* 예속 띠 자리는 **줄 단위**(`geoFor`가 줄별로: 그 줄에 예속 띠를 그릴 정권이 있을 때만) — `g.depH`를 읽는 곳을 `geoOf(row).depH`로.
* 접혀 있는(`nest`) 소속도 펼쳤을 때 탭에 관계 딱지. 소속선 설명글에 관계 이름. `toSVG`의 하드코딩(`'vassal'` · `'federation'` · `'org'`)을 갈래 기준으로.
* 범례: 지금 자료에 **쓰인 종류만**(`kindsUsed`), 종속 갈래는 "종속 갈래 — 딱지로 구분" 한 줄 + 예속 띠 짙기 견본 네 칸.
* **뒤집기 (2026-09-20 감독 결정 — 위 세 줄의 예속 띠 · 탭 딱지 · 파선 테두리를 대신함)**: 감독이 "보호 · 조공이라는 말로 퉁쳐지는 게 짜친다 — 배열 · 빗금 같은 글자 없는 디자인으로", 이어서 글자 없는 세 안(상국 빛이 속국 띠 안에서 차오름 · 상국 빛 빗금 · 위아래 방향 — 모두 상국이 속국 띠 안)을 보고 "종속된 국가 띠 안에 상국 띠가 있는 게 마음에 안 든다, 반대가 되어야"라고 함. 뒤집은 두 안 가운데 **R2 매달림 · 품음**을 고르고 "안의 속국 띠와 상국 사건이 겹치지 않게, 들어가면 자연스럽게 넓게"를 덧붙임. 자료 형식은 그대로입니다.
  * 속국 띠 안에는 상국을 그리지 않고, 책갈피 탭에 종속 갈래 · 소속 관계의 글자 딱지도 달지 않습니다. 종속 갈래의 제 띠는 옅은 띠 하나(테두리는 실선 — 점선은 추정 · 미정 연대만).
  * **상국 띠가 속국 이름표를 품습니다**(`Timeline.depProxies` — 트랙이 달라도): 스스로 다스린 관계(자율성 3 · 2 · 명목상 · 구성국 · 동군연합 · 관계를 적지 않은 소속)는 상국 띠 아랫변 밑에 끼워 **매달린 탭**(`.tl-hang` — 빈 탭 · 칠한 탭 · 점선 · 파선), 상국이 다스린 관계(1 · 0)는 상국 띠 안 맨 아래의 **품은 칸**(`.tl-dep` — 옅은 칸 · 짙은 칸 · 빗금 칸). 밖 ↔ 안을 옮긴 때는 **세로 끈**(`.tl-hang-link` — 다른 이름표를 가로지르면 긋지 않음).
  * 자리: 품은 칸은 기간 막대 아래의 예속 칸 자리(줄 수만큼 — `depRows`), 매달린 탭은 구역 탭처럼 띠 아래 덧붙는 높이(`hangRowLanes` → `rowCut`, 구역 탭은 그 아래) — 둘 다 줄 단위, 자료로 정하므로 사건 글줄 · 막대와 겹치지 않고 화면을 움직여도 높이가 그대로. 줄은 상국마다 밖 · 안을 따로 나누고 0번 줄이 띠 아랫변에 가장 가까움(밖 ↔ 안을 옮긴 속국이 먼저, 나머지는 시작 순 · 같이 시작하면 오래 매인 쪽 먼저).
  * 이름표는 속국의 빛깔 · 이름(들어가는 대로 이름 → 첫 글자 → 없음), 길이는 소속 기간, 같은 속국의 이어지는 구간은 하나의 긴 칸 + 구분선, 칸의 미정은 그쪽 끝이 옅어짐. 누르면 그 속국(`data-uid`) · 올리면 같은 트랙의 속국 띠도 진해짐 · 모여드는 움직임에서 제 상국 띠를 따라감(`data-band`).
  * 접힌 소속(`singleHost`)은 이름표 없음(이미 상위 띠 밑) — 소속선은 이제 접혔다 펼친 소속에만. 그림 내보내기 · 범례(매달린 탭 · 품은 칸 견본) · 종류 설명(hint) · 견본 sample-kinds의 글도 같게. dev-smoke ㉜.

### 2-3. 상세 · 메이커
* 소속 목록(`partOfHTML`)에 관계 배지 · 글. 종류 배지는 저절로.
* 시대 폼: 종류 고르기는 갈래별 `optgroup`(자주 · 종속(자율성 순) · 특수). 소속 줄에 **소속 관계 고르기 + `상위 띠 아래에 접기` 체크**(시대 폼에서만 — 같은 줄을 쓰는 기관 · 왕조 폼에는 안 보이게. `.map(HT.partOfRowHTML)`은 index를 둘째 인자로 넘기므로 `s => HT.partOfRowHTML(s, opt)`로, 줄 추가 단추는 `[data-parts]`의 data 속성으로 어느 폼인지 앎). 메이커 표에서 소속을 바로 고칠 때도 `relation` · `nest` 보존. `KIND_ALIASES`의 '조공국' · '속국' 뭉개기를 풀고 새 이름 추가. 패치 탭 `fmtVal`이 소속 목록을 "[object Object]"로 적지 않게.
* 검사: 모르는 `relation`은 경고(무시).
* 하지 않음: DLC가 정의하는 **내 종류**(전역 등록은 DLC를 꺼도 남고, 정규화가 팩마다 따로 돌아 다른 DLC의 종류를 잃음).

## 3. 지위 (건의 1)

### 3-1. 형식
```json
"rankDefs": [ { "id": "king", "name": "왕", "tier": 8, "aliases": ["국왕"], "description": "" } ],
"periods": [ { "name": "…", "ranks": [ ["공", null, -325], { "name": "왕", "start": -325, "note": "" } ],
               "leaders": [ { "name": "…", "start": -337, "end": -311, "rank": "왕" } ] } ]
```

* `rankDefs`(최상위, 선택) — **지위 사전**: `id` · `name` · `tier`(서열, 클수록 높음 · 비우면 서열 밖) · `aliases` · `description`. 병합은 **id로만**, 참조는 id → 이름 → 별칭. 우선순위: 켠 DLC들(먼저 정의가 이김) → 맨 끝에 내장 사전(빈 자리만 채움). 사전에 없는 이름을 적어도 됩니다(서열 없는 지위로 다룸).
* 내장 사전 `HT.RANKS`는 **서열 뼈대만**: 황제 8 · 왕 7 · 대공 6 · 공 5 · 후 4 · 백 3 · 자 2 · 남 1, 서열 밖: 대통령 · 총리 · 주석 · 섭정. 문화권 고유 칭호와 그 대응(무엇이 왕과 같은 격인가)은 **자료**이므로 내장하지 않고 감독이 지위 메이커 탭에서 적습니다. 별칭은 **서열(짙기)만 빌리고, 화면에는 적은 글을 그대로** 그립니다.
* `periods[].ranks` — 칸 목록(연호와 같은 틀). 저장되는 기준 칸은 `name`(읽을 때 `rank`도 받음). **첫 칸의 시작을 비우면 정권 시작부터**, 끝을 비우면 다음 지위가 시작할 때까지(없으면 정권 끝까지).
* `leaders[].rank` — 그 지도자의 지위(선택).

### 3-2. 모델
* `p.rankSpans`(모델 전용) = 적힌 `ranks`를 풀어 끝을 채운 것(`endY`) + 각 칸에 `name` · `tier` · `def`. `ranks`가 없고 지도자에게만 `rank`가 있으면 같은 지위가 이어지는 구간을 묶어 **끌어냄**(`derived: true`). 연표 · 뷰어 · 검색이 모두 이 배열과 순번을 봅니다.
* `leaders[].rankAuto` = 즉위한 해의 정권 지위(`rank`를 안 적었을 때).

### 3-3. 연표
* **지위 단**: 왕조 칸과 지도자 칸 사이(`G.rank = 13`). 조건 = `show.ranks !== false` 이고 그 트랙에 **`rankSpans`가 둘 이상인 정권**이 하나라도 있을 때(보기 밀도 `빽빽하게`에서는 없음). 하나의 긴 둥근 칸 + 가는 구분선(`layoutStrip`, keyOf = 늘 같은 값), 글은 이름 → 첫 글자 → 없음. **서열이 높을수록 제 색이 짙게** — 네 묶음(사전 전체의 서열을 4등분 + 서열 밖은 중립)이라 같은 지위는 어느 나라에서나 같은 짙기. 홀짝 `is-alt` 없음. `data-cell="rank:i"`(i = `rankSpans` 순번).
* 지위 단이 없는 트랙에서 지위가 **하나뿐인** 정권: 책갈피 탭의 이름 뒤에 작은 지위 딱지(`<small class="rk">`, 종류 딱지와 같은 꼴 — 탭 폭 계산에 포함, 자리가 없으면 생략).
* 지도자 칸 설명글 · `HT.leaderFull`에 지위. 왼쪽 줄 이름 아래 부제는 `지도자 · 지위(첫 글자) · 왕조`. 지도자 칸의 띠 끊김(`keyOf`)에는 지위를 넣지 않습니다.
* 표시 체크 `지위`(기본 켬). `toSVG`에 같은 단.

### 3-4. 상세 · 검색 · 메이커
* `parseCellRef`에 `rank` 갈래. 지위 칸 상세는 `cellDetailHTML`을 재사용하지 않고 따로: 지위 · 서열 · 기간 · 그 기간의 지도자들 · 앞뒤 지위(승격 ▲ · 격하 ▼는 **여기 목록에서만**) · 정권 문서로 가는 링크. 누르면 그 기간 조명. 정권 상세에 "지위" 목록(`data-year`), 지도자 칸 상세에 지위 배지. 같은 해 보기의 "그때 각 나라는"에 그 해의 지위.
* 검색의 칸 찾기에 지위. **지위 칸 문서는 두지 않습니다**(문서 키 정규식 · 칸 종류 목록 아홉 곳을 고칠 값어치가 없음).
* 시대 폼: "지위 변천" 줄(`data-cells="ranks"`: 지위(자동 완성) · 시작 · 끝 · 메모) + 여러 줄 붙여넣기. 지도자 줄에 `지위` 칸. `readCells` · `readCellRows` · `fillCellRows` 종류 배열 · 붙여넣기 라벨 표 · 접힘 구역 여는 조건 · `PATCHABLE` · 패치 재정규화 목록 · `describePeriods` 칸 목록 · `FIELD_LABELS` · `FIELD_NAMES`.
* 바탕 메이커 탭 **지위**: 사전 표(id · 이름 · 서열 · 별칭 · 설명) + `기본 지위 넣기`(내장과 같은 id로 채워 고쳐 쓸 수 있게). 바탕 표(`renderTable`)를 "열 설정표" 방식으로 일반화해 지위 · 가문이 함께 씁니다.

## 4. 가문 (건의 2)

### 4-1. 형식 · 모델
```json
"houses": [ { "id": "h-a", "name": "…", "surname": "…", "seat": "…", "parent": "…(본가)", "founder": "…", "color": "#a0bcc5", "description": "", "wiki": "" } ]
```
* 병합은 id로만(먼저 정의가 이김), 참조는 id → 이름. `parent`로 **본가 → 분가** 나무. 등록하지 않은 이름을 적으면 자동 등록.
* 가리키는 칸 `house`: 시대(= **국성**) · 지도자 · 내각 · 인물 · 왕조. **원문은 모델에서 고쳐 쓰지 않고** 풀어낸 것은 `houseId` · `houseName`에.
* 왕조의 `house`는 지금 "본가 왕조 이름"으로 쓰입니다 → 두 해석을 **따로** 계산: 가문 사전에 있으면 `houseId`, 그리고 기존 본가 왕조 찾기는 지금 그대로. 둘 다 아닐 때만 가문으로 자동 등록. 왕조 폼의 칸 설명에서 실제 이름 예시를 지우고 "가문(가문 탭의 이름) — 옛 파일의 본가 왕조 이름도 읽습니다". 패치 · 뷰어의 칸 이름은 종류별로(시대 = 국성, 왕조 = 가문·본가).
* 지도자의 가문: `leader.house` → 즉위 해 왕조의 가문 → 시대의 국성(`houseAuto`).
* `model.houses`(나무) · `houseMap` · 가문마다 `members`(지도자 · 내각 · 인물 · 왕조 · 국성으로 삼은 나라 — 시작 순). 문서 키 `house:<id>`(`HT.docKey`의 접두어 정규식 **세 곳** + 문서 ↔ 대상 연결(core.js 1621-1633)이 `houses[].wiki`를 잡게).

### 4-2. 연표
* 지도자 · 내각 칸, 인물 막대, 왕조 칸에 `data-house`. 설명글에 가문.
* 표시 체크 `가문`(기본 **끔**): **가문 줄** — 칸과 별개인 `<i class="tl-houseline">`을 지도자 칸 아래 테두리 바로 안쪽에(같은 가문이 이어지는 구간마다 하나, `layoutStrip` keyOf = 가문, 긴 칸의 둥근 끝에서는 3px 안으로, `pointer-events` 없음). 칸의 `box-shadow`/`background`를 쓰지 않으므로 올림 · 조명 상태와 부딪히지 않습니다. 빽빽한 칸(`is-dense`)일 때는 그리지 않음.
* 가문 창이 열려 있는 동안 그 가문의 칸 · 막대가 `is-house`로 진해짐(`timeline.setHouse(id)`, `_applyStates`).

### 4-3. 가문 창 · 메이커
* `openDetail('house:<id>')`(0-1의 갈래 표): `setSelected(null)` + `setHouse(id)` + `setAnchor(null)`. 구성: 머리(이름 · 배지: 성 · 본관 · 본가 → 분가 길 칩 · 갈라져 나간 분가) · **국성으로 삼은 나라** 칩 · **구성원 목록**(나라별로 묶어 시작 순, 역할 딱지, `data-uid` · `data-year`) · 문서 · 하위 문서. 단추는 `data-doc` · `data-year` · `data-uid`만. `refresh()` · `setEditMode` · 문서의 "연표에서" 단추가 `house:` 꼴을 알게.
* 지도자 칸 · 인물 · 왕조 · 시대 상세에 가문 배지(누르면 가문 창). 검색 결과 종류 `house`, `[[가문 이름]]` 링크 · 자동 완성, 범례 한 줄.
* 바탕 메이커 탭 **가문**(열 설정표: id · 이름 · 성 · 본관 · 본가 · 색 · 설명, 쓰는 곳 역참조, id·이름을 바꾸면 `leaders[].house` 같은 중첩 참조까지 함께). 지도자 · 내각 줄에 `가문` 칸(내각은 연호와 줄 갈래를 나눔), 시대 폼에 `국성`, 왕조 폼의 자동 완성은 가문 + 왕조 이름. 문서 탭 대상에 가문.
* 뒤로 미룸(2차): 가문 연대 막대 그림.

## 5. 인물 (건의 6)

### 5-1. 형식
```json
"figures": [ { "id": "f-x", "track": "a", "name": "…", "aka": ["…"], "role": "장군",
  "birth": 1545, "death": "1598-12-16", "start": 1576, "end": 1598,
  "service": [ { "polity": "…", "office": "…", "start": 1591, "end": 1598 }, { "track": "b", "polity": "…" } ],
  "house": "…", "importance": 3, "description": "", "tags": [], "source": "", "wiki": "" } ]
```
* `track` · `name` 필수. 날짜는 `birth`·`death`(생몰) · `start`·`end`(활동) · `service[].start/end` 가운데 **하나 이상**. 활동 시기를 비우면 섬긴 기간의 합, 그것도 없으면 생몰.
* `role`은 자유 글(자동 완성은 일반 명사: 장군 · 재상 · 관료 · 학자 · 승려 · 예술가 · 상인 · 탐험가 · 왕족 · 봉기 지도자). 사건 쪽에 `events[].figures: ["이름"]`(관련 인물).
* 전용 읽기(시작이 선택 사항) · id 접두어 `f-`, 자동 id의 씨앗은 **트랙 + 이름(+ 생년)**(섬긴 기록을 고쳐도 id가 안 바뀜). `DATED`에 `figures`, `HT.DATE_KEYS`에 `birth` · `death`. `service`는 패치에서도 다시 정규화. `HT.USER_LISTS`에 `figures`.

### 5-2. 모델
`figureMap`(패치 · 내 수정 · 숨김의 조회 사슬에 추가) → `model.figures`, `byUid`(`kind:'figure'`, `itemKind:'figure'` — 갈래는 늘 `HT.itemKindOf`로). 시기 계산은 **패치 · 내 수정이 끝난 뒤**: `start` · `endY`(짐작이면 `startAuto` · `endAuto` — 수정 폼은 그 칸을 비워 둠) · `polityUid`(첫 섬긴 정권) · `services[]`(정권 uid · 색, 정권 기간 안으로 잘림). `service`가 없으면 활동 가운데 해의 같은 트랙 정권에 자동 배정. 트랙 자동 생성 · 색 배정 · 사건 소속 후보에 섞이지 않게 `periods`에 넣지 않습니다.

### 5-3. 연표 — 인물 단
* **자료의 길**: `setData({ …, figures, scopes })`가 받아 `this._data`에도 싣습니다(`relayout()`이 `_data`로 다시 짓기 때문 — 빠뜨리면 첫 접기에서 통째로 사라짐). 뷰어 `applyFilters`가 **보이는 트랙 · 중요도 필터를 통과한 인물**만 넘기고, 메이커 미리보기 두 곳도 넘깁니다.
* 자리: **기간 막대 아래 · 예속 띠 위**, 줄마다 단 수가 다름. `geoFor(L, 인물 단 수, 예속 띠 유무)`로 넓히고 모든 줄에 제 geo를. 한 단 `G.figure = 15`, 단 사이 2.
* 그림: 기관 칸(`.tl-org.is-agency`)처럼 **줄 직속 요소** — `data-k="f:인물uid:정권uid"` · `data-uid` · `data-row` · `data-house`, 띠 안쪽으로 가두는 계산도 기관 칸과 같이. 그래서 떠오름(`_laneFx`) · 상태 유지 · 올림 강조 · 고름이 저절로 붙고 부모 띠의 흐림을 물려받지 않습니다. **활동 막대**(둥근 칸, 이름은 들어갈 때만 → 첫 글자 → 없음, 중요도 3은 굵게) + **수명선**(생 ~ 몰의 가는 선)은 평소 숨기고 **올리거나 골랐을 때만**(`--t-in`) — 기간 막대와 같은 "눈금 달린 가는 선"이 늘 겹겹이 놓이지 않게.
* 단 배정: 줄 배정이 끝난 뒤 **줄 단위**로(계승으로 한 줄을 같이 쓰는 앞뒤 띠에서 같은 사람이 다른 단으로 튀지 않게), **활동 막대만**으로, 중요도 높은 순 → 시작 순으로 위 단부터. 최대 단 수는 1절 표대로. 넘치는 인물은 그리지 않습니다(정권 상세의 인물 목록에는 모두 나옴). 빽빽하면(막대 평균 폭 6px 미만) 단 전체를 `인물 n명 — 확대하면 나뉩니다` 한 칸으로.
* 상위 띠 아래 숨은 정권 · 접힌 민족 줄의 인물은 사건처럼 보이는 상위 줄로(`rowFor`), 바탕 문화 · 기관을 섬긴 인물은 그리지 않음(상세에서만).
* `_anchorLane`에 인물 → 섬긴 정권의 줄 찾기, `focusOn`은 인물이면 섬긴 정권 기준으로 접힌 민족 · 숨은 소속을 폄. `setSpotlight`가 **배열**도 받음(`this.spots` — 두 정권을 섬긴 인물은 띠마다 조명).
* 표시 체크 `인물`(기본 켬). `toSVG`에도.

### 5-4. 상세 · 검색 · 메이커
* 인물 상세(갈래 표): 이름 · 다른 이름 · 역할 배지 · 생몰(향년) · 가문 배지 · **섬긴 기록**(정권 칩 · 직함 · 기간) · 관련 사건(사건의 `figures`에서 역으로) · 같은 시기의 지도자 · 설명 · 출처 · 문서.
* 정권 상세에 "인물" 목록, 지도자 칸 상세에 "이 시기의 인물"과 **같은 이름의 인물 링크**(이름 · 다른 이름이 같고 시기가 겹치면 자동 — 새 입력 칸 없음), 사건 상세에 관련 인물 칩, 같은 해 보기에 그 해 활동한 인물.
* 검색 · 표 보기는 `state.visible`(시대 + 사건)만 돌므로 셋째 목록 `state.visibleFigures`를 둠. 구분 `인물`. 문서 링크의 이름 찾기 순서는 항목 → 칸 → **인물**(기존 링크의 목적지가 바뀌지 않게), `[[인물:이름]]` 꼴로도.
* 내용 메이커 탭 **인물**: 표(이름 · 역할 · 생 · 몰 · 섬긴 정권 · 중요도) + 드로어 폼(`HT.FORMS.figure`, 섬긴 기록 줄: 트랙 · 정권 · 직함 · 기간 · 메모) + 빠른 추가. 사건 폼에 `관련 인물`. 미리보기 · 검사 · 패치 대상 · 뷰어 추가 길(우클릭 메뉴 · 단축키).

## 6. 조약 (건의 4)

### 6-1. 형식 — 사건에 얹는 조약 규격
조약은 새 목록이 아니라 **사건의 `treaty` 묶음 칸**입니다. 이미 사건으로 적어 둔 조약이 그대로 조약이 되고, 패치로 기본팩의 사건에도 규격을 얹을 수 있으며, 위치가 어긋날 일이 없습니다(체결 = 사건의 `start`, 실효 = `end`, 아직 유효 = `ongoing`).

```json
{ "track": "a", "title": "통칭", "start": "1876-02-27", "end": 1910, "category": "diplomacy",
  "treaty": { "formal": "정식 명칭", "type": "peace", "unequal": false,
    "ratified": "", "effective": "", "endReason": "abrogated", "place": "…", "languages": ["…"],
    "parties": [ { "track": "a", "polity": "…", "side": 1, "role": "…", "signatories": [ { "name": "…", "title": "…" } ] },
                 { "track": "b", "polity": "…", "side": 2, "signatories": "이름(직함); 이름(직함)" } ],
    "articles": [ { "no": "제1관", "title": "…", "tag": "recognition", "text": "…" } ],
    "concludes": "끝낸 전쟁(사건)", "supersedes": "대체한 조약" } }
```
* `type`: `peace` 강화 · `armistice` 휴전 · `alliance` 동맹 · `nonaggression` 불가침 · `trade` 통상 · `border` 국경 · `cession` 할양·병합 · `protectorate` 보호 · `investiture` 책봉·조공 · `marriage` 혼인 · `other`. `endReason`: `expired` · `abrogated` · `superseded` · `fulfilled` · `annulled`. `articles[].tag`: `territory` · `indemnity` · `trade` · `extraterritorial` · `military` · `recognition` · `other`. 모두 한국어도 읽음(어휘마다 따로).
* `side`: 같은 편끼리 같은 수. 비우면 **모두 한 목록**. 서명자는 `[{ name, title }]` 또는 글 `이름(직함); …`(같은 값으로 비교되게 비교용 정리 함수). 조항은 문자열 목록도 읽음. `ratified` · `effective`는 날짜 글을 받음(`ratifiedAt` 짝 칸 — `unfoldDates`가 재귀라 중첩도 풀림).
* `readTreaty`(화이트리스트)로 정규화하고 `PATCHABLE`에 `treaty`(통째 교체 — 지도자 목록과 같은 방식, 패치에서도 다시 정규화).

### 6-2. 모델 · 연표
* `itemKind: 'treaty'`(= `treaty` 칸이 있는 사건 — `HT.itemKindOf`). 함께 겪은 자리(`placements`)를 만들 때 **당사국을 더함**(이 단계는 이미 패치 · 내 수정 뒤에 돎). 풀어낸 참조는 모델 전용 `x.treatyRefs`(당사국의 정권 uid · 색, 서명자 ↔ 같은 이름의 인물, 끝낸 전쟁 · 대체한/대체된 조약의 uid) — 원래 `treaty`는 제자리에서 고치지 않습니다.
* 점 대신 **마름모 인장**: `.tl-ev.is-treaty .d`에 `rotate: 45deg`(`transform`이 아니라 개별 속성 — 올림 · 고름의 `scale` 규칙과 안 부딪힘), 한 변은 채운 것 5px · 속 빈 것 6.4px(대각선이 기존 점 지름을 넘지 않게), 모서리 둥글기 1px 이하. 조약은 거의 늘 `shared`이므로 `.is-treaty.is-shared:not(.is-pair) .d`는 **채움을 되돌림**(첫 자리 = 채운 마름모, 다른 당사국 자리 = 속 빈 마름모).
* 기간이 있으면 **겹줄 가는 선**(`.tl-rail.is-treaty`, 올림 · 고름용 높이 규칙을 같은 세기로 따로). 발효가 체결과 다르면 작은 눈금 — 기간 막대가 있을 때만. 중요도 가중은 **하지 않습니다**(감독이 매긴 중요도를 뒤집지 않음). 이름 없는 조약 점이 알약에 묶여 모양이 사라지는 것은 허용하되 묶음 카드 목록에는 마름모를 보임. 범례 · `toSVG`에 마름모.

### 6-3. 상세 — 조약문 양식
`itemKind === 'treaty'`면 큰 틀의 "…가 함께 겪은 일입니다" 글과 기본 기간 줄을 끄고 양식이 대신합니다.
1. 머리: 종류 배지 · (불평등) · 통칭 · 정식 명칭
2. **당사국**: 편이 정확히 **둘**일 때만 좌우로 맞세우고, 그 밖에는 세로 목록(편 제목 + 카드). 카드 = 정권 색 칩(누르면 그 나라) · 역할 · 서명자 `이름 — 직함`(같은 이름의 인물이면 링크)
3. **날짜 진행 표**: 체결 → 비준 → 발효 → 실효(있는 것만) · 사이 간격 · 끝난 까닭
4. **조항**: 번호 · 제목 · 분류 칩, 본문은 접었다 펴기
5. 관련: 끝낸 전쟁 · 대체한/대체된 조약 · 장소 · 언어 · 출처 · 문서

검색 글(`_hay`)에 정식 명칭 · 장소 · 당사국 · 서명자 · 조항 제목. 표 보기 구분 `조약`.

### 6-4. 편집
* 사건 폼(뷰어 수정 모드 · 메이커 공용 `HT.FORMS.event`)에 접는 구역 **조약 규격**(`details.adv[data-adv="treaty"]`): 정식 명칭 · 종류 · 불평등 · 비준 · 발효(날짜 칸) · 끝난 까닭 · 장소 · 언어 · 당사국 줄(트랙 · 정권 · 편 · 역할 · 서명자 글) · 조항 줄(번호 · 제목 · 분류 · 본문 textarea) + **조항 한꺼번에 붙여넣기**(`제n조` · `제n관` · `Article n`으로 시작하는 줄에서 나눔) · 끝낸 전쟁 · 대체한 조약. 폼에서는 시작 · 끝 칸의 이름표가 조약일 때 `체결` · `실효`. 구역을 비우면 `treaty` 칸이 사라져 보통 사건으로 돌아갑니다.
* 내용 메이커 탭 **조약** = `treaty`가 있는 사건만 거른 보기(표: 통칭 · 체결 · 종류 · 당사국) + `새 조약`(분류 외교 · 조약 구역이 열린 사건). 사건 탭의 드로어에는 `조약으로 바꾸기`. 뷰어 추가 길에 `조약 추가`.

## 7. 대범위 (건의 7)

### 7-1. 형식 · 모델
```json
"scopes": [ { "id": "s-x", "track": "a", "name": "…", "label": "시대", "start": 892, "end": 936,
              "members": ["…", "…"], "epoch": "…", "color": "#d7c18e", "default": false, "description": "", "note": "", "wiki": "" } ]
```
* `track` · `members` 필수, `name`은 `epoch`이 없을 때 필수. `epoch`(같은 뜻의 시대 구분 이름·id)를 적으면 비워 둔 **이름 · 기간 · 색을 시대 구분에서 물려받습니다**(두 번 적지 않게, 폼에 `시대 구분에서 가져오기`). 기간을 끝내 모르면 구성 정권의 범위. `label`은 성격(자유 글).
* 구성 정권은 **같은 트랙 안에서만** 모입니다(`.tl-track`이 `contain: paint`, `.tl-lanes`가 `overflow: hidden` — 띠가 트랙을 넘을 수 없음). 다른 트랙은 검사에서 경고.
* 시대 구분과 같은 부류: **뷰어에서 수정 · 숨김 없음**(폼은 메이커 전용), 패치 대상 아님 — 뷰어의 epoch 예외 자리(수정 열기 · 우클릭 메뉴 · 문서의 focus)에 scope를 더합니다. `DATED`에 `scopes`. 모델: `model.scopes`, `byUid`(`itemKind:'scope'`), `scope.members`는 정권 객체 목록(원문은 `memberRefs`), 정권 쪽 역참조 `p.scopes`.

### 7-2. 배치
* 상태: `opts.scopesOn` · `toggleScope(uid, force)` · `onScope(list)`. 뷰어는 `ui.scopes: { uid: true|false }`, 기록이 없으면 `default`.
* `_layoutTrack`: **먼저 전원으로 민족 나무를 짓고 → 가지마다 시작 해(`start0`)와 `tr.depth`를 그 상태로 확정 → 그다음에** 켠 대범위의 구성 정권만 합성 가지 `__scope:<uid>`(뿌리 바로 아래)로 옮깁니다. 정렬은 `start0`으로, 왼쪽 칸 폭은 옮기기 전 깊이로 — 켜고 꺼도 **다른 민족 묶음의 순서와 왼쪽 칸 폭이 그대로**입니다. 한 정권이 켠 대범위 둘에 들면 먼저 시작한 쪽. 상위 띠 아래 숨은 소속은 상위를 따라가고, 가지 안에서도 계승으로 이어진 정권은 같은 줄.
* 왼쪽 칸: 민족 칸 전체 폭을 쓰는 세로 칸(`.tl-people.is-scope`), 누르면 민족처럼 접힘. `toggleScope(on)`은 그 가지의 접힘 열쇠를 지워 **늘 펼친 채** 모이게. `focusOn`이 `__scope:<uid>` 접힘도 풉니다.
* **집합 테두리**(`.tl-scope`, 띠 뒤, 몸통은 `pointer-events: none`): 세로 = 가지의 줄들 + **머리 16**(책갈피 탭 자리 **위**: `top = rowTop[가지의 펴진 첫 줄] − G.tab − 머리`) + 아래 6. 간격은 도우미 하나(`_scopePad`)를 `_layoutTrack`과 `_foldRows`의 **두 간격 공식 끝에 똑같이** 더합니다(가지가 트랙의 첫 줄인 경우 포함). 되돌아가는 계승선의 우회 높이는 머리 몫을 뺀 간격으로. 세로 자리는 `_buildTracks`에서 접힌 크기로 태어나 `_collapseRows`의 민족 칸 갱신 옆에서 함께 쓰고(`.tl-scope`를 common.css의 top·height 전환 목록에), 가로 자리는 매 그리기의 `_drawScopes(tr, X, W)`에서 −1 ~ W+1로 잘라 `clip-l`/`clip-r`(전환 없음).
* 테두리의 **가로 = 구성 정권 띠 전체의 범위**(오래 간 나라가 구성 정권이어도 띠가 테두리를 뚫고 나가지 않게), 그 안에서 **대범위의 기간은 조금 더 짙은 세로 구간**. 둥근 모서리 12 · 대범위 색 옅은 칠 + 톤 테두리. **이름표**는 테두리 왼쪽 위 — 테두리 왼쪽 끝이 화면 안에 있을 때만 보이고 밖으로 나가면 옅어지며 물러납니다(그때는 왼쪽 세로 칸이 이름을 말함). 누르면 대범위 상세. `toSVG`에도 테두리.
* 구현 메모(배치 단계): 켜고 끌 때 붙잡는 줄은 상징적 본국이 있으면 **본국 줄**(줄 번호가 아니라 그 정권을 다시 찾아 — 위쪽에 있던 구성 정권이 빠져 번호가 바뀌어도 본국 줄이 화면에서 제자리), 없으면 트랙 위쪽. 토글은 `relayout`을 거치지 않아 '밀려남 알림'이 뜨지 않고, 그 트랙의 전체 떠오름(`is-opening`)도 떼어 떠오르는 것은 테두리 · 왼쪽 칸(`is-born`)뿐. 본국 줄에 매달린 가지는 머리가 `머리 + 2 − (gap + groupGap)`만큼(테두리 위쪽이 본국 줄 아랫변). 테두리가 좁아 이름표가 들어가지 않으면 성격 → 이름 순으로 줄이고 그래도 안 되면 물러남(테두리 밖으로 나가지 않게). 칩 줄의 칩은 시트를 먼저 접고 `--t-out` 뒤에 켭니다. 모여드는 움직임(7-3)이 들어오며 붙잡는 줄은 7-3의 구현 메모대로 바뀌었습니다(다시 지을 때는 트랙 위쪽 · 스크롤 0px, 그다음 누른 본국 줄만 따라가며 붙잡음).
* 구현 메모(검토 반영): 켠 대범위로 떠난 정권은 옛 상위를 펼쳐도 그 아래에 다시 놓이지 않고(`pushMembers`), 본국 띠의 `▸ n`도 세지 않으며, 검색 · 여기로 가기는 옛 상위 대신 가지의 접힘만 풉니다. 본국 줄에 매달린 가지는 간격 전체가 머리(위 2 · 이름표 14 · 아래 2 · 탭)라 되돌아가는 계승선은 반대쪽 빈 곳으로 돌고, 계승선 · 소속선은 이름표 자리(`_scopeLabelRect`)를 비켜 갑니다(소속선은 이름표 오른쪽으로, 자리가 없으면 긋지 않음). '직접 계승만'이면 부흥선 묶음도 숨깁니다. 민족 칸이 한 단뿐이면(`this.depth === 1`) 가지 안의 민족 딱지는 대범위 칸 안쪽 오른쪽 끝의 가는 띠(폭 5 · 글 없음)가 되고 이름은 그 왼쪽에 남습니다.

### 7-3. 모여드는 움직임 (별도 커밋)
한 손짓, 한 시계 — `T.move` + `C.spring`, `_applyFlip`이 높이 전환을 거는 **같은 호출 안에서** 시작.

* **스크롤은 0px**: `toggleScope`가 다시 짓기 전에 `_pressHold = { trackId, row: -1 }`(트랙 위쪽을 붙잡음), 닻이 있으면 비워 새 자리를 기준으로. 옛 · 새 자리는 **화면 좌표**(`getBoundingClientRect().top`)로 — 옛 것은 `toggleScope` 안에서 다시 짓기 직전, 새 것은 `_applyFlip` 뒤(남은 스크롤 보정과 진행 중인 이동까지 흡수).
* 세 갈래:

| 새 줄의 정권이 | 움직임 |
| --- | --- |
| 모두 같은 옛 줄에서 옴 | **줄째로** 이동(탭 · 사건 · 기간 막대 함께) + 왼쪽 줄 이름도 같은 거리 |
| 섞임(끌 때 계승 사슬 줄로 합쳐지는 구성 정권) | 줄의 기준은 구성 정권이 **아닌** 쪽의 옛 줄(대개 0), 구성 정권은 줄 안에서 **정권 단위**(`b:` · `tab:` · `m:` 요소)로 이동, 그 정권의 사건은 `--t-in`으로 떠오름 |
| 옛 줄이 접혀 있었음 / 접힌 민족 줄로 들어감 | 옮기지 않고 `--t-in` 떠오름만 |

* 건국·멸망 네모는 줄별 `<g data-row>`로 묶어 줄과 같은 거리 · 같은 시계로. 계승선 · 소속선은 컨테이너에 `지연 160 + --t-in` 떠오름(이동과 같은 순간에 도착 — 끝나는 시각이 둘을 넘지 않게). 다시 그려져도 이어지도록 `tr._gather = { t0, dy }`를 두고, `innerHTML`을 다시 쓴 직후마다 지난 시간만큼 음수 delay로 다시 붙이는 도우미 하나.
* 테두리 · 왼쪽 세로 칸은 `--t-in`으로 떠오름. 켠 뒤 테두리가 화면에 안 걸리면(머리 + 한 줄 미만) 지금의 데려오기 장치로 **최소 거리만**, 걸려 있으면 0px. 토글에서는 정권별 "밀려남 알림" 칩을 띄우지 않습니다.
* 토글 한 번에만: 트랙 전체 떠오름(`is-opening`/`is-closing`) · 새로 생김/없어짐 효과(`_was`) · 줄 번호로 이어받는 접힘 기억(`tr._rowMemo = false`)을 끕니다. 자료 갱신(메이커 미리보기의 주기적 `setData`)에는 재생하지 않음. 동작 줄이기면 즉시.
* 코드 자리(다른 채팅과의 충돌 줄이기): `setData`에는 `_applyFlip` 다음 **한 줄** `this._gather(before)`, 그리기는 `_drawLinks` 호출 다음 한 줄 `this._drawScopes(tr, X, W)`, 새 메서드는 `toSVG` 바로 앞에 한 덩어리. 한 줄짜리 상수(`G` · `AXIS` · `this.show`)는 그 줄을 고치지 않고 다음 줄에 `Object.assign(G, { … })`로.
* 구현 메모(모여듦 단계): 옛 자리는 `toggleScope`가 다시 짓기 직전에(`_gatherFirst` — 줄 · 정권 띠 · 민족 칸 · 테두리의 화면 좌표, 도중에 다시 누르면 진행 중인 이동까지), 새 자리는 `_applyFlip` 뒤에 재어 줄별 표(`tr._gather.rows` — `dy` · 정권 단위 `els` · 떠오를 정권 `fadeP` · 떠오를 사건 `fadeE` · 옛 자리 없음 `all`)를 만들고, 적용은 `_gatherAnim` 하나(WAAPI — 줄 · 왼쪽 줄 이름은 `translate`, 네모 `<g data-row>` · 정권별 `<g data-p>`는 `transform`). 민족 칸 · 다른 테두리 · 민족 딱지는 옛 top · height로 되돌렸다가 제 전환(같은 길이 · 곡선)으로 흐름. 늦게 붙는 것(첫 그리기 · 다시 쓴 줄 이름 · 매번 다시 쓰는 네모)은 첫 이동의 `currentTime`만큼 앞당겨 붙여 한 시계(출발 전이면 같은 프레임에 함께 출발) — `_drawTrack` 끝의 한 줄 `_gatherDraw`. 끝나는 시각은 둘(떠오름 200 · 이동 360): 계승선 · 소속선 그림은 160 기다렸다 200, **끄는** 대범위의 테두리 · 왼쪽 칸은 옛 요소를 잔상으로 남겨 200 기다렸다 `--t-out`(160) — 모두 이동과 같은 순간에 끝남. 새 테두리의 이름표가 처음부터 물러나 있어야 하면 전환 없이(떠오르는 테두리 안에서 보였다 옅어지는 셋째 움직임이 없게). **붙잡기**: 다시 지을 때는 늘 트랙 위쪽(스크롤 0px). 그다음 `_gatherHold` — 본국 띠의 `▸` 단추를 눌렀거나 창이 열린 항목이 이 트랙의 구성 정권이 아니면 그 줄을 제자리에: 위쪽 줄이 빠져 그 줄이 옮겨지면 스크롤을 한 번에 옮기지 않고 그 줄 움직임의 진행값(`getComputedTiming().progress`)으로 조금씩 옮겨, 그 줄은 1px도 안 움직이고 나머지가 함께 미끄러짐(견본의 군웅 할거: 위쪽 줄 셋이 빠져 본국 줄이 255px 올라가야 하는 경우). 필터 칩 · 상세 스위치 · 우클릭 메뉴처럼 연표 밖에서 켜면 붙잡는 것이 없어 스크롤 0px. 창이 열린 항목이 구성 정권이면 함께 모이고, 보이던 줄이 가려지게 될 때만 `_revealAnchor`로 최소 거리. 동작 줄이기면 모여듦 없이 즉시(누른 본국 줄 · 닻은 그 자리 — 스크롤이 한 번에).
* 구현 메모(모여듦 검토 반영): **붙잡는 차례는 누른 본국 줄 → 창이 열린 항목**(이 트랙의 구성 정권이 아닐 때) — 창이 구성 정권 · 다른 트랙 · 같은 트랙의 다른 나라 어디에 열려 있어도, 안 보이는 곳에 열려 있어도 누른 본국 줄은 1px도 움직이지 않습니다(예전에는 누르기만 하면 붙잡았다고 치고 실제로는 닻을 따라가 본국 줄이 255px 미끄러졌음). 창이 열려 있으면 스크롤은 닻이 쓰므로 닻 자리의 대리 스프링에 본국 줄의 이동을 싣습니다(닻 줄의 자리는 그때그때 재어, 닻이 아래 트랙에 있어 높이 흐름을 따라 내려가도 맞음). `_gather`의 '붙잡음'은 실제로 붙잡았을 때만이고, **붙잡은 채 다 모였을 때 가려지는 것이 있으면**(`_pressScroll`) — 보이던 고른 줄이 옮겨져 여유 밖으로 나가면 그 줄을(`_revealTo`), 창이 없거나 안 보이던 때는 켠 테두리의 머리와 첫 줄이 화면에 걸리지 않으면 그만큼을(`_scopeMiss` — `_gatherReveal`과 한 판정) — 그 최소 거리를 **같은 곡선 · 같은 진행값에 더해** 데려오고 본국 줄은 그만큼만 옮겨집니다(⑧의 데려오기 예외: 화면 아래 가장자리 근처의 본국 띠에서 켜면 테두리가 보이도록 본국 줄이 조금 올라감). 둘 다 화면에 들어가지 않으면 본국 줄이 먼저(온전히 보이는 데까지만). 옮기는 줄이 없으면 같은 길이 · 곡선의 빈 움직임을 시계로. 동작 줄이기에서도 차례는 같음(`_pressStill` — 누르기 전 본국 줄의 자리로 한 번에). **도중에 다시 켜기**: 끄던 대범위의 잔상(`_ghost`에 그 uid)이 아직 옅어지는 중이면 그 밝기를 읽어 두었다가, 새 테두리 · 왼쪽 칸은 `is-born`(밝기 0부터) 대신 그 밝기에서 `--t-in`으로 이어 떠오릅니다 — 한 프레임에 꺼졌다 다시 떠오르는 번쩍임이 없음.

### 7-4. 뷰어 · 메이커
* 필터 시트 **대범위** 칩 줄(트랙별): 누르면 **시트를 먼저 접고**(`--t-out`) 모여들게 — 시트가 주연을 가리지 않게. 칩 위임은 맨 앞에서 `group === 'scopes'`를 갈라 `timeline.toggleScope`만(다시 거르지 않음). 가리지 않는 스위치: 대범위 상세의 `모아 보기` · 테두리 이름표 · 이어진 시대 구분 상세 · 우클릭 메뉴.
* 대범위 상세(갈래 표): 이름 · 성격 · 기간 · 구성 정권 · 스위치 · 문서. 정권 상세에 "대범위" 칩, 검색.
* 내용 메이커 탭 **대범위**(항목 탭 — 트랙 · 이름 · 기간이 있으므로 `CFG`/드로어/`HT.FORMS.scope` 그대로): 구성 정권 줄(자동 완성) · 시대 구분 · 색 · 처음부터 켬. 미리보기에 스위치, 미리보기에서 대범위를 누르면 그 탭으로. 검사에 "계승 줄이 끊기는 구성 정권" 알림.

## 8. 넓은 드로어 · 큰 입력 창 (건의 3)

1. **넓은 드로어**(0-1에서 먼저): 드로어 왼쪽 가장자리를 끌어 폭 조절(기억됨) + 머리의 `넓게/좁게`. 칸이 좁은 첫째 원인(폭 520px 상한)을 풉니다.
2. **큰 입력 창**(`js/fieldpop.js`, `HT.fieldPop` — 메이커와 뷰어 수정 폼 공용, 같은 화면 위에 떠 있는 창):
   * 여는 길: 긴 글 칸(textarea)의 **이름표 줄에 작은 `크게` 단추**(폼을 채운 뒤 후처리로 끼움 — `namu.attach`처럼 `dataset` 표시로 한 번만, 줄 안의 textarea는 그 줄에) + 단축키 `Alt+Enter`(초점 있는 textarea · 허용 목록의 글 input: 설명 · 메모 · 출처 · 서명자 글). 날짜 · id · 검색 · 표 칸은 대상이 아닙니다(표 칸은 Enter로 여는 드로어가 이미 큰 편집기). `Alt+Enter`가 표의 Enter(드로어 열기)와 위키 목록 이어쓰기에 먹히지 않게 두 곳에 `!e.altKey`. 글리프 ⤢는 쓰지 않습니다(뷰어에서 "전체 보기").
   * 창: 유리 패널, 제목 = 칸 이름 길, 큰 글 칸, 아래에 글자 수 · 닫기. 제목 줄을 끌어 옮기고(`setPointerCapture`) 모서리를 끌어 크기 조절(기억됨). **한 번에 하나** — 다른 칸에서 열면 같은 창이 그 칸으로. `Esc`는 이 창만 닫음. `<dialog>` 안의 칸이면 창을 **그 dialog 바로 아래 · form 밖**에 붙이고 모든 단추는 `type="button"`. 원래 칸이 한 줄 input이면 Enter = 닫기, 붙여넣은 줄바꿈은 빈칸으로, `maxlength`를 물려받음.
   * **비추기 규칙**: (1) 창에 초점이 있는 동안은 창이 주인 — 원래 칸 → 창 반영 없음 (2) 창 → 원래 칸: `value`를 쓰고 **그 칸에서** `input`(bubbles)을 쏘되 표시(`ev.htMirror`)를 달아 창 자신과 `wiki.js`의 `onInput`이 건너뜀, 닫을 때 `change` (3) 한글 조합 중(`isComposing`)과 값이 같을 때는 대입하지 않음 (4) 원래 칸 → 창은 사용자가 원래 칸에 직접 칠 때와 다시 묶을 때만.
   * **다시 묶기는 좁게**: `name`이 있는 폼 칸과 표 칸(`tr[data-id]` + `data-field`)만 다시 찾고, 줄 칸은 "줄 순번 + 그 줄의 이름 · 시작 값"이 열 때와 같을 때만. 아니면 곧장 "원래 칸이 닫혔습니다 — 글은 이미 저장돼 있습니다 · 복사 · 닫기". 새 작업본(`setDraft`)과 메이커 탭 전환에서는 강제로 뗌(엉뚱한 칸 · 다른 파일을 덮어쓰지 않게).
   * 문서 칸이면 창의 글 칸에 나무위키 편집기를 새로 붙이고 닫을 때 뗌. 이를 위해 `wiki.js`의 자동 완성 상자와 재는 거울 요소를 `ta.closest('dialog') || ta.ownerDocument.body`에 붙이도록 고침(지금의 수정 대화상자 문서 칸도 함께 고쳐짐). 이름 목록은 `attach`가 textarea에 남긴 옵션에서.
   * `index.html` · `dlc-maker.html`에 script 태그(core · wiki · platform 뒤), 부르는 쪽은 `if (HT.fieldPop)`, `sw.js` PRECACHE에 한 줄.
3. **새 브라우저 창으로 꺼내기**(맨 마지막 별도 커밋 — 문제가 있으면 이것만 뺄 수 있게): 창의 `↗ 새 창` — `HT.platform.name === 'web' && !HT.platform.mobile`일 때만. 글 칸 하나(위키 편집기 없음), 같은 비추기 규칙, 어느 쪽이 닫히든 정리.

## 8-2. 칸의 미정 (추가 건의 — 2026-09-18 밤 "도읍 등에 미정 추가")

지금 "미정"은 시대·사건·기관·문화·왕조의 시작·끝에만 적을 수 있고, **칸**(도읍 · 지도자 · 내각 · 연호, 그리고 새로 생기는 지위 변천 · 인물의 섬긴 기록 · 소속/얹힌 기간)의 시작은 날짜가 아니면 그 칸이 통째로 버려집니다. 칸에도 같은 말을 적을 수 있게 합니다. 구현은 종류·소속 관계 다음, 지위 앞(새 칸 목록들이 이 틀을 물려받게).

* **형식**: 칸의 `start` · `end`에 `"미정"`(`불명` · `모름` · `?` 도 — `HT.isUnknownText`). 짧은 꼴도: `["도시", "미정", 538]`. 저장되는 꼴은 시대와 같은 `startUnknown: true` / `endUnknown: true` + (있으면) 배치용 `start`/`end` 숫자. 배치용 연도를 따로 주려면 `startHint` · `endHint`.
* **자리 잡기**(모델, 짐작 값은 다른 이름에 — 0절 4): 시작이 미정이면 `startHint` → **앞 칸의 끝**(이어지는 종류: 지도자 · 내각 · 연호 · 지위 · 정도) → 정권의 시작. 끝이 미정이면 `endHint` → 다음 칸의 시작 → 정권의 끝. 지금 "끝을 비우면 다음 칸까지"와 자리는 같되, **비움 = 거기까지가 맞음 / 미정 = 모름**으로 뜻이 다릅니다. 시작·끝이 모두 미정이고 단서도 없으면 검사에서 경고하고 정권 전체 기간에 놓습니다.
* **연표**: 미정인 쪽은 띠의 미정 끝과 같은 말투 — 그쪽 끝이 **옅어지며 사라지고**(칸 안에서만, 이웃 칸을 덮지 않음) 구분선이 점선. 하나의 긴 둥근 칸은 끊지 않습니다. 날짜 칸의 도읍 · 연호 줄, 띠 안의 지도자 · 내각(· 지위) 칸, 도읍 노선도 카드(역 사이 선이 점선), `toSVG`.
* **글**: 칸의 기간 글(`cellRange`, 상세의 칸 목록, 칸 상세, 설명글, 검색 결과, 표)은 `미정 ~ 538년`처럼. 재위 조명은 자리 잡은 구간으로.
* **편집**: 줄 입력의 시작·끝 칸에 `미정`이라고 치면 됩니다(칸 설명글에 안내, 예시 값 placeholder 없음) — `HT.readCellRows` · `readPartOfRows` · 여러 줄 붙여넣기(`이름 미정~538 메모`) · `HT.cellsToText`. 파일 거름망: `readCells` · `HT.normalizeCapital` · `HT.readPartOf` · 패치 재정규화. 메이커 패치 탭 · 뷰어 내보내기 비교가 새 표시 칸을 같은 값으로 봅니다.
* 옛 파일은 그대로(칸에 미정이 없던 파일은 1px도 같음). 새 칸을 쓴 파일은 형식 버전 2.
* **통합 마무리(g1)에서 이은 것 — 지위 변천 · 섬긴 기록 · 활동 시기**: `HT.readRanks`가 칸 끝을 `HT.readCellEdge`로 읽어(시작이 미정인 칸은 첫 칸이 아니어도 남김 · 배치용 연도 없는 칸은 적은 차례에서 앞 칸 뒤에) 파일에 `startUnknown`(+ 숫자)으로 남기고, `HT.resolveRanks`가 미정이 있을 때만 `HT.placeCells`로 자리를 잡음(시작을 비운 첫 칸은 먼저 정권 시작에 두어 뒤 칸의 '앞 칸'이 되게 · 짐작은 `rankSpans` 사본에만) — 연표의 지위 칸은 `unkCell`, 그림 내보내기는 지도자 칸과 같은 옅어짐 · 점선 구분선, 지위 창 · 정권의 지위 목록에 `미정`과 '연표에는 … 무렵부터'. 인물은 `readService` · 인물의 활동 `start` · `end`가 같은 규칙(배치용 연도가 없으면 **비운 것과 같은 자리** — 섬긴 기록은 활동 시기, 활동 시기는 섬긴 기간 · 생몰), 모델의 섬긴 구간에 `fromUnknown` · `toUnknown`(기간을 비운 줄은 활동 시기의 미정을 물려받음), 활동 막대는 미정인 끝이 옅어지고 점선(올리거나 고르면 가림을 거둬 수명선이 보이게), 인물 창 · 막대 설명 · 섬긴 기록 줄에 `미정`. 폼: 지위 · 섬긴 기록 줄은 `미정` 글 + `data-start-hint`, 인물 폼의 활동 시작 · 끝은 `미정` 체크(숫자 칸 = 배치용 연도). 지위 변천 · 인물은 원래 형식 2라 `HT.usesCellUnknown`은 그대로. 함께 **인물 창의 '서명한 조약'**(모델 전용 `f.signedTreaties` — `linkTreatySigners`가 서명자 ↔ 인물을 이을 때 거꾸로도 · 관련 사건 목록에서는 뺌). 견본 `samples/sample-unknown-ranks-figures.json`, dev-smoke ㉑.

## 8-3. 추가 건의 3건 (2026-09-18 밤 — 다른 채팅은 움직임만 맡으므로 이쪽에서)

순서: **칸의 미정 → 칸 기간 조명 → 시기 구분**(지위 앞) · 플래그 탭은 지위와 같은 묶음에서.

### (가) 칸 기간 조명 — "연호 등을 누르면 시작점이 아니라 지도자처럼 기간을"
* 지금: 띠 안의 지도자 · 내각 칸만 누르면 그 기간이 조명되고(`setSpotlight` — 칸은 진하게, 띠 안 그 기간은 옅게 칠함) 칸 상세가 열립니다. 맨 위 날짜 칸의 **연호 · 도읍 칸**은 누른 자리의 해에 선만 서고 정권 상세가 열립니다.
* 바꿈: 칸 종류를 표 하나로 — `HT.CELL_KINDS`(core: 종류 id · 목록 열쇠 · 이름표 · 기간 낱말 · 문서 종류 · 제목 함수 — `HT.docKey`의 칸 종류 정규식 세 곳과 메이커 · 뷰어의 사본 여섯 곳이 이 목록에서 나옴) + 뷰어의 `parseCellRef` · `cellDetailHTML`이 그 표를 읽음(지금은 "지도자냐 아니냐" 두 갈래). 연호 · 도읍 칸을 누르면 `onSelect(uid, 해, { cell: 'era:i' | 'capital:i' })` → **그 정권 띠 안에 그 기간이 옅게 칠해지고, 누른 날짜 칸의 칸은 진하게**, 상세는 그 칸의 상세(이름 · 기간 · 정권 · 앞뒤 칸 · 문서). 왕조 칸을 누르면 왕조 상세와 함께 그 띠에서 다스린 기간 조명. 검색에서 칸을 고르면 정권 상세가 아니라 **칸 상세 + 조명**. 뒤에 생기는 지위 · 시기 · 인물도 이 표에 한 줄씩.
* 조명은 자리 잡은 구간으로(끝을 비운 칸은 다음 칸까지, 미정은 8-2의 자리). `setSpotlight`는 배열도 받습니다(5-3).

### (나) 시기 구분 — 후대 학계의 나라 안 시대 구분 (여러 체계가 함께)
```json
"periods": [ { "name": "…", "phases": [
  { "scheme": "구분 체계(출전 · 학설) 이름", "note": "", "spans": [ ["첫 시기", null, 654], ["둘째 시기", 654, 780, "메모"], { "name": "셋째 시기", "start": 780 } ] },
  { "scheme": "다른 체계", "spans": [ … ] } ] } ]
```
* `phases` = **체계 목록**, 체계마다 `spans`(칸 목록 — 연호와 같은 틀: 첫 칸의 시작을 비우면 정권 시작부터, 끝을 비우면 다음 칸까지, `미정` 가능). 체계마다 시기의 이름도 경계도 달라도 됩니다. 체계가 하나뿐이면 `scheme`을 비워도 되고, 납작한 꼴 `[{ name, start, end, scheme }]`도 읽어 체계별로 묶습니다. 한 체계 안에서 시기가 겹치면 검사 경고.
* 모델: `p.phaseSchemes`(끝을 채운 모델 전용), 원문 `p.phases`는 그대로. 칸 종류 표에 `phase`(문서 종류 `phases` — 시기마다 문서를 달 수 있음: `cell:<uid>:phases:<이름>@<시작 해>`), 검색의 칸 찾기.
* **연표 — 시기 단**: 띠 안 **왕조 칸 아래 · 지위/지도자 칸 위**. 체계마다 얇은 한 줄(`G.phase = 13`, 줄 사이 2), 파일에 적은 순서로 위에서 아래. 하나의 긴 둥근 칸 + 가는 구분선, 글은 이름 → 첫 글자 → 없음. 모양은 **학술 주석처럼 조용하게**(나라 색이 아니라 종이빛 중립 + 옅은 테두리) — 왕조 칸(왕조 색) · 지위 칸(나라 색 짙기)과 헷갈리지 않게. 체계가 둘 이상이면 각 줄의 보이는 왼쪽 끝에 작은 체계 이름표(그 칸의 글과 함께 들어갈 때만, 아니면 설명글에만). `data-cell="phase:<체계 순번>:<시기 순번>"` — 누르면 그 기간 조명 + 시기 상세.
* **높이는 줄 단위로**: 시기 단과 지위 단은 글줄 **위**에 놓이지만 트랙 공통으로 두면 한 나라 때문에 그 트랙의 모든 띠가 높아집니다. 그래서 `geoFor`가 줄마다 "위쪽 덧단"(그 줄의 정권들이 가진 체계 수 × 13 + 지위 단)을 받아 `leaderTop` · `cabinetTop` · `textTop` 아래를 그만큼 내립니다(지금 있는 왕조 · 지도자 · 내각 단은 트랙 공통 그대로 — 옛 화면은 1px도 같음). `g.textTop`을 트랙 공통으로 읽던 곳(사건 글줄 · 건국 네모 · `_laneKey` · `_ghost` …)은 모두 `geoOf(row)`로. 한 줄에 그리는 체계는 최대 3(넘으면 상세에서만). **3-3의 지위 단도 이 덧단에 실려 줄 단위**가 됩니다(조건: 그 줄에 지위가 둘 이상인 정권이 있을 때).
* 상세: 시기 상세 = 체계 · 이름 · 기간 · 앞뒤 시기 · 문서 + **체계 견주기**(그 정권의 모든 체계를 같은 시간 축에 나란히 놓은 작은 막대 그림 — 경계가 어떻게 다른지 한눈에, 막대를 누르면 그 시기로). 정권 상세에 "시기 구분" 목록(체계별). 같은 해 보기에 그 해의 시기.
* 표시 체크 `시기`(띠 안 묶음, 기본 켬) — 날짜 칸의 `시대 구분`(epochs)과 말이 비슷하므로 UI에서는 늘 "시기"/"시기 구분(학계)"로 적습니다. `빽빽하게`에서는 그리지 않음. `toSVG`.
* 편집: 시대 폼에 "시기 구분" 구역 — 체계 묶음(체계 이름 · 메모 + 시기 줄: 이름 · 시작 · 끝 · 메모 + 여러 줄 붙여넣기)을 더하고 뺌. `PATCHABLE` · 패치 재정규화 · `describePeriods` · `FIELD_LABELS` · `FIELD_NAMES` · `fmtVal` · 형식 버전 2.

### (다) 플래그 탭 — "띠 위에 얹힌 이름표가 아니라 띠 밑에 깔린 포스트잇 플래그처럼"
* 지금: 책갈피 탭이 띠 **위에**(z 3) 얹혀 윗변을 3px 덮고, 테두리 · 그림자가 사방에 있어 "붙여 놓은 딱지"로 보입니다.
* 바꿈: 탭은 띠 **뒤에서 위로 빠져나온** 필름 플래그 — ① 띠보다 아래 층(띠의 윗변 테두리가 탭을 덮음) ② 아래쪽은 띠 윗변에서 **곧게 잘림**(아래 모서리 둥글림 · 아래 테두리 없음), 위쪽 모서리만 둥글게 ③ 띠 윗변 바로 위에 띠가 드리운 옅은 그늘(안쪽 아래 그림자)로 "밑에 끼워져 있음"을 말함 ④ 바탕은 나라 색의 반투명 필름(종이가 살짝 비침), 바깥 그림자는 없앰 ⑤ 속이 빈 띠(연맹 · 점선 띠)에서도 비쳐 보이지 않게 탭은 띠 안으로 들어가지 않음. 화면 왼쪽에 붙어 따라오는 동작 · 종류 딱지 · 첫 글자 줄임 · 고름/올림 상태 · 접힌 줄에는 없음은 그대로. 탭 높이 · 줄 간격(`G.tab`)은 그대로라 배치는 1px도 안 바뀝니다. `toSVG`도 같은 모양.
* 구현 메모: 모양은 `css/common.css` 끝의 '플래그 탭' 블록(바탕 짙기는 `--film` 하나 — 기본 35% · 올림 46% · 고름 64%, 필름 불투명도 86%), 탭 높이는 `_drawTrack`에서 `G.tab + G.bw` — 띠 윗 테두리 두께(1px)만큼만 띠 밑으로 들어가 ①처럼 띠의 테두리 · 바탕이 그 1px를 덮습니다(띠 안쪽으로는 들어가지 않아 ⑤도 그대로 · 아랫변이 띠 윗변에 딱 맞으면 띠의 둥근 모서리와 탭 아랫변 사이에 높이 1px 미만의 틈이 생겼음). 글자는 보이는 10px 칸 안에: 10px 글자 · 아래 여백 3px(띠 밑 1px + 2px)로 기준선이 띠 윗변 2px 위 — 한글 아래 끝이 띠에서 1px 떨어지고 괄호도 가려지지 않음(10.5px 글자는 줄 상자가 칸보다 커서 글자 아래가 띠에 붙거나 가려졌음 · 폭 계산은 10.5px 그대로). 그늘은 1px 올려(`inset 0 -4px 3px -2px`) 보이는 모양이 그대로. `toSVG`는 탭 모양을 띠보다 먼저(밑에) 그리고 아랫변을 `y + G.bw`로. 탭 안의 작은 딱지(`small`)는 낮아진 탭에 닿지 않게 테두리 없는 옅은 칩(글자를 올린 만큼 1px 도로 내려 보이는 칸 가운데). **예외 하나**: 띠 윗변에 걸친 '다른 견해' 고리(`.tl-palt` — 띠 안의 것이라 탭보다 위 층)가 탭 자리에 걸릴 때만 탭이 고리의 윗반을 가립니다(`has-pin` → z 3 · 이때는 띠보다 위이므로 아래 1px를 `clip-path`로 잘라 띠의 윗 테두리를 덮지 않음). 고리가 이름 글자를 덮는 것을 막습니다(예전에는 탭이 고리를 거의 다 가렸음).
* **감독 확인 뒤 다듬음(2026-09-19 — 세 안 가운데 '안 2 · 필름 + 모서리 밑')**: 층만 띠 밑으로 내린 것으로는 탭이 여전히 "띠 위에 얹힌 이름표"로 보였습니다(탭이 띠와 같은 옅은 칠 · 같은 테두리라 띠의 일부인 폴더 탭처럼 읽힘 · 띠가 탭을 가리는 곳이 눈에 띄지 않음). 그래서 ① 재질: 테두리 없는 반투명 색 필름(`--film` 기본 72% · 올림 84% · 고름 96%, 불투명도 88% · 어두운 화면은 42 · 54 · 66%로 덜 섞음), 글자는 먹빛 쪽, 위 모서리 2px, 탭 안 딱지는 종이빛 칩 ② 가림: 띠의 왼쪽 위 둥근 모서리가 화면 안에 있으면(시작이 미정이 아니고 띠가 왼쪽 밖으로 나가지 않았을 때) 탭을 그 모서리에 맞춰 끼우고(`at-corner` — 6px 안쪽이 아니라 띠의 바깥 왼쪽 끝), 모서리의 둥근 틈(띠 바깥 · 원 밖)에만 탭의 아랫부분이 비치게 함(`::after` + 원 밖만 남기는 가림막 — 속이 빈 띠 안으로는 비치지 않음). 띠의 테두리 곡선이 탭 위를 지나가 "띠가 덮고 있음"이 보입니다. 그림 내보내기도 같은 모양(모서리 조각을 띠보다 먼저). 탭 폭이 6px 늘어난 만큼 좁은 띠에서 글이 조금 더 들어갈 수 있음(배치 규칙은 그대로). 검사: dev-smoke '플래그 탭' 블록.

## 8-4. 추가 건의 3건 (2026-09-18 밤, 둘째 묶음)

### (라) 조명 메아리 — "지도자를 고르면, 설정으로, 그 시기를 다른 나라에도"
* 칸 기간 조명(8-3 가)에 설정 하나: **`같은 시기를 다른 나라에도`**(필터 시트의 선·견해 묶음 체크 + 칸 상세 안의 같은 스위치, `ui.show.spotEcho`, 기본 끔). 켜면 조명된 기간이 **그 기간에 걸친 다른 모든 띠 안에도** 옅게 칠해집니다(주인 띠보다 한 단계 옅은 `.tl-spot.is-echo` — 띠 안쪽으로 잘림, 띠가 그 기간의 일부만 겹치면 겹친 만큼만). 맨 위 연도 줄에는 그 기간의 가는 괄호. 지도자 · 내각 · 연호 · 도읍 · 왕조 · 지위 · 시기 · 인물 조명 모두에 같이 듭니다.
* 메아리는 그리기일 뿐 선택이 아닙니다(다른 띠가 "고른 것"처럼 진해지지 않음 — `is-picked`의 흐림은 그대로 두되 메아리 칠은 흐려지지 않게). 접힌 트랙 · 접힌 민족 줄의 가는 막대에는 그리지 않습니다. `toSVG`에는 넣지 않습니다(화면 상태).

### (마) 실재성 — 전설로만 전하는 나라 · 한때 인정되었으나 부정된 나라
지금의 `certainty`(확실 · 통설 · 추정 · 전승)는 **연대**가 얼마나 확실한가입니다. 나라가 **있었는가**는 다른 축이므로 칸을 따로 둡니다.

| `historicity` | 이름 | 딱지 | 뜻 |
| --- | --- | --- | --- |
| (비움) `attested` | 실재 | — | 기본값 |
| `semi` | 반전설 | 반전설 | 실재는 인정되나 기록이 전설에 기대는 나라 |
| `legendary` | 전설 | 전설 | 전승 · 신화에만 전하는 나라 |
| `disputed` | 실재 논쟁 | 논쟁 | 있었는지를 두고 학계가 갈리는 나라 |
| `refuted` | 부정됨 | 부정 | 한때 인정되었으나 고고학 · 사료 비판으로 부정된 나라 |

* 형식: `periods[].historicity` + `historicityNote`(근거 · 출전 · 누가 언제 부정했는가 — 자유 글). 한국어도 읽음. 옛 칸 `legendary: true`/`certainty: "legend"`는 지금 그대로 **연대의 전승**으로 남습니다(뜻을 바꾸지 않음).
* 연표 — 선 모양 · 빗금은 이미 연대 불확실에 쓰이므로 **바탕의 질감과 이름 글꼴**로 말합니다:
  * `legendary`: 띠가 **안개처럼** — 위에서 아래로 옅어지며 사라지는 바탕(아래 테두리 없음 · 옆 테두리는 아래로 갈수록 투명), 이름은 기울임. 
  * `semi`: 보통 띠 + 아래쪽 1/3만 같은 안개.
  * `refuted`: **지운 자국처럼** — 색을 뺀 회색빛 옅은 바탕 + 가는 회색 테두리, 책갈피 탭의 이름에 취소선. 계승선 · 소속선은 그대로 그리되 옅게.
  * `disputed`: 보통 띠 + 탭 딱지 `논쟁`만.
  * 모두 책갈피 탭에 딱지(종류 딱지와 같은 꼴, 둘 다 있으면 나란히 — 탭 폭 계산에 포함). 띠 안의 칸 · 사건은 그대로 그립니다.
* 필터: 자료에 실재성이 쓰였을 때만 칩 줄 **실재성**(실재 · 반전설 · 전설 · 논쟁 · 부정됨 — 끄면 그 나라와 딸린 사건을 숨김, 종류 칩과 같은 방식). 범례 한 줄씩. 상세에 배지 + "실재성" 상자(근거 글). 검색 글 · 표 보기 · 같은 해 보기(전설 · 부정된 나라는 옅은 글씨) · `toSVG`.
* 편집: 시대 폼의 불확실성 구역에 `실재성` 고르기 + 근거 글. `PATCHABLE` · `FIELD_LABELS` · `FIELD_NAMES` · 메이커 표 붙여넣기 별칭 · 형식 버전 2.

### (바) 할거와 부흥 — 상징적 본국 아래의 군벌 · 멸망한 나라를 되살리려는 세력
구성 요소 넷으로 풉니다(앞의 종류 · 소속 관계 · 대범위에 얹음).

1. **종류 `warlord`**(군벌·할거 세력, 딱지 `군벌`, 종속 갈래 · 자율성 3) — 2절 표에 추가. 부흥 세력은 이미 있는 `movement`.
2. **소속 관계 `nominal`**(명목상 — 상징적 본국을 받들되 실제로는 따로 다스림, 자율성 3): 예속 띠는 **속 빈 테두리 + 점선**(가장 옅은 종속). `partOf: [{ "polity": "본국", "relation": "nominal", "start": …, "end": … }]`.
3. **계승 종류 `revival`**(부흥 — 멸망한 나라를 되살리려 함): `succeeds: [{ "from": "…", "type": "revival" }]`. 계승선은 간접 계승과 같은 점선에 **끝에 작은 고리**(되돌아옴). 줄 잇기 규칙은 다른 계승과 같음(같은 줄을 쓸 수 있음).
4. **대범위에 `host`(상징적 본국)**: `scopes[].host`를 적으면
   * 켰을 때 집합이 뿌리 아래가 아니라 **본국 줄 바로 아래**에 생깁니다(본국 줄은 1px도 안 움직임 — 본국 자신은 구성 정권이 아님). 테두리는 본국 띠 아랫변에 **매달린 모양**(테두리 위쪽이 본국 띠 아래에 붙고, 이름표는 테두리 안 왼쪽 위).
   * 본국 띠의 그 기간에는 **할거기 칠** — 띠 바탕이 그 구간만 속이 비어 가는 모양(가운데가 옅고 테두리 쪽만 남는 세로 구간, `.tl-zone` 자리에 `z-hollow`) — "이름은 남았으나 실제 다스림은 흩어짐". 대범위를 꺼 두어도 이 칠은 보이고, 그 구간 왼쪽 위에 작은 단추 **`▸ 〈성격〉 n`**(소속 정권 단추 `.tl-mem`과 같은 꼴)이 있어 **띠에서 바로** 모아 보기를 켜고 끕니다.
   * 부흥 운동처럼 본국이 **이미 끝난 뒤**의 대범위면(기간이 본국의 끝 뒤) 할거기 칠은 없고, 집합은 본국 줄 아래 · 본국이 끝난 자리의 오른쪽에 생깁니다. 본국의 멸망 네모에서 테두리로 가는 부흥 계승선은 구성 정권마다가 아니라 **테두리로 한 줄**(구성 정권들이 `revival`로 본국을 가리킬 때 묶어 그림).
   * `host`가 있는 대범위의 구성 정권은 `partOf`를 따로 적지 않아도 상세에 "〈본국〉 아래 할거/부흥"으로 나옵니다(자료에 `partOf`가 있으면 그것이 우선).
* 편집: 대범위 폼에 `상징적 본국`(자동 완성) · 시대 폼의 계승 줄 종류에 `부흥` · 소속 관계에 `명목상`. 검사: `host`가 구성 정권에 들어 있으면 경고.

### (사) 남의 민족 아래 놓인 나라의 민족 표기
상위 띠 아래에 접혀 들어간 소속 정권(그리고 대범위로 모인 정권)은 **자리는 정치(소속)가 정하므로** 왼쪽 민족 칸이 상위의 민족(또는 대범위)으로 덮여, 제 민족이 보이지 않습니다.

* 원칙: **자리는 소속이, 표기는 제 민족이.** 그 줄의 정권 민족이 그 자리를 덮은 민족 칸과 다르면, 그 줄 높이만큼의 **민족 딱지**를 민족 칸 자리의 오른쪽 끝 단에 **끼워 넣습니다**(제 민족 색 · 세로 글 · 종이빛 1px 테로 상위 칸과 구분 — 의도된 끼움이라 겹쳐 보이지 않게, 폭은 단 폭 − 8). 설명글 "〈민족〉 — 〈상위〉 아래에 놓인 다른 민족". 누르면 그 민족의 문서/정보(접기 단추가 아님).
* 같은 민족이면 아무것도 그리지 않습니다. 민족이 없는 정권도 없음. 접힌 줄에는 없음. 줄이 접혀 높이가 0이면 함께 사라짐(`_collapseRows`의 민족 칸 갱신 옆에서).
* 대범위 가지에서도 같은 딱지(여러 민족의 나라가 한 집합에 모였을 때 누가 어느 민족인지).
* 상세: 민족 줄에 "(상위 〈나라〉는 〈민족〉)" 한마디. 제 줄에 선 소속(예속 띠)은 제 민족 묶음 안에 그대로 있으므로 해당 없음 — 즉 `nest`(상위 띠 아래에 접기)를 고르는 것이 곧 "소속 자리에 놓고 민족은 딱지로"를 고르는 것입니다.

* **DLC 메이커**(`dlc-maker.html`) — **지금의 수정 모드 화면 그대로**(연표 · 상세 · 문서 · 검색이 같고, 늘 수정 모드) + 메이커 줄. 옛 메이커(`js/maker.js` · `css/maker.css` · 옛 `dlc-maker.html`)는 지웁니다(git 기록에 남음). 두 화면은 **같은 코드**(`js/viewer.js`)를 쓰고 `<body data-app="view|make">`로 갈립니다 — 보기 전용에서는 편집 길이 아예 닫힙니다(단추만 숨기는 것이 아니라 함수가 거절). 메이커 전용 코드는 새 `js/maker.js`(부품 — `HT.makerPlugin`, 지도 부품과 같은 방식) · 새 `css/maker.css`.

### 고치는 DLC (작업본)
* 메이커는 늘 **DLC 하나**를 고칩니다: 들어올 때 `어느 DLC를 고칠까요` — 설치된 DLC 목록 · `새 DLC` · `파일 열기`(마지막에 고치던 것을 기억). 다른 DLC와 기본팩은 **배경**으로 함께 보입니다.
* 지금의 "내 수정"(덧씌움: 추가 · 고침 · 숨김 · 문서를 따로 들고 있다가 나중에 DLC로 묶음)을 없애고, **작업본(draft = DLC JSON)을 바로 고칩니다**:
  * 새 항목 → 작업본의 목록에 바로(uid는 처음부터 `<DLC id>/<항목 id>`).
  * 작업본의 항목을 고침/지움 → 그 항목을 바로 고침/지움.
  * **다른 DLC · 기본팩의 항목을 고침 → 작업본의 `patches`에 바뀐 칸만**(원본과 견줘 다시 계산해 그 대상의 패치를 통째로 갈아 씀 — 원래 값으로 되돌리면 패치가 사라짐), 숨김 → `hide` 패치.
  * 문서 → 작업본의 `documents`(제 항목은 상대 키).
  * 쓰인 트랙 · 분류 · 민족은 작업본의 목록에 저절로 실림.
* 작업본은 글자를 칠 때마다 브라우저에 임시 저장(`HT.KEYS.draft`)되고 연표에 바로 반영됩니다(모델 = 다른 팩들 + 작업본). **연표(보기 전용)는 반영 전까지 옛 판을 봅니다.**
* **반영** — 단추 하나, 묻지 않음: ① 검사(`normalizePack`) — 오류로 DLC를 만들 수 없으면 멈추고 알림(작업본은 그대로) ② **판 올림**(`x.y.z` → `z + 1`, 그 꼴이 아니면 뒤에 `.1`) ③ 설치된 같은 id의 DLC를 **덮어씀**(없으면 설치) · 켬 ④ 알림 "v1.0.4로 반영". `파일로`는 따로(같은 판 번호의 JSON 내려받기). 반영하지 않은 고침이 있으면 메이커 줄에 `고친 것 n`.
* id를 바꾸는 것은 `DLC 정보`에서만(바꾸면 새 DLC로 설치되고 옛 것은 그대로 — 경고).

### 옛 "내 수정"의 이사
연표 · 메이커 어느 쪽이든 새 판이 처음 뜰 때 `ht.user`(내가 추가 · 고침 · 숨김 · 문서)에 내용이 있으면: 지금의 `editsAsPack`으로 DLC **`내 수정`**(id `my-edits`, 이미 있으면 거기에 합침)을 만들어 설치하고, 원본은 `ht.user.backup`에 남긴 뒤 비웁니다. 만들기에 실패하면 아무것도 지우지 않습니다. 한 번만 돌고 알림을 띄웁니다. `buildModel(packs, user)`의 둘째 인자는 이사 · 검사용으로만 남깁니다.

### 메이커 줄과 창들
`[고치는 DLC ▾ 이름 v판]` · `DLC 정보` · `바탕 자료` · `붙여넣기` · `검사 n` · **`반영`** · `파일로` · `연표로`.
* **DLC 정보**: id · 이름 · 판 · 만든 사람 · 설명 · 함께 쓰면 좋은 DLC.
* **바탕 자료**(떠 있는 창 — 옆에 연표가 보임): 트랙 · 분류 · 민족 · 시대 구분(뒤에 지위 · 가문이 여기에 한 칸씩) — 목록 + 같은 폼 틀(`HT.FORMS.track|category|people|epoch`), 쓰는 곳 역참조, id를 바꾸면 참조도 함께.
* **붙여넣기**: 옛 메이커의 표 붙여넣기(사건 · 시대 — 표 계산 프로그램에서 복사 → 미리보기 → 넣기)를 옮겨 옴.
* **검사**: `normalizePack(작업본)`의 오류 · 경고 목록, 누르면 그 항목으로.
* 항목 추가는 연표에서(우클릭 · 독의 ＋ · 단축키 — 시대 · 사건 · 기관 · 문화 · 왕조, 뒤에 인물 · 조약 · 대범위), 목록으로 훑어 고치려면 표 보기에서 줄을 눌러 편집.
* 옛 메이커에서 **없어지는 것**: 종류별 표 · 드로어 · 빠른 추가 글 · 패치 탭(저절로 만들어짐) · 문서 탭(문서 창에서) · 미리보기 탭(화면이 곧 미리보기) · 연표 → 메이커 넘겨주기.

### 진행 — m1(뼈대)까지 된 것과 m2가 알아 둘 것
* **m1 완료**: 화면 갈림(`<body data-app>` — 보기 전용에서는 `openEditor` · `deleteItem` · `revertItem` · `saveDoc`이 `false`를 돌려주며 거절) · 메이커 줄(고치는 DLC 고르기 / 새 DLC / 파일 열기 · `고친 것 n` 창 · 반영 · 파일로 · 연표로) · 작업본을 바로 고치는 저장 길 · 옛 "내 수정"의 이사. `DLC 정보` · `바탕 자료` · `붙여넣기` · `검사` 단추는 `dlc-maker.html`에 `hidden`으로 자리만 잡혀 있습니다(`#mkInfoBtn` · `#mkBaseBtn` · `#mkPasteBtn` · `#mkCheckBtn`).
* **나눔**: 순수 계산은 `js/core.js`의 `HT.draft.*`(노드에서 `scripts/dev-smoke.mjs`가 검사) · 메이커 줄과 작업본의 보관은 `js/maker.js`의 `HT.makerPlugin(ctx)` · 편집기와 문서 창은 `js/viewer.js`(부품이 있을 때만 열림). m2의 창들은 `maker.js`에 더하고, 작업본을 고친 뒤에는 `commit()` → `ctx.refresh()`.
* **설계에서 더 정한 것**:
  * 편집기는 **제 항목은 파일 그대로의 값**(정규화한 작업본의 항목 + 지금의 문서 본문)으로, **남의 항목은 지금 보이는 모습**(모델의 항목)으로 채웁니다 — 모델의 화면용 값(짐작으로 배정된 색 `colorAuto` · 파스텔로 맞춘 색 · 계승선으로 바뀐 `successors`)이 저장할 때 자료로 굳지 않게. 패치 비교(`patchSet`)도 같은 값들을 "고치지 않은 것"으로 봅니다. 기준: **아무 항목이나 열어서 그대로 저장해도 제 DLC는 1바이트도 달라지지 않고, 남의 항목에는 패치가 생기지 않는다**(기본팩 289개 · 견본 37개로 확인).
  * 폼에 칸이 없는 값은 지우지 않습니다: 제 항목의 폼 밖 열쇠(사건의 `polity` 같은) · 손으로 적은 패치의 폼 밖 열쇠와 메모 · 다른 견해의 출처처럼 폼이 모르는 안쪽 값(`FORM_ROW_KEYS`). 새 기능이 폼에 없는 칸을 더하면 이 규칙이 지켜 줍니다.
  * **반영은 고친 것이 없으면 판을 올리지 않습니다**(설치된 같은 id가 있을 때). 판은 작업본과 설치본 가운데 높은 쪽에서 하나 올립니다(파일로 연 낮은 판이 설치된 높은 판을 뒤로 돌리지 않게).
  * 숨긴 항목은 연표에 보이지 않으므로 **`고친 것` 창**에서 되돌립니다(남의 항목에 건 패치 목록 — `보기` · `↩ 되돌리기`).
  * 기본 내장 팩은 메이커에서 직접 고르지 못합니다(고치는 DLC의 패치로 고칩니다). 옛 메이커의 "내장 팩을 통째로 열기"는 없어졌습니다.
  * 내 데이터 절은 없앴지만 **백업 파일 저장**(설치한 DLC 모두 + 켜고 끔)은 `DLC 관리`에 남겼습니다(앱 사이 옮기기에 쓰임). 백업에 든 옛 `user`는 복원할 때 이사를 거칩니다.
  * **검토 반영(m1)** — ① **바탕 판**: 작업본을 가져오거나(설치본 고르기 · 파일 열기 · 새 DLC · 설치된 판으로 되돌리기) 반영할 때 그때의 설치본 지문을 `ht.maker.origin`(`{ id, sig, version }` — `HT.makerKit.packSig`)에 적고, 모델을 지을 때마다 설치본과 견줍니다(`HT.makerKit.followOrigin`). 설치본이 따로 바뀌었으면(DLC 관리의 설치 · 백업 복원 · 다른 탭의 반영) 작업본에 제 고침이 없으면 그 자리에서 새 판으로 다시 가져오고(편집 창에 저장하지 않은 고침이 있으면 가져오지 않음), 고침이 있으면 메이커 줄에 `⚠ 설치된 판이 바뀌었습니다`(누르면 `고침을 버리고 설치된 판 불러오기`) — 그때만 **반영이 "덮어쓸까요"를 묻습니다**(묻지 않는 반영의 유일한 예외: 모르고 새 판을 지우지 않게). 기록이 없는 옛 작업본은 설치본과 같으면 조용히 바탕으로 삼고, 다르면 같은 알림. ② **파일 열기**: 같은 id의 설치본(기본 내장 포함)이 있으면 `새 id로 열기 / 그대로 열기 / 취소`, 쓸 수 있는 id가 없는 파일은 겹치지 않는 새 id로(기본 `my-dlc`가 남의 DLC를 덮어쓰지 않게). ③ **패치로 단 문서**(`set.wiki`)는 열어서 그대로 저장해도 패치에 남고, 문서를 고치거나 지우면(`HT.draft.setDoc`) 그 항목의 패치 본문을 걷어 `documents` 하나로. ④ **패치의 색**: 편집 창은 보이는 색을 한 번 더 파스텔로 맞춰 담으므로, 패치에 적힌 색이나 그것이 파스텔을 거친 값이면 고치지 않은 것 — 견본 밖의 색이 열 때마다 바래지 않음. 패치의 칸 차례도 옛 패치를 따라, 손으로 적은 패치를 열어 그대로 저장하면 글자 하나 다르지 않음(dev-smoke ⑬).

### 진행 — m2(편집 창 · 메이커의 창들)까지 된 것과 통합 때 끼울 자리
* **m2 완료**: 편집기는 `<dialog>`가 아니라 오른쪽에 붙은 **편집 창**(`#editPane` — 틀 · 폭 · 떼어 내기 · 기억은 `js/maker.js`, 폼 채우기 · 저장 · 물음은 `js/viewer.js`의 `openEditor` · `fillEditor` · `saveEditor` · `leaveEditor` · `closeEditor`) · `DLC 정보`(대화상자) · `바탕 자료`와 `검사`(떠 있는 창) · `붙여넣기`(대화상자) · 표 보기의 줄 → 편집 창 · 넘겨받기 → 편집 창. 상세와 편집 창은 같은 자리라, 편집 창이 붙어 있는 동안 `openDetail`은 편집 창을 그 항목으로 바꿉니다(고칠 수 없는 것이면 편집 창을 닫고 상세).
* **통합 때 끼울 자리** (모두 설정만 더함 — 메이커 코드는 고치지 않아도 됨):
  * 바탕 자료의 칸(지위 사전 · 가문): `Object.assign(HT.makerKit.BASE_TABLES, { rankDefs: {…}, houses: {…} })` — 열쇠 = 작업본의 목록 이름(그 목록은 `HT.draft.LISTS`에도 있어야 작업본에 실림). 설정은 `word · lead · idBase · docPrefix · cols · refs · autoColor · fresh · foot`(설명은 `js/maker.js`의 `BASE_TABLES` 위 주석). 중첩 참조는 길 글로: `refs: { id: [{ list: 'periods', path: 'leaders[].house' }, { list: 'figures', path: 'house' }] }` — 쓰는 곳 세기와 id 바꿈 때 따라 고치기가 모두 이 길을 봅니다(`scripts/dev-smoke.mjs` ⑫에 가문 모양의 검사가 있음). 표 대신 편집 창의 폼으로 고칠 칸이면 `form: 'HT.FORMS의 종류'`(시대 구분이 그 예).
  * 연표의 추가 길(우클릭 두 분기 · 독의 `＋ 추가` · 단축키)은 `HT.FORMS`를 돕니다. 폼 항목의 선택 속성: `add: false`(추가 길에 두지 않음 — 시대 구분) · `addLabel`(메뉴 글) · `key`(단축키 — `'Shift+F'` 꼴, 없으면 뷰어의 `KEYS[종류]`). 인물 · 대범위 폼은 `HT.FORMS`와 `HT.USER_LISTS`에 더하면(작업본에 넣으려면 `js/core.js`의 `DRAFT_ITEMS`에도 한 줄) 저절로 추가 길 · 편집 창 · 검사 창의 "그 항목으로" · 바탕 자료의 트랙 참조(`itemLists`)에 들어옵니다.
  * 시대 구분 폼(`HT.FORMS.epoch`)은 `js/maker.js`가 메이커에서만 등록합니다(연표는 보기 전용이라 필요 없음).
  * 지도자 줄에 칸을 더하면: 편집 창 안의 줄 입력은 제 규칙이 없는 칸도 기준 폭(72px)을 받아(`css/maker.css`의 `:where(.ep-body .cell-row) > input`), 창이 넓으면 한 줄, 좁으면 저절로 접힙니다. 칸마다 폭을 정하려면 그 칸의 클래스로 규칙을 더하세요.
* **검토 반영(m2)** — ① **편집 창 맞추기**(`js/viewer.js`의 `syncEditor`, 부품에는 `ctx.syncEditor`): 작업본이 편집 창 밖에서 바뀌면(바탕 자료의 id · 이름 바꿈 · 상세와 `고친 것`의 되돌리기 · 문서 창의 저장 · 다른 메이커 탭) 열린 편집 창을 다시 채웁니다 — 고침이 없으면 저장된 값으로, 고침이 있으면 손댄 칸은 그대로(참조는 같은 `renameRefs`로 따라 고침) 손대지 않은 칸만 새 값으로. 폼이 옛 트랙 id · 옛 민족 이름 · 걷어 낸 패치 값 · 옛 문서를 들고 있다가 다음 저장 때 되살리던 것을 막음. 이 합치기는 **폼의 `read`로 읽은 값을 `fill`에 다시 넣으면 같은 값이 읽힌다**는 것에 기대므로, 새 폼(인물 · 대범위 · 조약 …)도 그렇게 짜 주세요(기본팩과 견본 셋의 항목 모두 그러함을 확인 — 예외는 견본 색 칸의 파스텔 맞춤뿐이라 syncEditor가 따로 돌려놓음). 바탕 자료의 가져오기 · 삭제 · 붙여넣기는 폼이 든 값을 바꾸지 않아 부르지 않습니다. ② 저장(Ctrl+S · 저장 단추) 뒤 다시 채울 때 **치던 칸 · 커서 자리로 초점을 돌려줌**, 초점이 편집 창 · 바탕 자료 · 검사 · 큰 입력 창 안에 있으면 연표의 한 글자 단축키(n · t · a · / …)가 새지 않음. ③ 떠 있는 편집 창을 **다시 붙이거나 화면이 좁아지면** 따로 열어 둔 상세를 닫음(편집 창 밑에 깔린 상세 때문에 편집 창이 멋대로 그 항목으로 바뀌지 않게). ④ 검색 칸의 Esc가 편집 창을 닫지 않음(메이커의 Esc는 키를 처음 받은 곳으로 판단). ⑤ 늦게 오는 물음 창 닫힘 알림은 m1 검토 반영에서 이미 막혀 있었음.
* **하지 않은 것**: 옛 메이커의 시대 구분 "흔한 구분 한 번에 넣기"(자료는 감독 몫) · 붙여넣기의 "예시 채우기"(실제 이름이 든 예시였음 — 대신 `머리글 줄 넣기`).

### 편집 창 — 건의 3(입력 칸 확대 · 창으로 꺼내기)은 여기서
* 메이커의 편집기는 가운데를 막는 대화상자가 아니라 **오른쪽에 붙은 편집 창**(막지 않음 — 연표를 보며 고침): 왼쪽 가장자리를 끌어 **폭 조절**(기억됨) · `넓게/좁게` · 제목 줄을 끌어 **떼어 내 떠 있는 창**으로(다시 붙이기). 다른 항목을 누르면 그 항목으로 바뀌되, 저장하지 않은 고침이 있으면 먼저 묻습니다.
* **큰 입력 창**(8절 2번)은 그대로 — 긴 글 칸의 `크게` + `Alt+Enter`. 편집 창이 대화상자가 아니므로 top layer 문제는 없어지고, 옛 표 · 드로어의 "다시 묶기"도 편집 창의 이름 있는 칸만 남습니다. 8절 1번(넓은 드로어)은 이 편집 창의 폭 조절로 대신합니다.

### 진행 — f3(큰 입력 창)까지 된 것과 통합 때 끼울 자리
* **f3 완료**: `js/fieldpop.js`의 `HT.fieldPop`(`attach` · `open` · `close` · `detach` · `check`). 두 화면이 core · wiki · platform 뒤에 읽고(`sw.js` PRECACHE에도), 연표에는 고칠 칸이 없어 나타나지 않습니다. 모양 규칙은 `css/maker.css` 끝의 "큰 입력 창" 블록.
* **여는 길**: 편집 창을 채운 뒤(`viewer.js`의 `fillEditor`)와 처음 뜰 때(페이지의 정적 칸 — DLC 정보의 설명) `HT.fieldPop.attach(폼)`이 **`label.field > span` 바로 아래의 textarea**에만 `크게`를 끼웁니다(이름표 줄의 오른쪽 끝에 떠 있는 작은 단추 — 줄 높이는 그대로). 이름표 줄이 없는 칸(붙여넣기의 표 칸 · 줄 칸 붙여넣기 · 문서 편집기 `#wikiText`)과 한 줄 input은 `Alt+Enter`만. 한 줄 input은 허용 목록 `HT.fieldPop.INPUTS`(출처 `name="source"` · 메모 `name="note"` · 줄의 `.c-note` · `.s-note` · 나라별 서술 `.view-desc`) 또는 칸에 `data-fp`(빼려면 `data-fp="off"`).
* **비추기 · 다시 묶기의 문맥**: 칸을 품은 창은 `data-fp-scope`(편집 창 `#editPane` · 문서 창 `#wikiPane` — 없으면 대화상자 · form), 문맥은 가까운 조상의 `data-fp-ctx` — 편집 창은 **다른 항목을 채울 때만** 새 번호(저장 뒤 같은 항목을 다시 채우는 refill은 그대로), 문서 편집기는 문서 키. 문맥이 같을 때만 이름(`name`)이 같은 칸, 줄 칸은 "줄 묶음의 `data-*` + 줄 순번 + 그 줄의 이름 · 시작 값"이 같은 줄의 같은 칸에 다시 묶습니다. 그 밖에는 곧장 `원래 칸이 닫혔습니다`(읽기 전용 · `복사` · 닫기). `setDraft`(다른 DLC · 파일 열기 · 설치된 판 다시 불러오기)는 `HT.fieldPop.detach()`로 강제로 뗍니다. 칸이 다시 그려지거나 닫히는 것은 그 창 안만 지켜봅니다(MutationObserver — 연표의 잦은 변화는 보지 않음).
* **바꾼 기존 줄**: `js/wiki.js`(`namu.editor` — 자동 완성 상자와 재는 거울을 `ta.closest('dialog') || body`에 · 칸에 `ta.htNamuOpts`를 남김(큰 입력 창이 같은 이름 목록으로 편집기를 붙임) · `onInput`이 `ev.htMirror`를 건너뜀 · 목록 이어쓰기 Enter에 `!e.altKey`) · `js/viewer.js`(`fillEditor`의 문맥 번호 · `attach` · 폼 문서 칸 편집기를 채울 때마다 떼어 자동 완성 상자가 body에 쌓이지 않게 · `renderWiki`의 문맥) · `js/maker.js`(`setDraft`의 강제 떼기).
* **새 브라우저 창으로 꺼내기**(8절 3번 — 따로 된 커밋이라 문제가 있으면 그 커밋만 되돌리면 됨): 창 머리의 `↗ 새 창`(`HT.platform.name === 'web' && !HT.platform.mobile`일 때만). `window.open('', 'ht-fieldpop', 'popup')`에 글 칸 하나만 그리고(모양은 이 화면의 색 토큰을 읽어 새 창의 `<style>`에), 이 화면의 창은 숨깁니다. 비추기 규칙은 같고 "창에 초점"은 그 창이 앞에 있고 글 칸에 초점이 있을 때. 한 번에 하나 — 꺼내 둔 채 다른 칸을 열면 그 창이 그 칸으로. 정리: 새 창을 닫으면(`pagehide` + 0.6초마다 `closed` 확인) 묶음을 마치고(바뀌었으면 `change`), 이 화면이 닫히면(`pagehide`) 새 창도 닫고, 원래 칸이 닫히면 새 창에도 `원래 칸이 닫혔습니다`. 팝업이 막히면 알림만. 이 작업 환경의 브라우저는 팝업을 막아 실제 새 창은 열어 보지 못했고, 같은 출처의 iframe을 새 창 대신 넘겨 비추기 · Ctrl+S 저장 · 다른 항목으로 가기 · 다른 칸으로 옮기기 · Esc · 창 닫힘 정리를 확인했습니다.
* **검토 반영(f3)** — ① **이름표는 글 칸을 가리킴**: `크게` 단추가 `<label class="field">` 안에 들어가면 `for`가 없는 이름표는 안의 첫 단추를 제 칸으로 삼아, 이름표 글자를 누르면 큰 입력 창이 뜨고 글 칸은 이름을 잃었습니다 — `attach`가 글 칸에 id(없으면 `fp-text-차례 번호`)를 주고 이름표의 `for`로 글 칸을 가리킵니다(이름표를 누르면 예전처럼 글 칸에 초점). 새 폼이 `label.field`에 제 `for`를 달아 두었으면 그대로 둡니다. ② **닫힘 알림은 사실만**: `원래 칸이 닫혔습니다` 뒤의 글은 창의 글이 닫히기 전에 원래 칸에 모두 들어갔으면 "모두 들어갔습니다 — 이제 읽기만", 아니면 "들어가지 못한 것이 있으니 복사해 두세요"(저장했는지는 그 칸의 창에서 한 대로라 말하지 않음 — 위 비평의 "글은 이미 저장돼 있습니다"는 칸마다 저장하던 옛 메이커의 전제라 쓰지 않음). 창에서 누른 `Ctrl+S`의 저장이 칸을 곧바로 닫으면(문서 편집기는 저장하면 읽기 화면으로) 알림 대신 창도 함께 닫힙니다.
* **통합 때 끼울 자리** (설정만): 조약의 서명자 글 · 조항 본문처럼 한 줄 input인데 긴 글이 들어가는 칸은 `HT.fieldPop.INPUTS.push('input.…')`(또는 칸의 HTML에 `data-fp`). 새 폼의 textarea는 `label.field > span + textarea` 꼴이면 저절로 `크게`가 붙습니다. 새 줄 칸(지위 변천 · 섬긴 기록 · 당사국 · 조항 · 구성 정권)은 `…-row` 클래스의 줄이 `data-*`가 달린 묶음 바로 아래에 있고 이름 칸이 `.c-name`/`.s-from`, 시작 칸이 `.c-start`면 다시 묶기 규칙이 그대로 듭니다(아니면 `ROW_KEYS`에 한 줄).

### 통합 — 메이커 갈아엎기(A)를 종류 · 인물 · 칸 · 가문 · 미정 · 조약 · 시기 · 지위(B · C · E) 위에 합치며 이은 것

* **보기 전용 지키기**: 다른 줄이 만든 상세(인물 · 칸 · 시기 · 지위 · 가문 창)의 `✎ 수정` · `🗑 삭제` · `↩ 원래대로`는 메이커에서만, 문서 단추는 A의 규칙대로(연표에서는 문서가 있을 때만). 메이커에서 편집 창이 붙어 있을 때 가문 창처럼 편집 창이 없는 것을 열면 편집 창을 닫고 상세로.

### 통합 — 플래그 탭 · 실재성 · 민족 딱지 · 대범위(D)를 그 위에 합치며 이은 것

* **소속선 · 계승선**: B의 관계 설명글(이어진 구간 전체) · 부흥 고리에 D의 대범위 이름표 비키기 · 부정된 나라의 옅은 선(`is-refuted` — 부흥 고리에도)을 함께. 되돌아가는 계승선의 통로는 D의 위 · 아래 두 후보에 B의 고리 여유(5px).
* **소속 줄**: B의 "정말 이 띠 아래에 접히는 정권만"(`m._host === host`)과 D의 "켠 대범위로 떠난 정권은 옛 상위 아래에 두지 않음"을 한 조건에.
* **대범위 × 메이커(A)**: `HT.FORMS.scope`는 메이커의 추가 메뉴에 두지 않음(`add: false` — 작업본의 항목 목록에 대범위가 없어 넣으면 저장이 깨짐), 편집 창으로 가는 길(`openEditorFor` · 우클릭의 수정 · 연표의 '메이커에서 고치기')도 대범위는 상세로. 파일에 적은 대범위는 작업본에 그대로 실려 반영 · 파일로 길에 나감. 연표의 대범위 상세 문서 단추는 다른 상세와 같은 규칙(문서가 있을 때만).
* **실재성 × 메이커(A)**: 패치 칸 목록(맨 위로 옮긴 `PATCHABLE`)에 `historicity` · `historicityNote` — 편집 창에서 남의 나라 실재성을 바꾸면 그 칸만 패치로, 되돌리면 패치가 사라지고, 실재로 되돌리는 패치(`null`)도 반영 · 파일로 길에서 형식 2(`HT.usesNewFormat`의 함수 줄). 메이커 화면(`dlc-maker.html`)에도 실재성 · 대범위 칩 줄.
* **할거 · 부흥 × 종류(B)**: 견본 `sample-scopes.json`의 두 부흥 세력이 본국을 B의 부흥 계승(`revival`)으로 이어, 켜면 세력마다의 부흥선이 본국에서 테두리로 가는 한 줄로 묶임(끄면 B의 고리 달린 부흥선 둘).
* **다음(통합 마무리) 몫** — **끝남**(아래 '통합 마무리(f1 · f2)' — 위 `add: false`와 상세로 돌려보내던 길은 그때 걷어 냄): 메이커에서 대범위를 고치는 자리(작업본의 목록 · 항목 목록에 `scopes` — 비운 id의 씨앗은 읽기와 같게 `트랙 + 이름 + 시작 해` · 바탕 자료 창이나 편집 창 · 미리보기 스위치 · 검사의 '계승 줄이 끊기는 구성 정권' 알림), 바탕 자료 창의 실재성은 해당 없음(시대 폼에 있음).

### 통합 마무리(g2) — 그림 내보내기 · 작은 빈틈 · 범례 · 문서
* **책갈피 탭의 글은 함수 하나**(`tabParts` · `tabRank` — js/timeline.js 위쪽): 화면(`_drawTrack`)과 그림 내보내기(`toSVG`)가 같은 탭 자리 · 같은 폭 셈으로 불러 딱지의 차례(이름 → 종류 · 관계 → 실재성 → 지위) · 수 · 첫 글자 줄임이 늘 같음 — 그림에서 옛 종류(종속 · 연맹 · 조직 · 시대)의 딱지를 빼던 규칙과 "종류 딱지만 빼고 이름은 남김"을 없애고 지위 딱지를 더함(옛 자료의 그림은 화면과 같아지는 쪽으로만 바뀜 · 연표 화면은 그대로). 기본팩 + 견본 열넷을 여러 보기 · 대범위 켬 · 소속 펼침으로 그려 화면의 탭 2004개와 그림의 탭 글이 하나도 다르지 않음을 확인.
* **그림 내보내기의 나머지 빈틈**: 소속 관계로 이어 붙은 예속 띠 칸 사이의 미정 경계는 두 칸의 테두리 대신 점선 하나(그때만 칠과 테두리를 나눠 그림) · 시기 칸의 미정인 바깥 끝은 지도자 · 지위 칸과 같은 가림막(`fadeMask`)과 점선 구분선 · 가문 줄도 그 칸의 가림막을 함께 받음 · 접힌 줄의 이름은 화면의 왼쪽 줄 이름처럼 접힌 묶음(민족 · 대범위 가지)의 이름.
* **연표의 빈틈**: 시작이 미정인 띠가 화면 왼쪽 가장자리에서 잘리면 왼쪽 22px 둥근 모서리를 폄(`cut-l` — 가장자리에 붙은 탭 아래 약 5px 틈. 탭이 없는 오른쪽, 곧 끝이 미정인 띠가 오른쪽 밖으로 나갈 때는 옛 화면 그대로 — 9절) · 화면의 가문 줄도 바깥 끝이 미정인 칸 아래에서 함께 옅어짐 · 계승선의 세로 통로(그리고 본국에서 테두리로 가는 부흥선 묶음)가 같은 트랙의 다른 가지 이름표를 곧게 지나면 이름표 오른쪽으로 비켜 감(소속선 · 되돌아가는 길과 같은 규칙, 자리가 없으면 그대로) · 모여드는 움직임의 섞인 줄에서 기관 칸(`o:`)과 할거 단추(`sb:`)도 그려지는 띠(`data-band`)를 따라 정권 단위로 · 전설 · 반전설 + 전승 연대의 종속 갈래 · 망명 · 부흥 세력 · 연맹 · 기관 · 시기 · 미정 띠에는 안개 빗금 없음(부정됨 쪽과 같은 목록) · 연표 몸통의 단추(민족 딱지 · 민족 칸 · 접힌 줄 이름 · 소속 · 할거 단추 · 트랙 이름)를 키보드(`Tab` → `Enter` · `Space`)로 누를 수 있음(누름과 같은 길 `pressButton` — 예전에는 초점만 가고 아무 일도 없었음) · 표 보기 CSV의 맨 끝에 `실재성` 열.
* **글**: 범례 · 표시 체크의 '같은 시기를 다른 나라에도' 설명이 실제 동작대로(지도자 · 내각 · 연호 · 도읍 · 왕조 · 시기 · 지위 칸과 인물 창의 섬긴 기간 모두) — `dlc-maker.html`의 같은 체크 설명은 메이커 갈래(F)와 합칠 때 같은 글로. DLC-형식.md의 형식 버전 설명을 절마다 같은 말("하나라도 쓴 파일만 2 · 쓰지 않으면 1 · 읽는 버전은 2")로, README의 견본 목록(열넷), 용어집의 새 낱말, 움직임 원칙의 모여듦 줄. dev-smoke는 블록 번호를 파일 안의 차례대로(④ ~ ⑭) 고쳐 매기고 ㉒를 더함.

### 통합 마무리(f1 · f2) — 메이커 배선 (g1 · g2와 합침)
* **끝낸 것**(위 두 '다음(통합 마무리) 몫'과 g1 · g2의 몫): 바탕 자료의 지위 사전 · 가문 칸 ✔ · 메이커의 대범위 편집 ✔ · 끝낸 전쟁 · 대체한 조약 자동 완성 ✔(f1 · f2) / 지위 변천 · 섬긴 기록 · 활동 시기의 미정 ✔ · 인물 창의 서명한 조약 ✔(g1) / 그림 내보내기를 화면과 맞춤 ✔(g2).
* **바탕 자료 창 일곱 칸**(트랙 · 분류 · 민족 · 시대 구분 · 지위 · 가문 · 대범위): 지위 · 가문은 표(`BASE_TABLES.rankDefs` · `houses` — id · 이름을 바꾸면 적은 곳이 따라감: 지위는 `RANK_PATHS`의 칸에서 이름 자리만(`[지위, 시작, 끝]` · `{ name }` · `{ rank }` 꼴과 g1의 `"미정"` · `startUnknown` · `startHint`는 그대로), 별칭으로 적은 곳은 쓰는 곳에만 셈. 다른 DLC가 먼저 쓰는 id면 '다른 DLC 우선' 딱지와 따라 바꾸지 않음), 대범위는 목록(누르면 편집 창). `HT.readRankDefs`는 경고마다 줄 차례(`at`)를 돌려 검사 창이 그 줄로 감.
* **대범위 편집**: 작업본의 목록 · 항목 목록에 `scopes`(`HT.normalizePack`이 시대 구분 바로 다음에 읽으므로 그 자리 · 비운 id의 씨앗은 읽기와 같은 `scopeSeed`), 추가 메뉴의 `＋ 대범위 추가`(단축키 없음), 편집 창과 상세 사이의 판단은 `paneEditable` 하나(openDetail · openEditorFor · 우클릭 메뉴), 편집 창 맨 위의 모아 보기 스위치(`syncEditorScope`), 검사의 대범위 경고와 '계승 줄이 나뉘는 곳' 알림(`scopeChecks`).
* **합칠 때 맞춘 것**: dev-smoke 끝 블록은 g1 · g2의 ㉑ ~ ㉓ 다음에 f1 · f2의 것을 ㉔ ~ ㉗로(파일 안 차례 = 번호 차례), `dlc-maker.html`의 '같은 시기를 다른 나라에도' 설명을 `index.html`과 같은 글로, README 편집 창 절은 g1의 시대 · 인물 폼 미정 글과 f1 · f2의 자동 완성 · 대범위 폼 글을 함께.
* **합친 뒤 검토 고침**: 파일에 배치용 연도를 `startHint` · `endHint`로 적은 제 항목(시대 · 사건 · g1의 인물 활동 시기 · f2의 대범위)을 편집 창에서 고쳐 저장하면, 폼의 숫자 칸(= 배치용 연도)은 `start` · `end`에 들어가는데 옛 `startHint` · `endHint`가 작업본에 남아 읽을 때 그것이 먼저 쓰여(`HT.readCellEdge` · `readRange`) 고친 연도가 소리 없이 버려졌음 — 작업본에 옮길 때(`putFields`) 폼이 시작 · 끝을 적었으면 옛 배치용 연도 열쇠를 걷어 냄(내보내는 파일은 그대로 · dev-smoke ㉘).
* **통합 검토 고침(다섯 관점)** — dev-smoke ㉙: ① 옛 "내 수정"의 이사가 지금 설치돼 있지 않은 DLC의 고침 · 숨김을 버리지 않고 패치로 옮김(적힌 값 그대로 — 그 DLC를 다시 설치하면 얹힘 · 알림에 따로 셈), 이름을 바꾼 남의 문화는 계승한 국가를 패치에 함께 담아 상대의 `succeeds`(옛 이름)에서 온 계승선을 지킴(메이커에서 이름을 바꿀 때도), 숨김 · 추가로 트랙 안의 자동 색 차례가 바뀌어 고친 항목의 색이 옛 화면과 달라지면 옛 색을 담음(이사에서만). ② 바탕 자료에서 트랙 id를 바꾸면 조약 당사국의 `"트랙:이름"` 글(당사국 줄이 글 · 트랙 칸이 빈 줄의 `polity`)도 따라감, 시대 구분의 이름을 바꿔 저장하면 그 이름으로 적은 대범위도 따라감(목록의 `쓰는 곳` · 지울 때 물음). ③ 표 붙여넣기의 종류 낱말이 파일 읽기(`HT.KIND_WORDS`)와 같은 표('조공국' → 조공·책봉국), 시작 `"미정"` + 끝 연도에서 끝이 버려지던 것(붙여넣기 · 파일 · 폼의 한 시점 규칙이 시작 미정일 때도 끝을 지웠음 — 화면 글과 자리는 그대로). ④ 민족 칸 이름이 대범위 가지를 비킬 때 줄 사이 틈까지 넓혀 재고, 그래도 들어가지 않으면 첫 글자만(딱지와 같은 규칙) · 그림 내보내기의 예속 띠 글을 보이는 부분의 가운데에. ⑤ 인물 창의 같은 시기의 지도자에서 같은 지도자가 두 번 나오던 것 · 한쪽 끝만 짐작한 활동 시기의 글. ⑥ 버전 2의 패치 칸을 비우는 패치(`treaty: null` 포함)도 형식 2, 패치의 `phases` · `ranks`: `null`은 무시하고 알림(문서대로), 패치의 `startHint` · `endHint`를 항목처럼 읽음, 문서 · README · 메이커 단추 도움말의 어긋난 글.
* **일방통행(2026-09-19 감독 결정)** — "연표-메이커 쌍방 이동 말고 메이커에서 연표로만 · 연표에서 수정한다던가 메이커로 보낸다던가 금지" + "메이커를 별도 프로그램으로": 연표의 `🛠 메이커에서 고치기`(우클릭 · ⋯ 메뉴 · `Shift+M`) · DLC 관리의 연표 쪽 `메이커에서 고치기` 단추 · 항목 넘겨주기(`HT.KEYS.handoff` · 메이커의 `#handoff` 받기 · 앱의 `ht:handoff` 신호)를 모두 걷고, 보기 전용 거절 알림은 `연표는 보기 전용입니다.`만(메이커 안내 없음), 큰 입력 창(`js/fieldpop.js`)은 메이커만 읽음. 남는 길은 메이커의 `연표로 ↗`(`HT.platform.openPage('index.html')` — 앱에서 이미 열린 창이면 앞으로 가져오기만) 하나이고, 메이커는 늘 마지막에 고치던 작업본으로 뜸(없거나 빈 작업본이면 고르는 창). 위 '화면 둘'의 "메뉴에 `메이커에서 고치기`"와 대범위 줄의 "연표의 '메이커에서 고치기'"는 이것으로 없어짐 — dev-smoke ㉚. 두 프로그램으로 나누는 포장은 따로.
