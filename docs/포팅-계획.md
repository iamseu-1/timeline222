**만든 DLC 옮기기** — 두 프로그램은 저장소가 따로라 메이커의 `반영`은 메이커 안의 연표 미리보기에만 보입니다. 메이커의 `파일로`로 DLC 파일을 저장 → 연표의 `DLC 관리`에서 설치합니다. 같은 id가 이미 있으면 연표는 두 판을 보여 주며 바꿀지 한 번 묻고(`confirm`), 확인하면 판과 상관없이 새 파일로 덮어쓰고 켭니다(`js/viewer.js`의 `installFiles` — 판이 낮은 파일도 확인하면 덮어씀). 거꾸로 연표에 설치해 둔 DLC를 고치려면 연표의 `DLC 관리 → 내보내기`로 받은 파일을 메이커에서 엽니다. 웹(PWA)으로 올릴 때는 `dist/web`과 `dist/maker`를 **따로** 올리며, 같은 사이트(origin)의 두 폴더면 브라우저 저장소를 함께 써서 `반영`이 연표에 바로 보이고, 다른 사이트면 위처럼 파일로 옮깁니다.

## 0. 한 줄 결론

* **웹 폴더 하나가 유일한 원본**이고, PC 앱·모바일 앱은 그 폴더를 **그대로 감싸는 껍데기**만 둡니다. 기능 코드는 한 벌만 관리합니다.
* 플랫폼마다 달라지는 것은 코드에서 **일곱 군데**(파일 저장 2, 파일 열기 2, 인쇄 1, 다른 화면 열기 1, 외부 링크 1)뿐입니다. 이것을 `js/platform.js` 한 파일로 모아 두면, 껍데기가 Tauri든 Capacitor든 PWA든 나머지 코드는 손대지 않습니다.
* 순서는 **① 플랫폼 경계 정리 → ② PWA → ③ Tauri 2로 Windows 실행 파일 → ④ 모바일(Tauri 2 안드로이드, 안 되면 Capacitor) → ⑤ 자동 빌드·배포**. ①~③까지 3~4일, ④는 2~3일 + 스토어 절차입니다.
* 프레임워크 재작성, 번들러 도입은 **하지 않습니다**. 지금처럼 `index.html` 더블클릭으로도 계속 열려야 합니다.

## 1. 원칙

1. **원본은 하나** — `index.html`, `dlc-maker.html`, `css/`, `js/`, `packs/`, `samples/`가 전부이며, 앱 프로젝트는 이 파일을 복사해 넣을 뿐 수정하지 않습니다.
2. **기능 100% 보존** — README 2절의 기능표를 그대로 검사표(6절)로 쓰고, 플랫폼마다 전부 통과해야 "포팅 완료"입니다.
3. **빌드 도구 없이 동작** — 브라우저에서 파일을 직접 열어도 지금처럼 돌아가야 합니다. 앱 전용 코드는 `window.__TAURI__` 같은 존재 여부로 **실행 시점에** 갈라집니다.
4. **명령 하나로 산출물 하나** — 대상마다 `npm run <대상>` 한 줄이면 설치 파일이 나오도록 합니다.

## 2. 최종 폴더 구조

```
(루트)                          ← 지금 그대로. 더블클릭 실행 유지
├ index.html · dlc-maker.html
├ css/ js/ packs/ samples/
├ js/platform.js                ← [새로] 플랫폼 경계 (저장·열기·인쇄·화면 이동·외부 링크)
├ manifest.webmanifest · sw.js  ← [새로] PWA
├ icons/                        ← [새로] 앱 아이콘 원본 1개(1024px)에서 자동 생성
├ package.json                  ← [새로] 스크립트 모음 (아래 표)
├ scripts/
│  ├ build-web.mjs              ← 배포용 파일만 골라 dist/web/ 로 복사 (허용 목록 방식)
│  └ sync-version.mjs           ← package.json 버전을 tauri.conf.json · manifest · sw.js 에 맞춤
├ src-tauri/                    ← [새로] Tauri 2 (PC + 안드로이드). Rust 코드는 거의 비어 있음
│  ├ tauri.conf.json            ← frontendDist: "../dist/web"
│  ├ capabilities/default.json  ← 파일 대화상자·파일 쓰기 권한
│  └ gen/android/               ← `tauri android init`이 만드는 안드로이드 프로젝트
└ docs/
```

| 명령 | 결과 |
| --- | --- |
| `npm run web` | `dist/web/` 생성 (다른 모든 명령의 입력) |
| `npm run pwa:serve` | 로컬에서 PWA 설치 테스트 |
| `npm run desktop:dev` | Tauri 창으로 실시간 확인 |
| `npm run desktop:build` | `역사연표-x.y.z-setup.exe` (NSIS) · `.msi` |
| `npm run android:dev` | 연결한 폰·에뮬레이터에서 실행 |
| `npm run android:build` | `.apk`(직접 배포) · `.aab`(플레이 스토어) |
| `npm run release` | 버전 올리기 → 태그 → GitHub Actions가 전 플랫폼 빌드 |

## 4. 단계별 계획

### 1단계 — 플랫폼 경계 정리 (반나절, 앱 없이 브라우저만으로 완료)

목표: 앱 프로젝트를 만들기 전에 웹 코드 쪽 준비를 끝내고, 브라우저에서 **아무것도 달라지지 않았음**을 확인합니다.

1. `js/platform.js` 신설. 인터페이스는 여섯 개:
   ```js
   HT.platform = {
     name: 'web' | 'pwa' | 'tauri' | 'capacitor',
     saveFile(filename, blob),        // Promise<boolean>
     openFiles(accept, multiple),     // Promise<{ name, text }[]>
     print(svgString, title),
     openPage(page, hash),            // 'dlc-maker.html', '#handoff'
     openExternal(url),
   };
   ```
   기본 구현(web)은 지금 `core.js`의 코드를 그대로 옮긴 것. `core.js`의 `downloadBlob/downloadJSON/pickFiles/readFile`는 `HT.platform`으로 위임하는 한 줄짜리 껍데기로 남겨 호출부 12곳을 건드리지 않습니다.
2. 인쇄를 숨긴 `<iframe>` 방식으로 교체 (`js/viewer.js:1022`). 브라우저에서도 팝업 차단 문제가 사라지므로 순수 개선입니다.
3. 메이커 열기·"연표 열기" 링크·출처 링크를 `HT.platform.openPage/openExternal`로.
4. CSS: `100vh`→`100dvh` 2줄, 글꼴 스택에 `"Noto Sans CJK KR"` 추가, `env(safe-area-inset-*)` 패딩을 헤더·필터 바·`＋－⤢` 버튼에 추가(브라우저에서는 0이라 영향 없음).
5. `index.html`·`dlc-maker.html`에 `<script src="js/platform.js">`를 `core.js` **앞에** 추가.
6. `scripts/build-web.mjs`: 허용 목록(`index.html dlc-maker.html css js packs samples icons manifest.webmanifest sw.js`)만 `dist/web/`로 복사. `.git`·`docs`·`src-tauri`가 앱에 섞여 들어가지 않게 하는 안전장치입니다.

검증: 크롬·엣지에서 파일 직접 열기 + `python -m http.server`로 열기, 6절 검사표 전부.

### 2단계 — PWA (반나절)

목표: 스토어 없이 **오늘 당장** 폰·PC 홈 화면에 설치되고 오프라인으로 도는 버전. iOS는 Mac이 없는 한 이 경로가 유일합니다.

1. `manifest.webmanifest`: 이름·아이콘(192/512, maskable)·`display: standalone`·`start_url: index.html`·`shortcuts`(연표 / DLC 메이커)·`file_handlers`(`.json` → 크롬 데스크톱에서 "연결 프로그램")·`share_target`(안드로이드에서 .json 공유 받기).
2. `sw.js`: 설치 시 `dist/web` 파일 목록을 통째로 캐시(precache). 버전 문자열은 `sync-version.mjs`가 넣음. **캐시 우선, 새 버전 감지 시 "새로고침" 토스트**.
3. 등록은 `location.protocol`이 `http`/`https`일 때만 — `file://` 더블클릭 실행을 깨지 않기 위해.
4. 호스팅: GitHub Pages(무료, https). `gh-pages` 브랜치에 `dist/web`만 올리는 액션 하나.

한계(문서에 적어 둘 것): iOS 사파리 PWA는 7일 미사용 시 저장소가 지워질 수 있음 → "백업 파일 저장" 안내를 첫 실행 토스트로.

### 3단계 — Windows 실행 파일: Tauri 2 (1~2일)

Electron 대신 Tauri를 고르는 이유: 설치 파일 5~10MB(Electron은 100MB+), 프로젝트 파일이 `tauri.conf.json` 하나뿐이라 관리가 가장 쉽고, **같은 프로젝트로 안드로이드까지** 냅니다. Rust는 설치돼 있고(1.94), Rust 코드를 쓸 일은 없습니다.

1. `npx @tauri-apps/cli init` → `src-tauri/`. 설정 핵심:
   * `build.frontendDist: "../dist/web"`, `build.beforeBuildCommand: "npm run web"`
   * `app.withGlobalTauri: true` → 번들러 없이 `window.__TAURI__`로 플러그인 호출 (원칙 3)
   * `app.windows[0]`: 제목 "역사 연표", 1280×800, 최소 900×600
   * `bundle.targets: ["nsis","msi"]`, `bundle.fileAssociations`는 `.json` 전체 연결이 과해서 기본 꺼 둠
2. 플러그인: `dialog`(열기·저장 대화상자), `fs`(쓰기), `opener`(외부 링크). 권한은 `capabilities/default.json`에 `dialog:allow-open/save`, `fs:allow-write-file` + 대화상자에서 고른 경로만 허용.
3. `js/platform.js`에 `tauri` 구현 추가 (`window.__TAURI__`가 있으면 자동 선택):
   * `saveFile`: `dialog.save({defaultPath: filename, filters})` → `fs.writeFile(path, new Uint8Array(await blob.arrayBuffer()))`
   * `openFiles`: `dialog.open({multiple, filters:[{name:'DLC', extensions:['json']}]})` → `fs.readTextFile`
   * `openPage`: `new WebviewWindow('maker', {url:'dlc-maker.html#handoff'})` — 이미 열려 있으면 앞으로
   * `openExternal`: `opener.openUrl`
   * 끌어다 놓기: Tauri의 `onDragDropEvent`로 경로를 받아 `fs.readTextFile` → 기존 `installFiles`에 넘김 (WebView2 기본 drop이 파일 내용을 안 주는 경우 대비)
4. 저장 내구성(5절): 앱에서는 `HT.store.set` 뒤에 300ms 디바운스로 `appDataDir/state.json`에 전체 키를 거울 저장. 시작 시 localStorage가 비어 있고 파일이 있으면 복원. 사용자에게 "데이터 폴더 열기" 버튼(DLC 관리 안)을 줌 — 백업·이관이 쉬워짐.
5. 아이콘: `npx tauri icon icons/app-1024.png` 한 번으로 전 플랫폼 아이콘 생성.
6. `npm run desktop:build` → `src-tauri/target/release/bundle/nsis/*.exe`. WebView2 런타임은 Windows 10/11에 기본 포함, 없으면 설치 파일이 내려받음(기본 설정).

검증: 6절 검사표 + 창 두 개(연표·메이커) 사이 DLC 설치 즉시 반영, 저장→재실행 후 유지, 파일 저장/열기 대화상자, 인쇄.

알아둘 것: 코드 서명 없이 배포하면 Windows SmartScreen 경고가 뜹니다. 개인 배포면 "추가 정보 → 실행" 안내로 충분하고, 널리 배포하려면 서명 인증서(연 20~40만 원)가 필요합니다.

### 4단계 — 모바일 앱 (2~3일 + 스토어 절차)

**4-a. 먼저 하루 실험(spike)으로 도구를 확정합니다.**

| | Tauri 2 안드로이드 | Capacitor |
| --- | --- | --- |
| 장점 | 3단계와 **프로젝트·설정·플러그인이 같음** → 관리 대상 하나 | 모바일에서 가장 검증됨. 파일·공유·뒤로가기 플러그인이 공식 |
| 약점 | 모바일용 공유 시트·파일 선택이 커뮤니티 플러그인 의존 | 프로젝트가 하나 더 생김(`android/`), 설정이 두 벌 |
| 판단 기준 | 실험에서 **파일 열기·저장(공유)·뒤로가기** 세 가지가 되면 Tauri로 확정 | 하나라도 막히면 Capacitor |

어느 쪽이든 `js/platform.js`에 구현 하나 추가하는 것이 전부이고 웹 코드는 같습니다.

**4-b. 공통 작업 (도구와 무관)**

1. 안드로이드 설정: `ANDROID_HOME` 지정(Android Studio는 설치돼 있음, SDK 경로만 등록), NDK 설치, `minSdk 26`, 화면 회전 허용, 서명 키(`keytool`)는 저장소 밖에 보관.
2. 파일 저장 = **공유 시트**: 앱 캐시 폴더에 쓰고 `Intent.ACTION_SEND` → 사용자가 드라이브·카카오톡·파일 앱 중 선택. 안드로이드 10+ 저장소 정책상 이 방식이 가장 안정적입니다. PNG·CSV·SVG·DLC·백업 전부 같은 경로.
3. 파일 열기: 기존 `<input type=file>` 유지(안드로이드 WebView가 시스템 파일 선택기를 띄움) + **"연결 프로그램"** — `application/json` 인텐트 필터로 파일 앱·카톡에서 받은 .json을 연표로 열어 `installFiles`에 넘김. 끌어다 놓기의 모바일 대체.
4. 뒤로가기 버튼: 상세 패널 열림 → 닫기, 대화상자 열림 → 닫기, 메이커 화면 → 연표로, 그 외 → 앱 종료 확인. `HT.platform.onBack(handler)` 하나 추가.
5. 인쇄 버튼 숨기고 "PDF·이미지 공유"로 라벨 변경.
6. 모바일 UI (CSS만, `@media (max-width: 720px)`; 데스크톱 화면 변화 없음):
   * 필터 바를 접이식 서랍으로(지금은 여러 줄로 접힘 → 연표 영역을 잠식)
   * 터치 대상 최소 40px: 트랙 이름·민족 칸·`▸ 3` 세모·`＋－⤢`
   * 상세 패널은 이미 전체 폭 → 닫기 버튼만 크게
   * 표 보기·DLC 관리 대화상자 세로 스크롤 확인
7. 성능: 기본팩(시대 84·사건 200+) + DLC 몇 개를 중급 폰(Galaxy A 시리즈급)에서 핀치 줌이 매끄러운지 확인. 느리면 `timeline.js`의 렌더 스로틀만 조정.

**4-c. iOS** — Mac + Xcode + Apple 개발자 등록(연 $99)이 필요합니다. Windows 환경에서는 **2단계 PWA로 대신**하고, Mac을 쓸 수 있을 때 같은 프로젝트에서 `tauri ios init`(또는 `cap add ios`)만 추가하면 됩니다. 웹 코드·플랫폼 어댑터는 변경 없음.

**4-d. 배포** — 직접 배포는 `.apk` 파일 공유로 끝. 플레이 스토어는 개발자 등록(1회 $25) + `.aab` + 스크린샷·개인정보 정책 페이지(데이터를 기기 밖으로 보내지 않는다는 한 쪽짜리).

### 5단계 — 자동화와 관리 (1일)

1. `sync-version.mjs`: `package.json`의 버전 하나만 올리면 `tauri.conf.json`·`manifest.webmanifest`·`sw.js` 캐시 이름·안드로이드 `versionCode`가 맞춰짐.
2. GitHub Actions `release.yml`: 태그 `v*`를 밀면 Windows 설치 파일·안드로이드 apk·PWA 배포를 한 번에. `tauri-apps/tauri-action` 공식 액션 사용. (macOS 러너를 켜면 Mac 빌드도 같이 나옴 — 서명 없이는 실행 경고.)
3. Tauri `updater` 플러그인: GitHub Releases의 `latest.json`을 보고 앱 안에서 "새 버전 받기". 서명 키 한 쌍 필요(무료, `tauri signer generate`).
4. `README.md` 7절 폴더 구성에 새 폴더 반영, `docs/포팅-검토.md`는 "결정 완료" 표시.

## 5. 저장소 설계 (3절 7번 자세히)

`HT.store`의 호출부 39곳이 전부 동기(`get`이 값을 바로 돌려줌)라 비동기 저장소(IndexedDB·파일)로 바꾸면 39곳 + 그 위의 흐름을 다 고쳐야 합니다. 그래서:

* **살아 있는 저장소는 그대로 `localStorage`** — 동기 API 유지, 코드 변경 0.
* **앱에서는 거울 저장** — `platform.js`가 `HT.store.set/remove`를 감싸서, 변경 후 300ms 뒤에 `ht.*` 키 전부를 JSON 하나로 앱 데이터 폴더(`state.json`)에 씁니다. 실패해도 localStorage는 멀쩡합니다.
* **시작 시 복원** — localStorage가 비어 있고 `state.json`이 있으면(OS가 WebView 저장소를 비운 경우, 앱 재설치 후 폴더만 남은 경우) 되돌려 넣습니다.
* **용량** — localStorage 5~10MB는 DLC 수십 개까지는 충분합니다. 넘어서면 그때 `installed` 키만 파일로 분리하면 됩니다(설치 목록은 시작 시 한 번만 읽으므로 그 한 곳만 비동기로 바꾸면 됨).
* **웹 ↔ 앱 사이 데이터 이동** — origin이 달라 자동으로 옮겨지지 않습니다. 이미 있는 **백업 파일 저장 / 복원** 기능이 그 역할이므로, 앱 첫 실행 화면에 "브라우저에서 쓰던 데이터가 있다면 백업 파일을 복원하세요" 한 줄만 둡니다.
