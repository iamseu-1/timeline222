## 1. 모든 건의에 걸리는 전제

1. **다섯 곳을 함께 고친다.** 새 자료 기능은 ① `DLC-형식.md` + `js/core.js`의 읽기(`normalizePack` · 모델) ② 웹 메이커의 폼 ③ 웹 연표(메이커의 미리 보기도 이것) ④ 새 앱용 내보내기(`prototype/scripts/export-layout.mjs` → 가져오기 JSON) ⑤ 엔진(저장소 · 타일) + 새 앱 그리기를 함께 고쳐야 끝납니다(인수인계 10절 4번 · 2026-09-22 결정 "메이커는 웹, 보는 프로그램은 새 앱"). 그래서 **창(대화상자)으로 보이는 기능은 싸고, 띠 안에 새 단을 그리는 기능은 비쌉니다** — 띠 안의 것은 타일 형식 · 층 · 1배 비교 · 성능 측정까지 걸립니다. 또 **줄 배치(줄 높이 · 쌓는 차례)는 내보낼 때 웹의 규칙으로 미리 셈해 저장소에 싣고 새 앱은 스스로 셈하지 않으므로**, 보는 사람의 손짓에 따라 줄 높이 · 쌓는 차례가 바뀌는 기능은 '미리 셈한 변형'(지금 소속 펼치기 · 대범위의 길)을 거쳐야 합니다. 이 문서는 될 수 있으면 창부터, 띠 안은 공용 틀(2절 바탕 4) 하나로 들이는 길을 고릅니다.
2. **옛 파일은 1px도 다르지 않게.** 새 칸은 모두 선택 사항입니다. 지금 앱이 읽는 형식 버전은 `2`(`HT.FORMAT_VERSION`)이므로, 이번 새 열쇠는 **형식 버전 `3`** 으로 내보내야 옛 프로그램이 "더 새로운 형식" 경고를 띄웁니다. 읽는 버전은 하나뿐이라 새 열쇠를 더하는 묶음들은 master에 **한 덩어리로만** 합칩니다(`docs/구상-체제-확장.md` 0절 2번과 같은 까닭 — 중간 상태의 앱이 모르는 열쇠를 조용히 버림).
3. **지켜 온 규칙 그대로**: 겹침 · 띠 밖 돌출 금지, 띠 높이는 자료가 정함(줄 단위), 움직임은 토큰만(`--t-move` 360 · `--t-in` 200 · `--t-out` 160 · 되튐 없음), UI 글 · 입력 칸에 실제 역사 이름 예시 금지, 짐작한 값은 파일과 다른 이름의 칸에(파일에 굳지 않게), 연표는 보기 전용 · 편집은 메이커만.
4. **불확실은 하나의 자로.** 묶음 5에서 정한 "무엇을 모르는가 → 이미 있는 표시의 폭"(칸의 미정 = 옅어지는 끝 + 점선, 대수 미상 = 번호 없음, 부정됨 = 회색 안개)을 새 기능에도 씁니다. **'비움'(적지 않음)과 '미상'(모른다고 적음)을 늘 구별합니다** — 칸의 미정과 같은 구별.
5. **판타지 · 대체역사 겸용.** 새 사전(관계 낱말 · 주제 · 행정 층위 · 언어)은 모두 **자료**로 받고, 프로그램 안에는 뼈대만 둡니다(지위 사전의 "내장 뼈대 + DLC의 `rankDefs`" 선례). 실제 지리 · 실제 언어를 가정하지 않습니다.

## 2. 공통 바탕 다섯 — 여러 건의가 함께 쓰는 것

먼저 정해 두면 같은 것을 건의마다 따로 만들지 않습니다.

### 바탕 1. 사람 하나로 — 지도자 칸과 인물 잇기 (1 · 2 · 7이 씀)
* 지금: 지도자는 시대 안의 **칸**(제 id 없음)이고, 인물(`figures`)은 id가 있는 항목입니다. 둘은 "이름이 같고 시기가 겹치면 저절로" 이어질 뿐입니다(체제 확장 9절에서 '지도자 ↔ 인물 직접 연결 칸'을 뒤로 미룸).
* 계보(1) · 가문 구성원(2) · 단체 구성원(7)은 **사람**을 가리켜야 합니다. 그래서 지도자 줄에 선택 칸 `person`(인물 id나 이름)을 두고, 사람을 가리키는 새 칸은 모두 같은 **사람 참조** 하나로 받습니다: 인물 id · 이름, 또는 지도자 칸 `{ "polity": "…", "leader": "…", "start": … }`(글 `"나라:지도자@즉위 해"`도 읽음).
* 인물 항목을 따로 만들지 않은 지도자도 **칸 자체를 사람으로** 봅니다(인물을 다 적어야 계보를 그릴 수 있게 하지 않음). 같은 사람이 두 나라를 다스렸으면(동군연합 · 양위 뒤 다른 나라) `person`이 같은 두 칸이 한 사람입니다.

### 바탕 2. 이름 목록 `names` — 모든 이름 칸에 같은 꼴 (3이 주, 1 · 2 · 7 · 8 · 10이 씀)
```json
"names": [
  { "text": "…", "lang": "x-moon", "kind": "원어" },
  { "text": "…", "lang": "x-moon-Latn", "kind": "로마자" },
  { "text": "…", "kind": "옛 이름", "end": 520 }
]
```
* `text` 필수 · `lang` = 언어 꼬리표(국제 표준 BCP 47 — `ko` · `ja` · `zh-Hant` · `la` · `ar` …, 가상 언어는 `x-` 로 시작) · `kind` = 원어 · 로마자 · 한자음 · 현지음 · 옛 이름 · 약칭 · 자유 글 · `start`/`end` = 그 이름을 쓴 기간(국호 변천 — 3-3).
* 붙는 곳: 나라 · 왕조 · 가문 · 성씨 · 인물 · 지도자 칸 · 연호 · 지명(바탕 3) · 단체(7) · 제도(8) · 사건 제목. **같은 꼴 · 같은 메이커 줄 · 같은 읽기 함수 하나**(체제 확장 0절 3번의 "거름망 여러 겹"을 새로 늘리지 않게).
* 인물의 `aka`(다른 이름)는 그대로 읽고, 화면에서는 `kind` 없는 이름으로 함께 보입니다.

### 바탕 3. 지명 사전 `places` (3 · 10, 사건 장소)
* 지금 도읍의 `city`는 글자일 뿐이고 "같은 글자면 같은 도시"로 이어집니다. 원어 병기와 지도는 **같은 곳**을 가리킬 열쇠가 필요합니다.
* `places: [{ id, name, names, at?, parent?, note }]` — `at`은 좌표(지도가 있을 때만 · 바탕 지도가 그림이면 그림 좌표), `parent`는 행정 층위의 위 구역(10). 도읍 · 사건(`place` 칸 새로) · 조약 체결지가 가리킵니다.
* **사전에 없는 이름을 적어도 됩니다** — 그 이름으로 지명이 저절로 생깁니다(가문 · 민족과 같은 규칙). 그래서 지금 파일은 그대로 읽히고, 사전은 원어 · 좌표를 달고 싶을 때만 적습니다.

### 바탕 4. 띠 안 칸 단의 공용 틀 (1 · 2 · 7 · 8이 씀 — 렌즈의 바닥)
* 지금 띠 안의 칸 줄(지도자 · 내각 · 지위 · 시기 · 왕조)은 웹 연표에서도 엔진 계약(`docs/계약-아카이브-3단계.md` 6-2 · 6-4)에서도 **종류마다 따로** 구현돼 있습니다. 새 주제(가문 칠 · 세력 · 실권 · 제도)를 같은 식으로 하나씩 더하면 다섯 곳 고침이 주제마다 되풀이됩니다.
* 그래서 **일반 칸 단** 하나를 만듭니다: "어느 띠 · 어느 단 이름 · 칸 목록(이름 · 기간 · 색 · 무늬 · 미정 끝 · 이설)". 웹 연표는 지금의 긴 둥근 칸 그리기(`layoutStrip`)를, 엔진은 칸 구역 하나를 함께 씁니다. 그 뒤의 주제는 **엔진 · 새 앱을 고치지 않고 자료만으로** 늘어납니다.
* 높이 예산: 띠가 두꺼워지지 않게 **한 번에 주인공 단 하나**(렌즈가 고름 — 3-8)를 원칙으로 합니다.

### 바탕 5. 보는 방법의 저장 — 보기 상태 (3 · 6 · 8 · 9가 씀)
* 표기(3) · 모아 보기 판(6) · 렌즈(8) · 글꼴(9)은 **자료가 아니라 보는 방법**입니다. 연표는 보기 전용이므로 보는 사람의 설정(지금의 `ht.ui`와 같은 자리)에 저장합니다.
* 만든 사람이 권하는 기본값은 DLC에 담을 수 있게 합니다(대범위의 `default`, 앞으로의 `views` · 렌즈 사전). 보는 사람이 바꾼 것이 늘 이깁니다.

## 3. 건의별 구상

각 절: **원하는 것 → 지금 있는 것 → 구상(자료 · 연표 · 창 · 메이커 · 새 앱) → 미상 처리 → 그려서 고를 것 → 무게.**

### 3-1. 통치자 계승과 세계표 (건의 1)

**원하는 것**: 누가 누구의 뒤를 어떤 관계로 이었는지(계승표), 집안의 나무(가문표 · 세계표), 모를 때 쓰는 미정 표시.

**지금 있는 것**: 지도자 칸(`name` · 묘호 · 시호 · 이름 · 대수(`미상` 됨) · 기간 · 왕조 · 지위 · 가문 · 메모)과 ◀ 앞 · 다음 ▶ 이동. 가문의 본가 → 분가 나무. **지도자 사이 · 사람 사이의 관계(부자 · 형제 …)는 형식 어디에도 없습니다.** 승계선은 나라와 나라를 잇습니다.

**구상 — 자료 둘**
1. **즉위 관계**(계승표의 재료 — 지도자 줄의 선택 칸 `accession`):
   ```json
   { "name": "…", "start": 812, "end": 830,
     "accession": { "kin": "동생", "how": "추대", "from": "…", "note": "…" } }
   ```
   * `kin` = 앞 임금과의 관계(아들 · 손자 · 동생 · 조카 · 사위 · 양자 · 외손 · 방계 · 무관 …) · `how` = 오른 방식(세습 · 선양 · 찬탈 · 추대 · 선출 · 정복 · 복위 · 섭정 뒤 즉위 …) · `from` = 비우면 **바로 앞 칸**, 다른 사람이면 사람 참조(바탕 1 — 형의 아들이 이은 경우 · 복위).
   * 낱말은 내장 뼈대 + DLC 사전(`kinDefs`) — 지위 사전과 같은 규칙. 사전에 없는 글도 받습니다(판타지의 입양 의식 · 선택된 자 …).
   * **비움 = 적지 않음, `"미상"` = 모른다고 적음.** `kin`만 미상 · `how`만 미상도 됩니다.
2. **혈연**(가문표 · 세계표의 재료 — 사람 쪽 선택 칸, 지도자 줄과 인물 둘 다):
   ```json
   "parents": [ { "who": "…", "as": "부" }, { "who": "미상", "as": "모" } ],
   "spouses": [ { "who": "…", "start": 790 } ]
   ```
   * `as` = 부 · 모 · 양부 · 양모 · 생부 · 후손(`gen`: 몇 대손) … · `who`는 사람 참조. `who: "미상"`은 **이름 모를 사람의 자리**(세대 수를 지키는 빈 고리)입니다.
   * 즉위 관계의 `kin`과 혈연이 둘 다 있으면 혈연이 이기고, 어긋나면 검사에서 알립니다(예: `kin: 아들`인데 부모가 다른 사람).

**구상 — 보이는 곳**
* **계승표 창**(나라 기준): 그 나라 지도자를 즉위 순으로 한 줄로 놓고, 칸 사이 이음매에 관계 글(동생 · 조카 …)과 방식 딱지. 선의 모양이 방식을 말합니다(안: 세습 = 실선 · 선양 = 겹선 · 찬탈 = 끊긴 선 · 미상 = 점선과 "?" — 승계선의 문법을 빌림). 복위는 같은 사람 카드로 되돌아가는 고리. 표 안의 칸을 누르면 연표의 그 칸이 조명됩니다.
* **세계표 창**(가문 기준 — 가문 창에서 엶): 세대 = 가로 줄, 사람 = 둥근 네모 카드. 임금은 다스린 나라 색으로 칠하고 대수 번호, 임금이 아닌 사람은 종이빛. 부모 → 자식은 꺾인 선, 양자는 점선, 이름 미상은 빈 고리, 여러 대 건너뜀은 점선 + "6대". 분가로 갈라지는 곳에 가문 이름표(본가 → 분가 나무와 이어짐).
* **연표 위**(선택 · 기본 끔): 필터 '띠 안'에 `즉위 관계` — 지도자 칸 사이 구분선의 모양만 바꿉니다(직계 = 지금 가는 선 · 방계 = 틈 · 찬탈 = 짧은 빗금 · 미상 = 점선). 새 단을 만들지 않아 높이가 그대로입니다. 지도자 칸 창에는 "앞 임금의 동생 · 추대"가 한 줄로.
* 여는 길: 나라 상세 · 가문 창 · 지도자 칸 창의 `계승표` · `세계표` 단추, 검색에서 사람 · 가문.

**메이커**: 지도자 줄의 '자세히'(블록 — 3-4)에 즉위 관계 두 칸과 부모 칸. 세계표 창을 메이커에서 열면 카드를 끌어 다른 카드 아래에 놓는 것 = 부모 적기(블록의 끌기 문법과 같음 · 놓기 전 "놓으면: 부 → ○○" 미리 글).

**새 앱**: 두 표는 창이라 엔진은 나라 · 가문별 사람과 관계 기록을 항목 기록(`entities`)에 실어 주면 됩니다(타일 형식 그대로). 연표 위 구분선 모양만 칸의 무늬 비트 하나.

**그려서 고를 것**: 계승표의 방향(세로 · 가로) · 방식별 선 모양 · 세계표의 나무 방향 · 연표 위 구분선 표시를 넣을지 · 미상 기호.

**무게**: 자료는 작고 창 둘이 새 그림이라 중~큼. 자료 입력량이 많은 기능이라 메이커 편의(3-4 · 3-5)가 먼저면 좋습니다.

### 3-2. 성씨 · 왕조 개편 (건의 2)

**원하는 것**: 누르면 성씨가 나오고, 누르면 그 기간이 하이라이트.

**지금 있는 것**: 가문(`houses` — 성 · 본관 · 시조 · 본가) · 왕조 칸(띠 맨 위) · 가문 줄(필터 `가문`, 기본 끔 — 지도자 칸 아래 2px 선) · 가문 배지 → 가문 창(성 · 본관 · 본가와 분가 · 국성으로 삼은 나라 · 구성원). 가문 창이 열린 동안 그 가문의 칸이 **진해지기만** 하고 **기간 조명은 없습니다.** 왕조 칸을 누르면 다스린 나라마다 그 기간이 조명됩니다.

**구상**
* **성씨 층**: 성씨 → 가문(본관 · 집안) → 왕실(국성으로 다스린 가문). 성씨는 가문의 `surname`에서 저절로 모읍니다(새 목록 필수 아님). 원어(3)를 달 때만 선택 목록 `surnames`(id · name · names).
* **올리면**: 왕조 칸 · 지도자 칸 · 국성 딱지에 올리면 작은 풍선에 `성씨 · 본관 · 가문`(지금 설명글을 넓힘). 선택안: 왕조 칸의 머리에 성씨 한 글자 도장 딱지.
* **누르면 — 가문 조명**: 그 가문이 왕위에 있던 모든 기간(지도자 칸 기준)을 **모든 나라의 띠에** 조명하고 날짜 칸 위에 괄호를 그립니다(같은 시기 타국 메아리와 같은 칠 · 같은 끄기). 다른 가문의 칸은 옅게. 지금의 '진해짐'을 '기간 조명'까지 넓히는 것입니다. **성씨를 누르면** 그 성씨의 모든 가문 기간을 가문별 짙기로.
* **가문 연대 막대**(체제 확장에서 뒤로 미룬 것): 가문 창 안에 시간 막대 — 나라별 한 줄, 왕위에 있던 기간은 칠, 구성원(인물) 활동은 가는 선.
* **지도자 칸의 가문 표시**: 필터 `가문`을 켰을 때 지금의 2px 선 대신 무엇으로 할지 고름(아래).
* **왕조와 가문 정리**: 왕조 = "한 가문이 한 나라를 다스린 한 시기", 가문 = 사람의 집안. 왕조의 `house`가 옛 뜻(본가 왕조 이름)과 겹쳐 헷갈리는 것은 메이커 화면 글로 분명히 하고 형식은 그대로 둡니다.

**새 앱**: 가문 강조 값(`emphasis.look.house`)이 이미 실려 오므로, 조명을 가문 단위로 묶는 조회 하나(엔진의 `echo`와 같은 꼴)를 더합니다.

**그려서 고를 것**: 가문 표시(가: 지금 선 · 나: 칸 아래 반쪽 칠 · 다: 칸 테두리 색) · 성씨 도장을 넣을지 · 가문 조명 때 다른 칸의 옅기.

**무게**: 중 — 대부분 이미 있는 조명 장치를 넓히는 일.

### 3-3. 원어 병기 (건의 3)

**원하는 것**: 국명 · 인명 · 지명 등에 원어를 함께 적고, 보이는 표기를 고를 수 있게.

**지금 있는 것**: 나라 · 왕조 · 가문은 `name` 하나뿐. 예외는 인물의 `aka`(다른 이름), 지도자의 묘호 · 시호 · 이름(표기 고르기 있음), 지위 별칭, 조약의 정식 명칭, 사건의 `perspectives`(나라마다 제 이름 — 필터의 '관점'). 원어 · 로마자 칸은 없습니다.

**구상**
* **자료**: 바탕 2의 `names`를 이름 칸이 있는 모든 곳에. 지명은 바탕 3. 사건의 `perspectives`는 그대로 두되, 보는 설정에서 원어와 한 줄로 고르게 합니다(둘 다 "어느 이름으로 보이나"이므로).
* **국호 변천**: `names`의 `start`/`end`로 같은 나라가 시기마다 다른 이름이었음을 적으면, 책갈피 탭이 화면에 보이는 해의 이름을 보이고 상세에 변천 목록이 나옵니다(2차 — 탭 글이 바뀌는 그림이라 새 앱 내보내기까지 걸림).
* **보는 설정 '표기'**(필터 시트 한 줄 + 바탕 5): 주 표기 = 한국어 · 원어 · 로마자 · 현지음/한자음, 병기 = 없음 · 상세 창만 · 탭과 칸에도(괄호 또는 둘째 줄 작은 글), 종류별 켬끔(나라 · 인명 · 지명). **기본값은 지금 화면 그대로**(상세 창에만 원어).
* **상세 창 머리**: 이름 아래에 원어(크게) · 로마자 · 언어 이름. 설명글에도 원어.
* **검색**: 모든 이름으로.
* **글 방향 · 글자**: 오른쪽에서 왼쪽으로 쓰는 문자(아랍 · 히브리)는 그 글만 방향을 바꿔 섞어 씀. 화면 글꼴에 없는 글자(옛한글 · 한자 확장 · 가상 문자)는 두부(□)가 되므로 글꼴 팩(3-9)과 이어집니다.
* **메이커**: 이름 칸 옆 작은 `文` 단추 → 이름 줄 목록(글 · 언어 · 종류 · 기간). 표(그리드)에 '원어' 열 하나(첫 원어)를 두어 여러 항목을 빠르게.
* **새 앱**: 탭 · 칸의 글은 글자 그림판(미리 그려 둔 글자 판)으로 그리므로, 원어를 **띠에** 그리려면 그 문자의 글자를 그림판에 담고 폭 셈을 다시 해야 합니다. 그래서 **1단계 = 창 · 설명글 · 검색**(작음), **2단계 = 탭 · 칸 병기**(큼)로 나눕니다.

**그려서 고를 것**: 탭 · 칸에서의 병기 자리(괄호 · 둘째 줄 · 올릴 때만) · 상세 창 머리 모양.

**무게**: 1단계 중, 2단계 큼.

### 3-4. 메이커 블록 체제 (건의 4)

**원하는 것**: 노션처럼 블록을 끌어 옮기고 바꾸는 손쉬운 편집.

**지금 있는 것**(코드 확인): 편집 창의 폼은 `js/core.js`의 `HT.FORMS`가 그리고 읽습니다. 지도자 · 연호 · 도읍 같은 목록은 **줄마다 낱 입력 칸**(`.cell-row`)이고 끝의 `＋`로 줄을 더합니다. 줄을 끌어 옮기는 기능은 **없습니다** — 유일한 선례는 DLC 정보의 '볼거리' 목록(⋮⋮ 손잡이 끌기 + Alt+↑/↓). 그런데 **칸은 저장하면 시작 순으로 다시 놓이므로**(`HT.sortCells`) 같은 목록 안의 차례 바꾸기는 시작이 같거나 미정인 칸에서만 뜻이 있습니다. 연표 위에서는 끝 · 이음매 끌기, Alt 끌어 옮기기, Ctrl 끌어 만들기가 있습니다. 왼쪽 구조 나무는 종류 · 트랙별 **자동** 묶음입니다. 되돌리기는 저장 한 번이 한 걸음입니다.

**그래서 블록의 쓸모는 '차례'보다 '자리 옮기기'에 있습니다.** 두 층으로 나눕니다.

* **(가) 폼 안의 블록**
  * 폼의 칸 묶음(기본 · 승계 · 지위 · 지도자 · 내각 · 연호 · 도읍 · 시기 · 날짜 견해 · 문서)을 접히는 블록으로, 목록의 줄마다 왼쪽에 **⋮⋮ 손잡이**(올렸을 때만 보임 — 노션 식).
  * 손잡이를 끌어: 다른 목록으로(지도자 ↔ 내각 = 종류 바꾸기 · 연호 줄로 복사), 다른 나라의 편집 창으로(떼어 띄운 창 둘 사이 = 그 나라로 옮기기), 같은 목록 안(시작이 같거나 미정일 때의 차례 — "저장하면 시작 순으로 놓임" 안내).
  * 손잡이를 눌러 **블록 메뉴**: 복제 · 위로/아래로 · 다른 나라로 옮기기… · 종류 바꾸기 · 지우기. 여러 줄은 Shift+손잡이로 함께 고름.
  * **`/` 명령**: 빈 줄이나 블록 사이에서 `/`를 치면 더할 블록 고르기(지도자 · 연호 · 도읍 · 소속 · 승계 · 즉위 관계 · 원어 · 문서 …) — 자주 안 쓰는 칸을 폼에 늘 펼쳐 두지 않아 폼이 짧아집니다.
  * **바꾸기**: 두 블록을 고르고 `바꾸기` — 두 줄의 내용 맞바꿈(같은 종류) · 두 지도자의 기간 맞바꿈(선택).
* **(나) 개요의 블록 — 끌 수 있는 구조 나무**(감독: "민족을 일일이 입력하지 않고, 민족 펼치기 같은 묶음 아래로 옮겨 놓으면 저절로 그 민족이 되는 느낌")
  * 원칙: **가리키는 칸은 치지 않고 놓아서 채운다.** 구조 나무에 '민족으로 보기'(트랙 → 민족 나무 → 나라 — 연표 왼쪽 민족 칸과 같은 나무, 펼치고 접음)를 두고, 나라를 어느 민족 가지 아래로 끌어 놓으면 그 나라의 `people`이 그 민족이 됩니다(위 단계 민족에 놓으면 그 단계로 — 단계 수 제한 없는 지금 규칙 그대로). 새 민족 가지는 나무에서 바로 만들어 이름만 칩니다.
  * 같은 문법을 가리키는 칸 모두에: 나라 위에 놓기 = 소속(`partOf` — 놓을 때 관계를 고르는 작은 메뉴), 트랙에 놓기 = 트랙 옮기기, 가문 가지에 놓기 = 국성, 대범위 · 모아 보기 판(3-6) · 단체(3-7) · 렌즈 주제(3-8) · 행정 상위 구역(3-10)에 놓기 = 그 구성원으로, 사건을 나라에 놓기 = 그 나라 트랙으로, 트랙 · 민족끼리 끌기 = 차례(`order`) 바꾸기. 보기 갈래(민족으로 · 소속으로 · 가문으로 · 대범위로 보기)를 바꾸면 같은 나무가 그 칸 기준으로 다시 묶입니다.
  * 여러 나라를 고른 채 끌면 함께 옮겨지고 되돌리기 한 걸음. **놓기 전에 "놓으면: 민족 → ○○ (3개)" 미리 글**, 놓을 수 없는 곳은 막고 까닭 글. 다른 DLC의 나라는 패치로 적힘(지금 규칙).
* 공통: 끌기 한 번 = 되돌리기 한 걸음(지금의 `transact`). 끌 때 다른 줄이 비켜나는 흐름은 `--t-move` · 되튐 없음. 키보드로도 같은 일(3-5).

**새 앱**: 영향 없음(메이커만).

**걸림돌 — 풀림(2026-10-12 감독 "풀어도 돼")**: 2026-09-22 결정("웹 메이커는 '아카이브용 내보내기' 단추 말고는 건드리지 않음")을 이 10건에 한해 풀었습니다. 폼은 지금 `core.js`(약 7천 줄)의 폼 HTML · 채우기 · 읽기에 걸쳐 있어, 블록 틀을 먼저 세우고 종류별 폼을 하나씩 옮기는 차례가 안전합니다.

**그려서 고를 것**: 손잡이 · 블록 메뉴 · 끌 때의 자리 표시 · `/` 명령 상자 · 구조 나무 끌기의 미리 글.

**무게**: 큼.

### 3-5. 메이커 묶음 · 키보드로 입력 칸 이동 (건의 5)

**원하는 것**: 묶음 기능으로 만들기 편하게, 상하키로 입력 칸 이동.

**지금 있는 것**: 가운데 **표**(그리드)에는 화살표 이동 · Enter 편집과 아래로 · Tab 오른쪽 · 채워 내리기(Ctrl+D) · 범위 복사/붙여넣기(엑셀과 같은 TSV)가 있습니다. **편집 창의 폼에는 화살표 이동이 없고** Enter는 잘못 저장하지 않게 삼키기만 합니다. 여러 항목을 고르면 오른쪽에 일괄 고침(트랙 · 종류 · 분류 · 중요도 · 민족 · 색 · 실재성 · 확실성 · 날짜 옮기기). 목록마다 '여러 줄 한꺼번에 붙여넣기' 글 칸.

**구상 — (가) 입력 칸 길잡이(키보드)** — 작고 빨리 이득, **먼저 권함**
* ↑/↓ = 같은 열의 위/아래 칸(지도자 줄의 '시작'에서 ↓ = 다음 지도자의 '시작' — 표와 같은 감각), 줄 목록 밖에서는 위/아래 칸.
* Enter = 다음 줄의 같은 칸(마지막 줄이면 새 줄을 만들고 그 칸으로) · Shift+Enter = 위 줄.
* Alt+↑/↓ = 줄 옮기기(볼거리 선례) · Ctrl+D = 줄 복제 · Ctrl+Shift+Delete = 줄 지우기 · Ctrl+Enter / Ctrl+S = 저장(그대로).
* 예외: 여러 줄 글 칸(설명 · 메모)에서는 커서가 첫 줄/끝 줄일 때만 칸을 옮김(노션 식) · 자동 완성 목록이 열려 있으면 목록 안에서 움직임 · **한글 조합 중에는 아무것도 하지 않음**(`isComposing`) · 큰 입력 창은 그대로.

**구상 — (나) 만드는 묶음** — 감독 결정: **넷 다**. 옮기기는 3-4 (나)의 '놓아서 채우기'와 한 문법입니다.
1. **고른 항목 묶음 → 일괄 고침 넓히기**: 지금 9개 칸에 국성 · 소속 · 대범위에 넣기 · 태그 · 렌즈 주제(8) 등을 더함.
2. **줄 묶음 붙여넣기**: 목록의 붙여넣기 글 칸을 표 붙여넣기처럼 — 엑셀에서 여러 열을 복사해 지도자 목록에 한 번에(열 맞추기 미리 보기).
3. **함께 만드는 틀**: "새 임금 = 지도자 줄 + 연호 줄 + 즉위 사건"처럼 자주 함께 만드는 것을 틀 하나로(틀은 작업실 설정 — 파일에 안 들어감). **16건의 8번 '한번에 입력'(묶음 6)과 같은 자리이므로 함께 설계합니다.**
4. **작업 폴더**: 구조 나무에 만든 사람이 직접 묶는 폴더(작업실 설정). 원하면 그 폴더를 모아 보기 판(3-6)으로 내보내 배포.

**새 앱**: 영향 없음.

**무게**: (가) 작음 · (나) 중.

### 3-6. 연표 같이 보기 · 모아 보기 판 (건의 6)

**원하는 것**: 보기 모드에서 묶어 보기 — 예를 들어 삼국시대면 신라 · 고구려 · 백제 · 가야를 모아 보기.

**지금 있는 것**: **대범위**(`scopes`)가 흩어진 나라를 한 가지로 모으고 테두리를 두르며 모여드는 움직임까지 있지만, ① **같은 트랙 안에서만** 모이고 ② **DLC가 정한 것만**(보는 사람은 켜고 끄기만) 됩니다. 트랙 · 민족 접기, 필터 칩(트랙 · 분류 · 종류)이 있고, **이름 붙여 저장하는 보기는 없습니다.**

**구상 — 모아 보기 판**
* 판 하나 = 이름 + 나라 목록(여러 트랙에 걸쳐도 됨) + 기간(선택 — 켜면 그 시대로 날아감) + 보기 설정(밀도 · 렌즈 · 표시 체크 — 선택).
* **켜면**: 구성 나라들이 맨 위 한 판에 모입니다(트랙을 넘어 — 대범위의 모여드는 움직임을 넓힘). 나머지는 (가) 접힘 (나) 옅게 남김 (다) 그대로 아래 — 그려서 고름. 판 이름표는 대범위 테두리와 같은 말씨.
* **만드는 길 셋**: ① 보는 사람이 연표에서 나라를 Ctrl+클릭으로 고른 뒤 `모아 보기로 저장`(보는 방법이라 보기 전용 원칙과 맞음 — 바탕 5) ② **시대 구분 띠를 누르면 "이 시대의 나라 모아 보기"를 저절로 제안**(그 기간 · 그 트랙에 있던 나라) — 예시의 삼국시대가 이 길 ③ DLC가 권하는 판(`views` 목록 — 만든 사람이 배포, 메이커의 작업 폴더에서 내보낼 수 있음).
* **같이 보기의 뜻(감독 결정)**: **한 화면에 모으기** — 트랙 · 민족이 달라 화면에서 멀리 떨어져 있던 나라들을 붙여 놓고 직접 비교합니다. 두 시간 축으로 나눈 나란히 보기는 하지 않습니다. 모인 판 안에서는 같은 해가 같은 세로선에 놓이므로, 같은 시기 타국 메아리 · 조명이 붙은 줄끼리 바로 견주어집니다.
* **대범위와의 관계**: 대범위 = 자료(만든 사람의 역사 해석 — 할거 · 부흥), 모아 보기 판 = 보는 방법. 대범위는 그대로 둡니다.

**새 앱**: 줄 옮기기 변형(계약 2-4 — 소속 펼치기와 대범위 모아 보기)이 이미 있으나, 변형은 **내보낼 때 웹의 배치 규칙으로 미리 셈해 저장소에 실어 둔 것**이고 트랙 안에서만 움직입니다. 그래서 길이 둘로 갈립니다 — ① DLC가 주는 판은 대범위처럼 **내보낼 때 미리 셈한 변형**으로(모양이 가장 바름) ② 보는 사람이 그 자리에서 만든 판은 미리 셈할 수 없으므로 **줄을 통째로 옮겨 쌓기만**(줄 안 배치는 그대로 · 옮긴 줄과 남은 줄 사이의 승계선 · 소속선은 단순한 선이나 생략). 트랙을 넘는 줄 쌓기는 줄 자리(SceneLayout)의 확장이 필요하고 이것이 이 건의 가장 큰 위험입니다.

**그려서 고를 것**: 나머지 처리(접힘 · 옅게 · 그대로) · 판 이름표 · 시대 구분에서의 제안 모양.

**무게**: 중~큼.

### 3-7. 단체 — 붕당 · 정권 · 세력 · 연합 세력 (건의 7)

**원하는 것**: 붕당의 이름, 정권, 세력, 연합 세력 같은 부가적 단체를 표현할 길.

**지금 있는 것**: 제 띠를 갖는 조직체(`org` — 절도사 · 막부 · 군벌) · 부흥 · 저항 세력(`movement`) · 군벌(`warlord`), 지도자 칸 아래의 내각 칸, 띠 안의 외세 기관(`organs`), 인물. **없는 것**: 나라 **안**의 정치 집단(붕당 · 정당 · 파벌)과 그 **분열 · 합류**, **실권**(명목 임금 뒤의 실제 권력 집단), **여러 나라에 걸친 연합**(동맹 · 연합군).

**구상 — 새 목록 `groups`(단체)**
```json
"groups": [
  { "id": "g-east", "name": "동쪽 무리", "type": "faction", "track": "a", "within": "갑 왕국",
    "start": 875, "end": 891, "from": [ { "group": "옛 무리", "how": "split" } ],
    "power": [ ["집권", 880, 885] ], "people": ["…"] },
  { "id": "g-pact", "name": "세 나라 맹약", "type": "coalition", "start": 560, "end": 575,
    "members": [ { "polity": "갑 왕국" }, { "track": "b", "polity": "을 공국", "end": 570 } ], "event": "맹약 사건 id" }
]
```
* `type`: `faction`(붕당 · 파벌) · `party`(정당) · `regime`(정권 · 실권 집단) · `bloc`(세력) · `coalition`(연합 · 동맹) · 자유 글. `within` = 그 단체가 있던 나라(여럿이면 기간과 함께), `from` = 갈라져 나온 · 합쳐진 단체(`split` · `merge`), `power` = 집권 · 실권 · 연정 기간(칸 목록 꼴), `people` = 구성원(사람 참조 — 바탕 1), `members` = 연합의 구성 나라.

**구상 — 보이는 곳**
* **나라 안 단체(붕당 · 정당)**: 띠 안에 **집권 단**(그때 집권한 단체의 칸 줄 하나 — 바탕 4의 공용 칸 단). 갈래 전체(누가 어디서 갈라졌나)는 띠에 그리면 높이가 커지므로 **붕당 계보 창**(계승표와 같은 창 틀 — 3-1과 함께 만듦)에서 봅니다.
* **실권(정권)**: 지도자 칸 바로 위에 **실권 단** — 명목 임금(지도자 칸)과 실제 권력을 나란히. 제 띠를 가진 조직체(막부 같은)는 지금 그대로.
* **연합**: 구성 나라의 띠를 그 기간만큼 잇는 **연합 끈**(안: 왼쪽 가장자리의 세로 괄호 · 구성 띠 테두리의 같은 색 표지 · 올리면 구성 나라 모두 진하게). 조약 사건과 이으면 체결 → 연합 시작이 함께 보임.
* **단체 창**: 이름 · 종류 · 기간 · 집권 기간 · 갈라져 나온/합쳐진 단체 · 구성원 · 문서. 검색 · 문서 링크 `[[단체:이름]]`.
* **렌즈와**: '붕당' 렌즈(3-8)는 이 자료의 집권 단을 띠의 주인공으로 세우는 보기입니다 — **자료는 7, 보는 법은 8**.

**그려서 고를 것**: 집권 단 · 실권 단의 칠과 자리 · 연합 끈 · 붕당 계보 창.

**무게**: 큼.

### 3-8. 렌즈 — 주제 보기 (건의 8)

**원하는 것**: 국가 연표 말고도 법률 · 선거제도 · 이념 · 체제 · 붕당 · 군사제도 · 조세제도 · 선발제도 같은 여러 보기 — 일종의 렌즈.

**지금 있는 것**: 필터의 '관점'은 **사건 제목을 나라마다 바꾸는 것뿐**입니다(`perspectives`). 주제별 보기는 없습니다. 가장 가까운 자료는 시기 구분(학계 — `phases`) · 지위 변천(`ranks`) · 내각입니다.

**구상 — 렌즈 = 같은 나라 띠 · 같은 시간 위에 주제 하나를 주인공으로 바꿔 끼우는 보기**
* **자료 셋**
  1. **주제 사전 `themes`**: `{ id, name, color, kind }` — 만든 사람이 정함(선거제도 · 이념 · 군사제도 · 조세제도 · 선발제도 · 법률 …, 판타지면 마법 체계 · 길드 제도). 내장은 뼈대만.
  2. **제도 칸 `institutions`**: 나라마다 주제마다 이어지는 칸 목록 — 연호와 같은 칸 꼴이라 메이커 입력이 같습니다.
     ```json
     "institutions": [
       { "theme": "tax", "polity": "갑 왕국", "family": "고르게 나눔",
         "spans": [ ["밭 나눔 법", 612, 790], ["두 철 거둠 법", 790, null] ] }
     ]
     ```
     `family` = 제도 갈래(여러 나라가 같은 갈래면 같은 색 — 나라 너머로 퍼진 것이 한눈에) · 칸마다 `from`(다른 나라 제도에서 옴 — 전파).
  3. **사건의 주제 꼬리표 `theme` + 규격**: 법은 조약처럼 **법 규격 `law`**(법 이름 · 제정/개정/폐지 · 조항 — 상세에 법전 모양), 선거는 **선거 규격 `election`**(2차 — 결과 · 의석).
* **렌즈를 켜면**: 띠 안 지도자 단의 자리에 그 주제의 **제도 단**(바탕 4) · 사건은 그 주제 꼬리표만 진하게(나머지는 옅게 — 거르지 않음) · 날짜 칸 위에 제도 변천 괄호 · 같은 갈래 칸은 같은 색이고 올리면 모든 나라에서 진해짐(메아리) · 전파선(`from`)은 승계선 문법의 옅은 선(선택).
* **고르기**: 필터 시트에 `렌즈` 한 줄(지금 `관점` 옆) + 단축키. **한 번에 하나**(높이 예산).
* **내장 렌즈와 자료 렌즈**: '체제' 렌즈 = 이미 있는 종류(`kind`) · 지위(`ranks`)를 주인공으로 · '붕당' 렌즈 = 단체(3-7)의 집권 단 · '법률' 렌즈 = 법 규격 사건 · 나머지는 주제 사전에서.
* **새 앱**: 모든 렌즈의 칸을 타일에 늘 실으면 커지므로 렌즈별 칸은 따로 구역 번호로 싣고 **렌즈가 꺼져 있으면 읽지도 않게**(지금 지도자 표기 구역의 선례 — "기본 표기면 그리는 쪽이 읽지도 않음"). 줄 배치는 내보낼 때 웹의 규칙으로 미리 셈하므로, 제도 단을 **지도자 단과 같은 자리 · 같은 높이에 바꿔 끼우면** 렌즈를 바꿔도 다시 셈할 것이 없습니다. 지도자 단 위에 **덧붙이는** 안은 줄 높이가 달라져 렌즈마다 미리 셈한 변형이 필요합니다 — 그려서 고를 때 이 값도 함께 봅니다.

**여덟 주제 모두 시도(감독 결정)** — 주제마다 재료가 다르므로 렌즈 틀 하나에 재료 넷을 꽂습니다.

| 주제 | 띠 안 주인공 단의 재료 | 사건 쪽 | 비고 |
| --- | --- | --- | --- |
| 체제 | 이미 있는 종류(`kind`) · 지위(`ranks`) + 제도 칸(군주제 · 공화제 …) | 체제 바뀐 사건 꼬리표 | 내장 렌즈 — 지금 자료만으로도 보임 |
| 붕당 | 단체(3-7)의 집권 단 | 환국 · 분열 사건 꼬리표 | 자료는 3-7 |
| 법률 | 제도 칸(그때 쓰던 법전 · 법체계) | **법 규격 `law`**(법 이름 · 제정/개정/폐지 · 조항) | 사건 규격 새로 |
| 선거제도 | 제도 칸(선거 방식 · 선거권 범위) | **선거 규격 `election`**(뽑은 자리 · 결과 · 의석) | 사건 규격 새로 |
| 이념 | 제도 칸(나라의 기준 이념 · 국교) | 꼬리표 | |
| 군사제도 | 제도 칸(병제) | 꼬리표 | |
| 조세제도 | 제도 칸(세제) | 꼬리표 | |
| 선발제도 | 제도 칸(관리 뽑는 법) | 꼬리표(시험 시행 등) | |

**단계**: ① 렌즈 틀 + 공용 칸 단 + 제도 칸 — 이 하나로 여섯 주제(체제 · 법률 · 선거 · 이념 · 군사 · 조세 · 선발 가운데 칸 재료)가 한 번에 섬 ② 붕당 렌즈(3-7과 함께) ③ 법 규격 · 선거 규격 ④ 전파선 · 같은 갈래 메아리. 주제 사전에는 여덟을 **내장 뼈대**로 두고 DLC가 더하거나 이름을 바꿉니다.

**그려서 고를 것**: 렌즈를 켰을 때의 띠(지도자 단을 바꿔 끼움 · 위에 덧붙임) · 같은 갈래 색 · 렌즈 고르기 자리.

**무게**: 아주 큼(자료 입력량도 큼 — 메이커 편의가 먼저면 좋음).

### 3-9. 글꼴 플러그인 (건의 9 — 우선도 낮음)

**지금 있는 것**: 글꼴을 싣지 않습니다. 웹은 시스템 글꼴 목록(Pretendard · Noto Sans KR · 맑은 고딕 …), 새 앱은 Pretendard와 대체 글꼴. 글꼴 설정은 없습니다. 웹은 이름이 들어가는지를 화면 글꼴로 재고, SVG 내보내기는 글꼴 이름을 고정해 씁니다.

**구상**
* **글꼴 팩**: DLC의 `fonts`(글꼴 파일을 압축 본문에 함께 · **라이선스 칸 필수**) 또는 따로 설치하는 글꼴 팩. 쓰임 셋: ① 화면 글꼴 바꾸기(보는 사람 설정 — 바탕 5) ② **원어 문자의 대체 글꼴**(3-3 — 옛한글 · 한자 확장 · 아랍 문자 · 가상 문자) ③ DLC가 제 세계관 글꼴을 함께 실음(판타지 문자).
* **주의**: 겹침 금지 규칙은 글 폭에 기댑니다. 글꼴을 바꾸면 '이름이 들어가나' 판정이 바뀌므로 웹은 바로 다시 재고, 새 앱은 글자 그림판을 다시 만들며, 내보낼 때 웹 글꼴로 셈한 값이 있다면 어긋나는지 확인해야 합니다. 한글 글꼴은 수 MB라 휴대폰 크기 · 라이선스(OFL 등) 확인.

**무게**: 중 — 원어(3-3)의 2단계와 함께 할 때 뜻이 큼.

### 3-10. 지도 (건의 10)

**원하는 것**: 층위가 있는 지도. 행정 층위를 직접 정하고, 핵심 지도는 밑바탕, 행정구역은 DLC 메이커로 직접 그리거나 파일을 올려 적용. 해마다 그려 장면처럼 넘기기. 대체역사 · 판타지에도 쓸 수 있게 범용.

**지금 있는 것**(`지도/` — 2026-09-18 메이커를 갈아엎으며 떼어 둠): 지형 팩(경계 호와 조각 · 실제 지리 · 동아시아 1만 1천여 조각 · 14.9MB) · 단위 팩(행정 구역 — **L1~L3 세 단 고정**, 단계 비교는 글 길이로 하는 임시 방편) · DLC `territory`(조각 · 구역별 소유 기록과 상태 — 본령 · 명목 · 유목 · 점령 · 분쟁) · 경계는 저장하지 않고 소유가 다른 이웃 조각 사이에 그음 · 캔버스 그림(원뿔 투영) · 연표 가운데 해를 따라감 · 재생 단추. 메이커 쪽은 옛 메이커용이라 지금 메이커에 안 붙습니다. **다각형 그리기 · GeoJSON 올리기는 앱에 없고**(노드 도구만), 밑그림은 경위도 네모에 놓는 그림 한 장. **판타지 지형을 앱 안에서 만들 길이 없습니다**(월흔해는 일부러 지도 없음). 다시 붙이려면 경로(`basemaps/` · `units/` 읽기 주소)부터 고쳐야 합니다. `DLC-형식.md`의 `territory` 절과 `core.js`의 읽기는 살아 있습니다.

**구상 — 층 쌓기**(아래 → 위)
1. **바탕(핵심 지도)**: 실제 지형 팩 **또는 그림 한 장**(판타지 · 옛 지도 — 좌표는 그림의 픽셀, `crs: "image"`). 실제 지리를 가정하지 않는 것이 범용의 첫걸음입니다.
2. **행정 층위 — 직접 정함**: `levels: [{ "id": "도", "name": "도" }, { "id": "군" }, { "id": "현" }]` — 단계 이름과 수를 만든 사람이 정합니다(고정 L1~L3을 대신). 구역은 기간을 가집니다(개편). 구역의 이름은 바탕 2 · 3과 같은 이름 목록.
3. **영토**: 나라가 언제 어느 구역 · 조각을 가졌나 — 지금 `territory` 그대로(상태 포함).
4. **지점**: 도읍 · 사건 장소 · 조약 체결지 — 지명 사전(바탕 3)의 좌표.
5. **길**(2차): 원정 · 이동 · 교역로.

**만드는 길(DLC 메이커의 지도 창)**
* **올리기**: GeoJSON(가장 흔한 지도 파일) — 올린 다각형을 구역으로 · 그림 — 바탕이나 밑그림(점 2~3개로 자리 맞추기).
* **그리기**: 점을 찍어 다각형 · 이웃 경계에 붙기(`지도/docs/구상-역사-지도.md`의 원칙 "선은 세계의 것, 면은 나라의 것" — 경계선은 한 번만 그리고 양쪽이 나눠 씀).
* **칠하기**: 구역 · 조각을 눌러 나라에 칠함(지금 방식).

**시간 — 장면과 기록을 하나로**
* **장면(슬라이드) 방식**: 해마다(또는 바뀌는 해마다) 그린 지도를 차례로 넘김 — 가장 쉽고 판타지에 바로 씁니다.
* 저장은 **열쇠 해**로 합칩니다: 그린 해 = 열쇠 해, 사이의 해는 앞 열쇠 해를 따릅니다. 경계를 섞어 미끄러지게 움직이지 않습니다(없는 사실을 그리지 않게 — 정직). 지금 `territory`의 '바뀌는 해' 목록이 곧 열쇠 해라 두 방식이 한 자료입니다.
* 재생: ◀◀ ▶▶ = 열쇠 해 넘기기, 연표의 가운데 해와 함께 움직임.

**연표와 잇기**: 연표 옆이나 아래의 지도 판(떼어 띄우기 됨) · 연표의 가운데 해와 고른 항목을 따라감 · 지도에서 나라를 누르면 연표의 그 띠 · 사건을 고르면 그 장소에 핀.

**지도 DLC**: DLC 분류에 `map`(지도팩)을 더해 지형 · 행정 층위 · 영토를 연표 자료와 따로 켜고 끕니다.

**새 앱**: 지도 그리기는 새로 만듭니다(Flutter 캔버스 + 엔진에 구역 · 경계 기록 · 배율별 간추린 선 — 지금 지형 팩의 10단계 간추림을 그대로 씀). 성능은 연표와 같은 합격선(놓친 장면 · 연달아 놓침)으로 잽니다. 휴대폰에서는 지형 팩 크기가 걸립니다.

**단계 제안**(감독 결정: 1단계 "해봐"): ① 그림 바탕 + 장면 방식 + 칠하기(판타지 · 대체역사 바로) ② 직접 정하는 행정 층위 + GeoJSON 올리기 ③ 실제 지형 팩 다시 붙이기(옛 부품 손질) ④ 그리기 · 경계 붙이기 · 길.

**그려서 고를 것**: 지도 판의 자리(옆 · 아래 · 떠 있음) · 영토 상태별 칠 · 열쇠 해 넘기기 조작.

**무게**: 아주 큼 — 따로 한 단계로.

## 6. 위험과 하지 않을 것

* **띠 높이**: 새로 생길 수 있는 띠 안 단(가문 칠 · 집권 · 실권 · 제도)을 다 켜면 띠가 두꺼워집니다 → 렌즈로 **주인공 단 하나**를 원칙으로, 나머지는 창에서.
* **새 앱 비용**: 자료 칸마다 내보내기 · 엔진 · 그리기를 함께 고쳐야 하고, 저장소를 다시 지어야 반영됩니다 → 공용 칸 단(바탕 4)과 '창 먼저'로 줄입니다. 새 그림은 층마다 성능을 재고 합격선을 낮추지 않습니다.
* **형식 버전 3**: 새 열쇠를 처음 쓰는 묶음이 읽는 버전을 3으로 올리고, 새 열쇠 묶음들은 master에 한 덩어리로 합칩니다.
* **자료 입력량**: 계보 · 원어 · 제도 · 지도는 손으로 넣을 양이 큽니다. 메이커 편의(가)를 먼저 두는 까닭입니다.
* **지도 자료의 라이선스**: 지금 지형 팩은 출처 표기 조건의 공개 자료로만 만들었습니다(`지도/README.md`). 사용자가 올리는 파일의 권리는 만든 사람의 몫이고, 배포 DLC에 담을 때 출처 칸을 둡니다.
* **하지 않음(이번 구상)**: 경계를 섞어 움직이는 지도 애니메이션 · 렌즈 여러 개 동시 켜기 · 연표에서 자료 고치기(보기 전용 그대로) · 옛 JSON/ZIP 열기.
