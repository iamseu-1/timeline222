# 리메이크 3단계 — 엔진 · 내보내기 계약 · 스키마 4 구현 계획

> **에이전트 작업자에게:** 과제를 하나씩, 걸음은 체크 상자(`- [ ]`)로. 과제마다 시작 조건 · 걸음 · 검사가 있고, 과제 끝마다 `인수인계.md` 5절에 다섯 줄 안으로 적습니다. 감독 확인 전에는 main에 합치지 않습니다.

**목표:** 형식 4의 뜻(객체 종류 열아홉 · 관계 · 정통성 · 중요도 · 사람 객체 · 직위 줄 빌림 · 실권 · 문화권 단위 줄 · 상자)이 **저장소까지 실려** 새 앱이 읽을 수 있게 한다(설계 2절 3단계 — "새 앱이 새 자료와 새 배치를 읽음 · 부품 그림은 아직 지금 것"). 3단계가 끝나도 **앱 화면은 지금과 1배로 같다**. 새 장치를 그리는 일은 4단계다.

**짜임:** 5단계와 같은 길을 잇는다. 읽기는 지금처럼 이음 층 → 다리 `HT.F4.down` → 옛 꼴 정규화 → 모델 → 내보내기 모듈 스물이고, 정규화가 이미 지키는 형식 4 칸(5단계 과제 3 · 4 · 6)을 **내보내기 모듈이 읽어 저장소에 싣는다**. **지금 있는 열 · 비트의 뜻은 하나도 바꾸지 않는다** — 새 열 하나(`periods.form`) · 새 표 하나(`sphere_lines`) · 새 구역 셋 · 칸의 새 비트 · 새 칸 종류 하나(9)를 더할 뿐이다. 새 칸을 적지 않은 파일은 새 열이 모두 0이고 나머지는 지금과 바이트 같다.

**설계:** `docs/설계-리메이크-객체-그릇-서고.md` 2절(단계표) · 3-8(이음) · 3-10(정함) · 3-11(장면 다섯 · 새 번호표 초안) · 4-1(서고 그림) · **`docs/계약-아카이브-3단계.md` 1-1(스키마 4 — 판 · 새 표 · 길. 값의 뜻은 6-1 가 · 6-2 · 6-9 가 · 6-12 — 과제 9에서 초안을 걷고 옮김)** · 6-1 · 6-2 · 6-10 · `docs/계획-리메이크-5단계.md` '이 계획 밖' 표 · 과제 12의 '알게 된 것'. 메이커 쪽 셈의 본보기는 `js/core.js`의 `HT.f4Preview`(서고 미리보기가 쓰는 형식 4 모델 — 사람 · 빌림 · 실권 · 문화권 줄)다.

**쓰는 것:** 웹 코드 `js/core.js`(정규화 · 모델) · 내보내기 `prototype/scripts/export/*.mjs` · 엔진 `prototype/engine`(`lay` 거울 · `schema.rs` · `builder.rs` · `patch.rs` · 조회) · 앱 `prototype/app`(읽기만 — `Store` 답 · 모델) · Node 24 · Rust 1.99.1 · Flutter 3.47.5. 새 크레이트 · 꾸러미 없음.

## 전체 제약

* 글 · 주석 · 문서 · UI는 한국어 · 개발 용어는 풀어서 · 검사 자료의 이름은 가상.
* **내보내기 JS가 정답, Rust는 거울** — P3 '옮기는 규칙' 그대로. 모듈을 고치면 JS 먼저, Rust를 같은 줄만큼, 머리의 원본 줄 범위 · 지문 갱신 → `layout-oracle.mjs`로 정답지 다시 뽑기 → `build-check` 차이 0 · `lay::RULES` 다시 씀 · 출력이 달라지면 `LAY_RULES_VERSION`을 올리고 골든 판을 덧붙임(`tests/lay_golden.rs`).
* **있는 값은 바이트 같다** — 등불 · 동아시아의 `export-layout` 전후에서 새 열 · 새 구역 · 새 표 · 칸 27비트 말고는 같음. 등불 · 동아시아는 형식 4의 새 칸을 안 쓰므로 새 구역 · 새 표도 비고, `form`에는 옛 kind에서 되살린 종류 · 관계만 선다.
* **앱 화면은 1배로 같다** — 3단계 끝에서 지금 앱 ↔ 새 앱 · 같은 장면 넷의 PNG가 바이트 같음(P3-18이 쓴 방법 — `prototype/results/p3-18-1배/`). 새 값은 실리기만 하고 그려지지 않는다.
* **옛 저장소가 그대로 열린다** — 스키마 3 · 3.1 저장소는 새 열 · 표가 없을 뿐이라 빈 값으로 답한다(계약 1절의 가려 읽기). 옮겨 읽는 표가 필요 없다.
* `packs/` · `samples/`는 바꾸지 않는다(6단계). 검사용 새 자료는 `prototype/fixtures/f4/`의 가상 팩 다섯(5단계 과제 0)을 쓴다.
* 앱을 띄우는 검사는 `--memory-dir=<폴더>`로만(인수인계 3절 · 판정 R50).
* 줄 끝 LF · 커밋은 경로를 지정해 제 파일만 · 합치기 · 밀기 · 릴리즈는 감독 지시. 작업은 가지 `remake-3` · 작업 폴더 `.claude/worktrees/remake-3`(main `b722ae6`에서 냄).

## 검토 초점

* **있는 값이 바이트 같은가** — 등불 · 동아시아의 배치 JSON에서 띠의 `form` · 새 구역 · 새 표 · 칸 27비트 말고는 고치기 전과 같음.
* **엔진 거울 차이 0** — 정답지 25벌 + 가상 팩 다섯(사람 · 상자 · 빌림 + 실권 · 공국 · 문화권 줄)의 `build-check`.
* **옛 저장소를 새 엔진이 읽은 답 = 지금 엔진이 읽은 답** — 같은 스키마 3 저장소를 두 엔진으로 열어 `layout` · 타일 · `entity` 답을 견줌(새 키는 빈 값).
* **앱 1배 같음** — 장면 넷 PNG 바이트 같음 · 스키마 3 저장소로 띄운 새 앱도 같음.

## 위험

* **새 열을 셈하다 있는 값을 건드린다** — 과제 3은 `form`만 더하고 `form-only-check`로 "다른 것은 바이트 같음"을 못 박은 뒤에 새 장치(과제 4 ~ 6)를 싣는다.
* **엔진 거울이 두 벌로 갈라질 수 있다** — 시작 조건 C의 두 가지(`magical-morse` · `sad-keller`)가 같은 일을 했다. 하나만 main에 들이고 다른 하나는 걷는다(감독).
* **앱 그림을 3단계에 함께 고치고 싶어진다** — 정한 것 #14대로 미룬다. 1배 같음이 깨지면 원인이 자료인지 그림인지 가를 수 없다.
* **4단계에서 옛 '조직체'와 '군벌'을 어떻게 그릴지** — `form`의 종류는 둘 다 군벌이고 `look`만 다르다. 4단계가 `form`으로 그림을 바꿀 때 정한다(설계 3-8 'org → 군벌'의 그림 몫).
* **이 PC에 KoreanTimeLine이 없다** — 0.3초 판단 · KTL 정답지 둘은 못 돌린다(인수인계 5-4와 같음). 받으면 과제 9에 더한다.
* **20만 띠 DLC는 이미 10초 · 2GB를 넘는다**(5-4) — 새 표가 그것을 더 늘리면 안 된다. 과제 9의 재기에서 2만 · 4만 기준 시간을 넘으면 멈춘다.
