# 모바일 포팅 분리 — 2026-09-20

감독 결정: “일단 모바일 포팅을 떼어내서 아예 분리시켜 놓고. 나머지는 차례대로 하자.”

이 문서는 `codex/desktop-next`의 PC·웹 작업 기준입니다. 분리 변경의 `master` 반영은 감독 확인 뒤에 합니다.

## 보존 위치

| 대상 | 위치 |
| --- | --- |
| 모바일 작업 가지 | `codex/mobile-port` — `master`의 `14eb2d3`에서 분기 |
| 모바일 작업 폴더 | 저장소 뿌리의 `.claude/worktrees/mobile-port/` |
| PC·웹 작업 가지 | `codex/desktop-next` |
| PC·웹 작업 폴더 | 저장소 뿌리의 `.claude/worktrees/desktop-next/` |
| 별도 보관본 | 저장소 뿌리의 `배포/모바일-분리/` — 소스 압축본, 기존 시험판 APK, 보존 안내와 지문값 |

모바일 작업본에는 안드로이드 프로젝트, 전용 빌드 도구, 모바일 설정과 연결 코드, 기존 인수인계 및 시안·촬영 도구가 남습니다. 저장 전이던 `MainActivity.kt`의 온 화면 모드 변경도 보존합니다. 이 변경은 앱 빌드·기기 검증 전이며, 기존 시험판 APK에는 포함되어 있지 않습니다.

## PC·웹 작업본의 범위

- 연표와 메이커의 웹·PWA·Windows 프로그램을 유지합니다.
- 안드로이드 프로젝트·빌드 명령·APK 수집·모바일 전용 아이콘·네이티브 파일 수신·Capacitor 대체 경로를 분리합니다.
- 일반 휴대폰 브라우저의 터치·두 손가락 확대·좁은 화면 대응·뒤로가기는 유지합니다. PWA의 화면 방향은 `any`로 둡니다.
- Windows 파일 저장·열기·저장소 거울, PWA 파일 연결과 오프라인 동작은 유지합니다.
- 기본팩과 기존 견본, 연표를 그리는 코드와 화면 디자인은 바꾸지 않습니다.
- SDK·Gradle·Rust 도구와 기존 사용자의 앱 데이터는 이 분리의 삭제 대상이 아닙니다.

## 이후 작업 순서

1. `d8` 마지막 이름 배치 수정의 실제 화면 검증.
2. 최신 종속 표시를 유지하며 `d8` 통합. `d8-sync`에는 마지막 `5fae1dd`가 없으므로 통합 대상에 포함되는지 확인합니다.
3. `d8-partial`의 부분 승계·흡수 검증과 통합.
4. 메이커 개편의 기존 1·2단계를 확인하고 편집 기본기부터 순서대로 진행.

모바일 ‘다 안’은 별도 작업으로 보관하며 이 순서에 끼워 넣지 않습니다. 나중에 모바일을 재개할 때 PC·웹 변경을 선택해 가져와 모바일 환경에서 다시 검사합니다. PC·웹 가지를 모바일 가지에 통째로 합치면 이번 분리 삭제까지 적용되므로 피해야 합니다.

## 검사 기준

- `node scripts/dev-smoke.mjs`의 끝이 ‘문제 없음’인지 확인합니다. ㉛은 모바일 전용 의존성 분리와 Windows·웹 파일 동작을 확인합니다.
- `npm run web`으로 연표·메이커 두 배포 폴더의 파일 참조와 오프라인 목록을 검사합니다.
- `js/*.js`, `scripts/*.mjs` 문법과 변경 파일의 줄 끝을 검사합니다.
- 분리 전후 기본팩·기존 견본 23개 파일의 SHA-256 및 옛 견본 기준 지문을 비교합니다.
- 모바일의 온 화면 모드와 기존 APK는 보존 대상입니다. 이번 분리 검사를 모바일 앱의 새 빌드·실기기 검증으로 간주하지 않습니다.
